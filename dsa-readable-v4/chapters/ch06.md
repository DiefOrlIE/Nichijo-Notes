# 第 06 章　数组、压缩矩阵与稀疏存储：从位置关系推导地址

> **来源**：《DSA 4-String》中数组和特殊矩阵相关部分。  
> **先修**：一维数组、整数下标、链表、存储大小计算。  
> **目标**：从“前面已经放了多少项”推导二维地址；理解对称矩阵、三对角矩阵的压缩；亲自执行稀疏矩阵转置和快速转置。

想象我们在纸上写一个有行有列的数字表。纸面上的第 i 行第 j 列很好定位，可是计算机的普通线性内存只有一格接一格的地址。问题就来了：怎样把二维位置变成一维位置？只要这个问题学清楚，后面的矩阵压缩、稀疏矩阵甚至快速转置，都会成为同一条“位置怎样安排”的思路的延伸。

## 06.1 二维下标为什么能够对应连续的一维偏移 {#v4-array-layout}

设一个矩阵 A 有 m=3 行、n=4 列，行列下标都从 0 开始。**行优先**的意思是先存完整第 0 行，再存第 1 行，最后第 2 行。内存中元素顺序因此是 <code>A[0][0],A[0][1],A[0][2],A[0][3],A[1][0],...</code>。

现在要求 A[2][1] 的偏移。它前面完整存过两行，每行四项，所以已经越过 2×4=8 项；到本行下标 1 之前还需要越过一项，最终偏移为 9。推广到 A[i][j]，行优先的 0-based 偏移便是 <code>i*n+j</code>。若每项占 w 字节、数组首项地址为 base，字节地址为 <code>base+(i*n+j)*w</code>。

这并非只需要背诵的公式。**i*n** 的意义是已经跨过 i 整行，**+j** 是在当前行再向右移动 j 项。只要画出一张 3×4 小表，就能现场重新推出。

如果题目改成**列优先**，含义随之改变：先存完整第 0 列，再第 1 列。要求 A[2][1]，先跨过一整列，共 m=3 项；然后在当前列跨过两项，偏移 <code>j*m+i=1×3+2=5</code>。注意行优先使用列数 n 作为跨行步长，列优先使用行数 m 作为跨列步长。

真实 C++ 原生二维数组默认按行优先连续布局；某些数值库或其他编程语言则可能采用列优先。做数学地址题时以题目给出的存储规则为准，不能只凭“二维数组”三个字决定。

## 06.2 对称矩阵：为什么把一半存起来就够了 {#v4-symmetric}

假设一个方阵满足 <code>A[i][j]=A[j][i]</code>，例如 A[1][4] 与 A[4][1] 必定相等。这样的矩阵称为对称矩阵。如果把整个 n×n 数组都保存，其中大致一半位置就在重复另一半的信息。

我们可以只存主对角线以及下面的三角区域。第 0 行只保存一个元素 A[0][0]；第 1 行保存 A[1][0]、A[1][1] 两项；第 2 行保存三项……第 i 行保存 i+1 项。所以整个 n 阶矩阵只要 <code>1+2+...+n=n(n+1)/2</code> 项。

要求位于下三角的 A[i][j]（i≥j）对应的压缩下标，先数出前 i 行保存了 <code>1+2+...+i=i(i+1)/2</code> 项，再向本行右走 j 项，因此：

<code>k=i(i+1)/2+j</code>。

例如 n=5 时，A[4][1] 的下标为 4×5/2+1=11。如果题目要求 A[1][4]，它位于上三角，但可利用对称性改查 A[4][1]，结果仍是 11。这里前提非常重要：如果矩阵不对称，交换 i、j 会读到不同的数据，不能做这种压缩；如果题目指定存上三角或列优先，公式也必须重新按实际存储顺序推导。

## 06.3 三对角矩阵：把每行真正有用的位置连在一起 {#v4-tridiagonal}

另一类特殊矩阵叫三对角矩阵。它的非零元素只可能出现在主对角线和紧邻的上下两条对角线上。换句话说，若下标从 0 开始，只有满足 <code>|i−j|≤1</code> 的 A[i][j] 才需要实际保存，其他项都可直接视为零。

n=5 时，第一行最多两项 A[0][0]、A[0][1]；中间三行每行最多三项；最后一行最多两项，所以总位置数为 2+3+3+3+2=13，即一般的 <code>3n−2</code>（n≥2）。

若按行把这些有效位置压成一维数组 B，先观察它们的排列：第 0 行是 k=0、1；第 1 行是 k=2、3、4；第 2 行是 k=5、6、7。给定带内位置 (i,j)，可以推出 <code>k=2i+j</code>。例如 i=4、j=4 对应 k=12。反向定位时，i 可以由 <code>⌊(k+1)/3⌋</code> 求得，j=k−2i。

最容易出错的地方是把公式拿去处理带外项。比如 A[0][4] 不属于三条对角带，题目若规定零区不存储，它根本没有对应的独立压缩下标。**判断能否存储，必须先于计算存储位置。**

## 06.4 稀疏矩阵：很多零值为什么值得换一种存储法 {#v4-sparse}

前面两种压缩都利用了矩阵结构的规律：对称性或固定对角带。但如果一个 1000×1000 矩阵只有零星五个非零项，其非零位置毫无规律地散布在表中，依然可以节省空间。

最朴素的办法叫三元组表：仅为每个非零项记录 (行下标,列下标,值)。例如原矩阵只有 A[0][2]=5 和 A[2][1]=7，则记录为 (0,2,5)、(2,1,7)。未出现在表里的位置默认是零。这个方案的存储大小主要与非零项个数 t 成正比，而不直接随 m×n 增长。

但省空间也会带来操作上的问题：如果现在要查询 A[800][900]，不能只靠数组下标直接访问一个固定槽位，而可能要在三元组表中查找对应的行列组合。特殊结构适合什么任务，始终与操作类型有关。

矩阵转置要求将每个 A[i][j] 搬成转置矩阵 B[j][i]。对三元组来说，值无需改变，只交换每项的行列坐标即可。可是如果我们规定输出三元组要按行号排列，那么交换完的记录顺序可能不再正确。普通转置可以逐个输出行号扫描原项，简单但会重复扫描；快速转置想解决的正是“如何一次知道每项应该写到哪”。

## 06.5 快速转置：从计数到起点，再把元素放进预留区间 {#v4-fast-transpose}

我们先不要看算法代码，先准备一个只含六个非零项的例子。假设原矩阵有四列，扫描全部三元组后发现各列非零项个数为：

<code>count=[2,0,1,3]</code>。

转置以后，原第 0 列成为新第 0 行，因此新第 0 行需要连续两个输出位置；原第 1 列没有非零项，新第 1 行需要零个位置；新第 2 行需要一个；新第 3 行需要三个。如果输出数组按新行号从小到大排，我们可以先计算每行的**起始下标**：

| 转置后行号 | 非零项数 count | 输出区间起点 start | 该行输出区间 |
|---:|---:|---:|---|
| 0 | 2 | 0 | 0、1 |
| 1 | 0 | 2 | 空 |
| 2 | 1 | 2 | 2 |
| 3 | 3 | 3 | 3、4、5 |

因此 <code>start=[0,2,2,3]</code>。这实际上是 count 的**排他前缀和**：第 c 行的起点等于所有行号小于 c 的非零项数之和。

现在逐个扫描原三元组 (r,c,value)，因为它在转置后属于新第 c 行，所以直接放入输出数组的 <code>start[c]</code> 位置，并将 start[c] 增加一，为同一新行的下一项预留位置。比如遇原项 (4,3,9)，它变为新三元组 (3,4,9)，应该放在最初的新第 3 行起点，即下标 3；放入后 start[3] 从 3 变成 4。

为什么不会覆盖别的行？因为开始时我们就按每行需要的项数划分好了互不重叠的输出区间；每放一个元素，就让该行的“下一空位”向右移动一次。全部 t 个三元组只需扫描一次，统计 count 和计算 start 需要 O(cols+t)，填充也为 O(t)，因此时间 O(cols+t)。额外的 count/start 工作数组为 O(cols)，输出三元组数组本身为 O(t)。

**把快转置完整跑完。** 我们为计数数组 count=[2,0,1,3] 构造一个真实例子：原矩阵 5 行、4 列，原始三元组已按行优先排序为 (0,0,4)、(0,3,8)、(1,3,9)、(2,2,6)、(3,0,7)、(4,3,5)。你可以先独立验证：第 0 列有 2 个非零项，第 1 列 0 个，第 2 列 1 个，第 3 列 3 个。

根据 count 算出新矩阵每行的起点 start=[0,2,2,3]。第二遍依次扫描原项，用它的旧列号 c 找新行的当前写入下标 start[c]，放入 (c,r,value) 后再把 start[c] 加一。下面表格展示了**每一次真正写入输出数组的动作**：

| 原三元组 | 写入的新下标 | 转置后的三元组 | 写入后的 start |
|---|---:|---|---|
| (0,0,4) | 0 | (0,0,4) | [1,2,2,3] |
| (0,3,8) | 3 | (3,0,8) | [1,2,2,4] |
| (1,3,9) | 4 | (3,1,9) | [1,2,2,5] |
| (2,2,6) | 2 | (2,2,6) | [1,2,3,5] |
| (3,0,7) | 1 | (0,3,7) | [2,2,3,5] |
| (4,3,5) | 5 | (3,4,5) | [2,2,3,6] |

最终输出依下标 0 至 5 排列为 (0,0,4)、(0,3,7)、(2,2,6)、(3,0,8)、(3,1,9)、(3,4,5)。读表时注意，start 记录的是**每个新行下一个空位置**，写入位置可能交错，因此不能直接把第二遍访问到的原项顺序照抄成输出顺序。

下面实现的是课件第 40—44 页的快速转置思路，并对越界下标作了检查；输入约定为合法三元组按原行、再按原列排序。若输入乱序，转置后各行内的列号也可能乱序，需额外排序。

~~~cpp
#include <vector>
#include <stdexcept>

struct Triple {
    int row, col, value;
};
struct SparseResult {
    int rows, cols;
    std::vector<Triple> terms;
};
SparseResult fastTranspose(int rows, int cols,
                           const std::vector<Triple>& a) {
    if (rows < 0 || cols < 0)
        throw std::invalid_argument("negative dimensions");
    std::vector<int> count(cols, 0), start(cols, 0);
    for (const auto& t : a) {
        if (t.row < 0 || t.row >= rows || t.col < 0 || t.col >= cols)
            throw std::invalid_argument("triple outside matrix");
        ++count[t.col];
    }
    for (int c = 1; c < cols; ++c)
        start[c] = start[c-1] + count[c-1];
    SparseResult b{cols, rows, std::vector<Triple>(a.size())};
    for (const auto& t : a) {
        int dst = start[t.col]++; // 先用位置，后移指针
        b.terms[dst] = Triple{t.col, t.row, t.value};
    }
    return b;
}
~~~

计数 O(t)，算每行起点 O(cols)，分配每个非零项 O(t)，因此总时间 O(cols+t)，辅助计数空间 O(cols)，输出空间 O(t)。课件中的普通转置需要为每个原列反复扫描全部 t 个三元组，代价 O(cols·t)。在分析复杂度时请保留列数 cols 与非零项数 t，避免将两个独立量混成一个 n。

## 06.6 正交链表：当“按行找”和“按列找”同样重要 {#v4-orthogonal}

三元组表把非零项按某一种顺序排列得很紧凑，但若矩阵需要频繁动态插入、删除非零项，或者经常分别遍历某行与某列，单一顺序可能不够方便。

可以让每一个非零结点拥有两条链接：right 指向同一行的下一个非零项，down 指向同一列的下一个非零项。再分别为每一行、每一列保存入口指针，这样从某个行入口沿 right 能枚举该行，从列入口沿 down 能枚举该列。两种链表交叉于相同的非零项结点，因此叫**正交链表**。

需要两条指针的理由很具体：某个非零项同时属于一行和一列，而“下一项”的含义取决于你是沿行走还是沿列走。仅有一条 next 很难同时高效表达这两种独立遍历次序。代价是额外的指针空间和更复杂的插删维护。它与三元组表的关系是典型的时间—空间取舍，而非谁无条件更好。

**用一次插入看清双链维护。** 假设矩阵有 3 行、4 列，依次插入 (0,2,5)、(2,1,7)、(2,3,9)。插入 (2,1,7) 时，它既属于第 2 行的 right 链，又属于第 1 列的 down 链。插入 (2,3,9) 后，从第 2 行入口沿 right 会依次访问 (2,1,7)、(2,3,9)；从第 1 列入口沿 down 只访问 (2,1,7)。**行链和列链必须指向同一个结点**，否则更新一个位置的值就要同步两份冗余数据。

假定行链按列号升序，列链按行号升序。插入新结点 x 时，分别找到它在行链和列链的前驱。先将 x.right 接到原行后继、x.down 接到原列后继；随后让两个前驱或对应的入口指针指向 x。删除时按相反逻辑，必须从两条链都摘下 x 以后才释放。若只修复行链就释放，列链仍保留指向已释放内存的地址，之后遍历会产生未定义行为。

下面的最小 C++17 示例实现有序插入和按行遍历。它只接受非零值；对重复坐标直接改值。使用 unique_ptr 保证结点在矩阵对象存活期间始终有效，示例未实现删除操作：

~~~cpp
#include <memory>
#include <vector>
#include <stdexcept>

struct OrthNode {
    int row, col, value;
    OrthNode *right = nullptr, *down = nullptr;
};
class OrthSparseMatrix {
    int rows, cols;
    std::vector<OrthNode*> rowHead, colHead;
    std::vector<std::unique_ptr<OrthNode>> owner;
public:
    OrthSparseMatrix(int r, int c)
        : rows(r), cols(c),
          rowHead(r < 0 ? 0 : r), colHead(c < 0 ? 0 : c) {
        if (r < 0 || c < 0)
            throw std::invalid_argument("negative dimensions");
    }
    void put(int r, int c, int value) {
        if (r < 0 || r >= rows || c < 0 || c >= cols || value == 0)
            throw std::invalid_argument("invalid sparse entry");
        OrthNode** rp = &rowHead[r];
        while (*rp && (*rp)->col < c) rp = &((*rp)->right);
        if (*rp && (*rp)->col == c) {
            (*rp)->value = value;
            return;
        }
        OrthNode** cp = &colHead[c];
        while (*cp && (*cp)->row < r) cp = &((*cp)->down);
        auto node = std::make_unique<OrthNode>();
        node->row = r; node->col = c; node->value = value;
        OrthNode* x = node.get();
        x->right = *rp;
        x->down = *cp;
        owner.push_back(std::move(node));
        *rp = x;
        *cp = x;
    }
    std::vector<int> rowValues(int r) const {
        if (r < 0 || r >= rows) throw std::out_of_range("row");
        std::vector<int> ans;
        for (auto* p = rowHead[r]; p; p = p->right)
            ans.push_back(p->value);
        return ans;
    }
};
~~~

本例中沿第 2 行搜索前驱，最坏需要遍历该行的非零结点；沿第 3 列也一样，因此插入代价与该行和该列的非零项数有关。若需要大量删除，还应加入双链摘除和内存管理。对于只做一次批量转置的任务，三元组数组的代码更短；对于经常增删并同时按行、按列访问的矩阵，正交链表提供了不同的时间与空间取舍。

## 06.7 章节练习：从计数重新推回公式 {#v4-array-exercises}

<details class="question"><summary>练习 1｜二维数组行列地址（基础，10 分）</summary>

**题目。** 二维数组 A 具有 4 行、6 列，行列下标从 0 开始，每项 8 字节。若 A[0][0] 的首地址为 base，分别求**行优先**和**列优先**存储时 A[2][3] 相对 base 的元素偏移和字节偏移。要求解释每项公式中的乘数。

**思路。** 行优先跨过 2 整行，每行 6 项；列优先跨过 3 整列，每列 4 项。

**解答。** 行优先元素偏移 2×6+3=15，字节偏移 15×8=120；列优先元素偏移 3×4+2=14，字节偏移 14×8=112。地址分别为 base+120 与 base+112。两个结果不同，因为实际线性存储顺序不同。

</details>

<details class="question"><summary>练习 2｜对称矩阵下三角压缩（作业同级，10 分）</summary>

**题目。** 一个 5 阶对称矩阵按行优先只保存下三角（含主对角线），B 的下标从 0 开始。求 B 的总项数，并求 A[1][4] 的压缩下标。解释为何需要先转换矩阵坐标。

**思路。** 用对称性将上三角查询变成下三角查询；前 i 行存储 1+2+...+i 项。

**解答。** B 总项数 5×6/2=15。A[1][4]=A[4][1]，所以位置 k=4×5/2+1=11。若直接把 i=1、j=4 代入下三角公式，会违反 i≥j 的适用前提。

</details>

<details class="question"><summary>练习 3｜三对角矩阵的反向定位（作业同级，10 分）</summary>

**题目。** 7 阶三对角矩阵只保存满足 |i−j|≤1 的位置，0-based 按行压成一维 B。已知 B[12] 是一个有效项，求它对应的原矩阵行列下标，并说明总共有多少有效存储位置。

**思路。** 先用 k 反求 i，再算 j，最后检查 |i−j|≤1。

**解答。** i=⌊(12+1)/3⌋=4，j=12−2×4=4，得到 A[4][4]。有效位置共有 3×7−2=19 项，所以 B 的合法下标为 0–18，12 合法。

</details>

<details class="question"><summary>练习 4｜快速转置的三阶段（作业同级，12 分）</summary>

**题目。** 一张原矩阵有 4 列，非零三元组按原行优先存储；统计得到各列非零项数 count=[2,0,1,3]。请计算转置输出每行的起点 start；若扫描到原项 (r=4,c=3,value=9)，应该写入转置输出数组哪一个下标？写入后哪个辅助值改变？

**思路。** start 是 count 的排他前缀和；原列 c 转置后成为新行 c。

**解答。** start=[0,2,2,3]。该项变成 (3,4,9)，新第 3 行目前起点为 3，因此放到输出下标 3；之后 start[3] 自增至 4。若此行前面已有其他非零项已存入，就应使用当时更新后的 start[3]，本题默认这是该行首次遇到的项。

</details>

<details class="question"><summary>练习 5｜稀疏表示的选择（提高，10 分）</summary>

**题目。** 数据集包含一个 1000×1000 的矩阵，但只有 5 个非零值。场景 A 只需要存储、偶尔扫描全部非零项；场景 B 要频繁按行及按列遍历非零项，并动态插删。请为两个场景分别选择三元组表或正交链表，并说明时间、空间与实现复杂度方面的理由。

**思路。** 先问主要访问方式，再考虑是否需要维护两种遍历顺序。

**解答。** 场景 A 优先三元组表：仅保存五项 (行,列,值)，结构简单、空间与非零项数成正比。场景 B 可以采用正交链表：每个非零项分别沿 right、down 参与行与列链，配合行头列头支持两种遍历与局部动态更新；代价是更多链接空间和更复杂的维护。完整二维数组在这个稀疏场景下会保存约一百万个位置，成本明显更高。
