# 第 06 章　多维数组、压缩矩阵与稀疏存储

> 来源：《DSA 4-String》中的数组与特殊矩阵部分。  
> 前置：一维数组、下标、线性表。

## 06.1 二维表格是怎样放进一段连续内存的 {#v4-array-layout}

数学中矩阵 A 有行和列，C++ 中二维数组也有两个下标。但物理内存中连续元素仍是按一个线性顺序排列的。最重要的问题是：给出 A[i][j]，到底要在第几个存储单元找到它？

假设 A 有 3 行、4 列，下标从 0 开始，按行存储：

<pre class="diagram">行 0：a00 a01 a02 a03
行 1：a10 a11 a12 a13
行 2：a20 a21 a22 a23

内存顺序：a00,a01,a02,a03,a10,a11,a12,a13,a20,a21,a22,a23</pre>

位置 A[2][1] 前有两整行，每行四项，共 8 项；本行中还要跳过下标 0 的一项，故线性偏移为 2×4+1=9。一般 m 行 n 列的 0-based 行优先偏移是 <code>i*n+j</code>；元素长 w 字节、首地址 base 时，地址为 <code>base+(i*n+j)*w</code>。

如果存储规则改为列优先，便先跨过 j 整列，每列 m 项，再进入第 i 行，偏移为 <code>j*m+i</code>。公式里出现的 n 和 m 不是凭记忆交换，而是“先跳过多少整行/整列”数出来的。课件中部分旧地址公式有行列参数的笔误，应以这个过程重新推导。

## 06.2 对称矩阵：为什么一半元素不需要再存 {#v4-symmetric}

对称矩阵满足 A[i][j]=A[j][i]。例如 A[1][4] 与 A[4][1] 是同一个值；如果两处都存，就重复占空间。选择只存下三角（包括对角线），第 0 行 1 项，第 1 行 2 项，…，第 i 行 i+1 项。要定位下三角的 A[i][j]（i≥j），前 i 行有 1+2+⋯+i=i(i+1)/2 项，所以 0-based 压缩下标为：

<code>k=i(i+1)/2+j</code>。

当 i<j 时，先换成 A[j][i]，再套公式。举例：5 阶对称矩阵的 A[1][4] 对应 A[4][1]，位置 k=4×5/2+1=11。整个 n 阶矩阵只需 n(n+1)/2 个元素。题目若按上三角存储或按列压缩，需重新数已存项，不能照搬这个下三角行优先公式。

## 06.3 三对角矩阵：为什么只有 3n−2 个有效位置 {#v4-tridiagonal}

三对角矩阵规定只有主对角线和紧贴它的上下两条对角线可能非零，其他全为零。n=5 时各行有效元素数量分别是 2、3、3、3、2，总数 13=3×5−2。一般 n≥2 的 n 阶三对角矩阵有效项为 3n−2。

按行把它们存入一维数组 B，0-based 的 A[i][j] 若满足 |i−j|≤1，则压缩位置可写作 <code>k=2i+j</code>。例如 n=7、A[4][4] 对应 k=2×4+4=12。反推时 <code>i=(k+1)/3</code>（整数除法向下取整）、<code>j=k−2i</code>，必须同时保证 k 属于有效范围、映射出来的 (i,j) 位于对角带内。

这个公式不能用于带外位置：A[0][4] 本来应视为零，不应该把它错误地映射到 B[4]。

## 06.4 稀疏矩阵：为什么不能为每个零存一个位置 {#v4-sparse}

如果 1000×1000 的矩阵只有 5 个非零项，为每个位置都存一个整数会浪费绝大多数空间。可以用**三元组**记录 (行号、列号、值)，只记录真正非零的元素。比如非零项是 A[0][2]=5、A[2][1]=7，我们只保存 (0,2,5)、(2,1,7)。

矩阵转置要求把 A 的行列互换，所以原项 (0,2,5) 变成 (2,0,5)，原项 (2,1,7) 变成 (1,2,7)。如果输出三元组还要按新行号排序，单纯交换坐标后可能需要重新排序；课件因此讨论普通转置和快速转置两种策略。

## 06.5 快速转置：先数每行该有多少项，再一次放到正确位置 {#v4-fast-transpose}

对输出矩阵而言，它的“新第 c 行”来自输入矩阵的“原第 c 列”。因此先扫描所有非零三元组，统计原各列非零项数 count[c]。例如原矩阵有四列，统计为 [2,0,1,3]，一共六个非零项。

新矩阵第 0 行有 2 项，故从输出位置 0 开始；第 1 行有 0 项，仍从 2 开始；第 2 行有 1 项，也从 2 开始；第 3 行有 3 项，从 3 开始。于是开始位置数组为 <code>start=[0,2,2,3]</code>。

接着按输入三元组次序逐项扫描。对于原项 (r,c,value)，目标输出下标是 start[c]；将 (c,r,value) 放到此处之后，把 start[c]++，供该列下一项使用。每个三元组只移动一次，统计和填充合起来需要 O(cols+terms) 时间，额外 start/count 数组为 O(cols)，输出本身存 terms 项。

<pre class="diagram">count:   [2,0,1,3]
start:   [0,2,2,3]
若遇到原项 (r=4,c=3,value=9)
输出三元组 (3,4,9) 放在新数组下标 3
然后 start[3] 改为 4。</pre>

关键不变量是“每个新行都有预留的连续输出区间”。如果没有先计算前缀和，就不知道一个来自列 3 的项应该写在整个输出数组的什么位置。

## 06.6 正交链表：何时要付出更多指针开销 {#v4-orthogonal}

三元组数组适合稀疏但相对静态的矩阵，访问某行某列全部非零项可能还要扫描许多记录。若矩阵不断动态增删非零项，可让每个非零结点同时有两条链接：指向同一行下一个非零项的 right，和同一列下一个非零项的 down。行头指针与列头指针分别引导两类遍历，构成**正交链表**。

为什么每个结点需要两个方向？因为同一个非零值同时属于一行和一列；两种访问顺序不能用一条单链同时自然表达。代价是额外的指针存储和更复杂的插删维护。
