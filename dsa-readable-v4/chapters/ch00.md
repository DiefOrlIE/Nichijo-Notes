# 第 00 章　C++ 指针与结点

<p class="chapter-epigraph">弄明白“改动的是谁”</p>

> **本章定位**：数据结构课程中链表、树和各种动态结点算法的阅读前置。本章是配套补充教学，旨在填平 C++ 代码理解上的缺口。  
> **已知知识**：变量、if、for、函数参数、普通数组。  
> **学完应能做**：画出对象与指针之间的指向关系；解释传值与引用；在不断链的前提下插删结点；找出 use-after-free 和头指针丢失等错误；独立手写单链表逆置。

数据结构刚开始出现指针时，很多代码看上去只是一串箭头：<code>p->next=q</code>、<code>q=p->next</code>、<code>head=head->next</code>。只要把其中两句交换，最终结果就可能大不相同。真正困难的地方是：读代码时我们必须同时区分“指针变量本身”“指针所指向的结点”“结点里的下一条链接”。本章先把这三类对象分开，让后面的链表与树能够建立在明确的理解之上。

## 00.1 指针与内存地址 {#v4-memory}

<p class="section-epigraph">从一个整数开始：地址与内容的区别</p>

想象你在宿舍储物柜里放了一本书。书有内容，储物柜有柜号。你可以拿着柜号去找那本书，也可以把书换掉而保持柜号不变。内存中的对象也类似：一个整数变量 a 在某段存储空间里保存数值，同时那段空间有地址。C++ 中 <code>&a</code> 表示“取出 a 的地址”，而 <code>int* p=&a</code> 让 p 保存这个地址。

先看几行代码。在读结果前，可以在草稿纸上画两个方框 a、b，再画一根从 p 指出去的箭头：

~~~cpp
int a = 4;
int b = 9;
int* p = &a;  // p 保存 a 的地址
*p = 6;       // 经由地址修改 a
p = &b;       // 改为保存 b 的地址
*p = 2;       // 经由新地址修改 b
~~~

开始时 p 指向 a。第四句 <code>*p=6</code> 访问的是 p 当前所指向的整数，因此 a 从 4 改为 6。第五句 <code>p=&b</code> 改变的是 **p 保存的地址**：它不再指向 a，改为指向 b。最后 <code>*p=2</code> 修改 b。程序结束 a=6、b=2。把这三个动作分别写成“改内容、改指向、改新内容”，便不会混淆。

这里的符号 <code>*</code> 有两种用法：在 <code>int* p</code> 中，它声明 p 是指向 int 的指针；在表达式 <code>*p</code> 中，它表示“沿指针找到所指对象”。同一符号在不同语法位置承担不同角色，读代码时应结合上下文区分。

如果 <code>p=nullptr</code>，它明确表示当前没有指向有效对象。此时直接写 <code>*p=3</code> 会访问不存在的对象，程序行为无定义。同样，刚声明却未初始化的局部指针 <code>int* q;</code> 也不能立刻解引用。以后每次看到 <code>p->next</code>，都要先问：p 是否确实指向一个仍然存在的结点？

## 00.2 指针传参与引用 {#v4-pointer-passing}

<p class="section-epigraph">为什么函数改了指针，调用者却可能看不到</p>

假设我们在函数外写 <code>int a=3; int* p=&a;</code>，把 p 传给一个函数。普通函数参数会获得一份**指针值的副本**，也就是说函数内部和外部各有一个指针变量，但两者最初保存的是同一个整数 a 的地址。

这就产生了很重要的差异：

~~~cpp
void changeNumber(int* q) { *q = 7; }
void changePointer(int* q) { q = nullptr; }
void reallyChangePointer(int*& q) { q = nullptr; }
~~~

调用 <code>changeNumber(p)</code> 后，外部 a 会变成 7，因为形参 q 沿地址找到了与外部相同的整数对象。调用 <code>changePointer(p)</code> 后，外部 p 仍然指向 a，因为函数内部只是把**局部指针副本**改成了 nullptr。最后调用 <code>reallyChangePointer(p)</code>，外部 p 才会被改为 nullptr，因为 <code>int*&</code> 的意义是“一个 int* 指针变量的引用”，函数操作的是调用者的那个指针变量本身。

这个区别以后会反复出现在“删除链表第一个结点”“往空树插入第一个结点”等操作里。如果函数必须改变外部的 head，它要么接收指针引用 <code>Node*& head</code>，要么返回新头指针并要求调用者写 <code>head=f(head)</code>。只传一个普通指针参数然后在函数内部给它重新赋地址，并不能自动改变调用者的指针。

还要记住：把 head 设置为 nullptr 不等于释放原先所有结点。它可能让原链变成无法到达的一串动态对象，从而造成内存泄漏。**修改指针的值**和**结束对象的生命周期**是两种不同的动作。

## 00.3 结点结构与动态分配 {#v4-nodes}

<p class="section-epigraph">第一次创建结点：数据域与链接域分别是什么</p>

普通数组把若干元素紧挨着存放，知道首项位置和下标便能找到第 i 项。链表则允许各个元素分散在不同地址，因此必须另外保存“下一项在哪里”。最简单的结点由两部分构成：数据域 <code>value</code> 和链接域 <code>next</code>。

~~~cpp
struct Node {
    int value;
    Node* next;
};

Node* first  = new Node{10, nullptr};
Node* second = new Node{20, nullptr};
first->next = second;
~~~

这三行创建的关系可画成：

<pre class="diagram">first ──→ [10 | next] ──→ [20 | nullptr]
                                ↑
                              second</pre>

<code>first</code> 和 <code>second</code> 只是两个保存结点地址的指针变量；两个 <code>new Node</code> 各自申请了一个真实的结点对象。<code>first->value</code> 是 <code>(*first).value</code> 的简写，而 <code>first->next</code> 保存第二个结点地址。能否把某条链顺着走下去，完全取决于 next 是否连接正确。

现在希望在值 10 与 20 之间插入值 15 的新结点。想象你需要改动一条通向第二结点的道路：如果提前把这条道路盖掉，又没有保存第二结点的位置，就无法再找到旧后继。因此正确做法一定是**先让新结点找到原后继，再让前驱指向新结点**。

~~~cpp
Node* middle = new Node{15, nullptr};
middle->next = first->next;  // 先保存 20 的地址
first->next  = middle;       // 再让 10 指向 15
~~~

得到 10→15→20。你可以把这两次赋值逐句读成：“15 先接向 20”“10 再改接向 15”。倘若先执行 <code>first->next=middle</code>，随后再写 <code>middle->next=first->next</code>，middle 读到的已经是它自己的地址，于是会生成一个指向自身的环，原结点 20 也可能失去从 first 可达的路径。

**先保存仍需使用的旧链接**，是链表插入、删除、逆置、合并中的核心习惯。之后我们会把它称为维护“未处理部分依然可达”的不变量。

## 00.4 链接修改与结点删除 {#v4-delete}

<p class="section-epigraph">删除结点与删除链接：为什么释放必须放在最后</p>

设链表此时为 10→15→20。要删除中间的 15，目标实际上包含两个动作：在逻辑结构中跳过它，以及结束这个动态结点的生命周期。两个动作都有必要，顺序也有要求。

先用 q 保存要删除的结点地址；把前驱 10 的 next 改接到 q->next，即 20；完成链接以后才 delete q：

~~~cpp
if (first != nullptr && first->next != nullptr) {
    Node* q = first->next;
    first->next = q->next;
    delete q;
}
~~~

删除之后我们仍能从 first 找到 20。若提前 <code>delete q</code>，然后再读取 <code>q->next</code>，便访问了生命期已经结束的对象，称为释放后使用（use-after-free）；其结果没有语言保证。另一个常见错误是执行 <code>delete q</code> 两次，或者把 q 释放后又当成有效结点加入别的链。

注意链表的“头结点”约定。有的教材让 head 直接指向第一个有效数据结点；有的教材额外分配一个不存有效数据的哨兵结点，真正第一项是 <code>head->next</code>。两种链表删除首项时需要更新的指针位置不同。遇到程序填空题，**首先确定 head 本身是不是一个有效数据结点**，否则即使每条赋值语句语法正确，逻辑也可能全部错位。

## 00.5 单链表原地逆置 {#v4-reverse}

<p class="section-epigraph">逆置链表：每轮既要转方向，也要保住后半段</p>

设有单链表 <code>1→2→3→nullptr</code>，希望变成 <code>3→2→1→nullptr</code>。只把 head 改为 3 的地址远远不够，因为原来 3 的 next 仍然为空，2、1 也不会自动反向。我们必须逐条修改 next 链接。

这里值得先提出一个限制：每当我们把当前结点的 next 反转，原先的后继地址就会被覆盖。如果没有提前保存它，整个未处理后半段便可能断链。所以我们需要三个角色：

- <code>cur</code>：当前要反转的结点；
- <code>prev</code>：已经反转完的链表的头；
- <code>next</code>：在覆盖 <code>cur->next</code> 之前保存的原后继。

从 prev=nullptr、cur=1 开始，一轮轮执行：

| 本轮开始时 cur | 暂存 next | 反转后已处理链 prev | 尚未处理链 |
|---|---|---|---|
| 1 | 2 | 1→nullptr | 2→3 |
| 2 | 3 | 2→1→nullptr | 3 |
| 3 | nullptr | 3→2→1→nullptr | 空 |

第二列记的始终是**修改之前**的原后继，所以不会在反转过程中丢掉未处理链。读完表后，代码几乎可以逐行从口头步骤翻译出来：

~~~cpp
Node* reverse(Node* head) {
    Node* prev = nullptr;
    Node* cur  = head;

    while (cur != nullptr) {
        Node* next = cur->next;  // 保留原链后半段
        cur->next  = prev;       // 当前结点改向已完成部分
        prev = cur;              // 已完成部分增加当前结点
        cur = next;              // 继续原链的下一个结点
    }
    return prev;
}
~~~

循环里始终成立的两件事是：prev 链已经被正确反转，cur 链仍保留原来的顺序、且没有被丢弃。每轮从 cur 中取出一个结点放进 prev，最终 cur 为空，全部结点都已经被反向连接。由于每个结点只操作一次，时间 Θ(n)；不申请与 n 成比例的新数组，额外空间 Θ(1)。

空链表时 cur 一开始就是 nullptr，直接返回 nullptr；单结点链表只执行一轮，将 next 设为 nullptr，最终返回该结点。写链表算法时要主动检查这些边界，而不要等在线评测失败以后才想到。

## 00.6 对象生命周期与指针安全 {#v4-lifetime}

<p class="section-epigraph">指针、引用与动态对象的使用边界</p>

到这里我们已经见到三类操作：通过指针访问对象、改变指针指向、通过 <code>new</code>/<code>delete</code> 管理对象生命周期。使用哪一种取决于要表达的关系。

若函数只需要读取一个对象，<code>const T&</code> 可以避免复制并阻止修改；若需要修改调用者的现有对象，用 <code>T&</code> 或有效指针都可以；若“可能没有对象”是题目中的合法状态，<code>T*</code> 与 nullptr 往往更自然。比如查找 BST 中某个键，找不到时可以返回 nullptr。若还需要更换树根，函数可以返回新的 <code>Node*</code>，调用方再接住它。

本课程中的链表、树经常直接使用原始指针。这样能够清楚地展示链接的变化，但也意味着程序员要认真考虑谁负责删除结点、何时不能再读该地址。工程代码可能借助 <code>std::unique_ptr</code> 等工具表达所有权；考试中如果给的是 <code>Node*</code>，你仍需要知道实际地址链接和内存生命周期规则。

最后再提醒一种容易被误认为“无害”的行为：在 C++ 中，指向数组首元素的指针继续向前递减，构造出数组起始位置之前的指针，也不具有普遍合法性。编程题必须以语言对合法指针范围的规定为准，不能因为某次运行打印了预期结果，就认定代码没有未定义行为。

## 00.7 本章综合练习 {#v4-pointer-exercises}

<p class="section-epigraph">章节练习：从画地址开始检查每一步</p>

#### 练习 1｜值与地址的逐句追踪（基础，8 分）

**题目。** 以下代码均在同一函数内顺序执行，所有整数变量都仍存活：

~~~cpp
int a = 5, b = 8;
int* p = &a;
*p = 1;
p = &b;
*p += 2;
~~~

请画出 p 在每句之后指向谁，写出最终 a、b 的值，并解释为什么第二次给 p 赋地址不会改变 a。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 画两个对象方框 a、b，只画一根 p 的箭头；读到 <code>*p</code> 才沿箭头改对象，读到 <code>p=&b</code> 只改箭头起点。

**解答。** p 初始指向 a，<code>*p=1</code> 让 a=1；随后 p 改指 b，a 的内容保持 1；最后 <code>*p+=2</code> 修改 b，从 8 变为 10。因此最终 a=1、b=10，p 指向 b。

**易错点。** 把 <code>p=&b</code> 误认为“把 b 的值复制给 a”。

</details>



#### 练习 2｜插入结点与操作顺序（作业同级，10 分）

**题目。** 定义 <code>struct Node {int value;Node* next;};</code>。原链为 3→5→7，变量 head 指向值为 3 的结点，已经创建了新结点 x，其 value=4、next=nullptr。**不新建其他结点**，请用恰好两条 next 指针赋值语句将 x 插在 3 与 5 之间，并写出每条语句执行后的链关系。说明若把这两条语句交换会发生什么。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 一条用于让 x 记住旧的后继，另一条才用于让 3 改向 x。

**解答。** 先执行 <code>x->next=head->next;</code>，此时 x→5→7，原链仍是 3→5→7；再执行 <code>head->next=x;</code>，得到 3→4→5→7。若倒置赋值，第二条 <code>x->next=head->next</code> 会读到 x 自己的地址，使 x->next=x，原后继 5 失去从 head 出发的可达路径。

**易错点。** 只关心最终画图却忽略“每一次赋值完成以后指针都已经发生变化”。

</details>



#### 练习 3｜函数参数与头指针（作业同级，10 分）

**题目。** 设 <code>Node* head</code> 指向非空链表首项，函数定义为 <code>void skip(Node* h){h=h->next;}</code>。调用 <code>skip(head)</code> 后，外部 head 是否改变？若希望通过函数修改外部 head，请给出两种合法的函数接口；同时解释“跳过旧首项”是否自动释放旧结点。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 明确普通指针形参是否为调用者的指针变量本身，再单独考虑动态对象的生命周期。

**解答。** 外部 head 不变，因为 h 是指针值副本。方法一：<code>void skip(Node*& h){h=h->next;}</code>；方法二：<code>Node* skip(Node* h){return h?h->next:nullptr;}</code>，并在调用点写 <code>head=skip(head);</code>。两种代码都只改变可达首结点，不会自动 delete 原首项。若原首项通过 new 创建并需要释放，应在改变头指针之前保存地址并明确谁负责释放。

**易错点。** 混淆改变变量、改变所指对象和释放对象。

</details>



#### 练习 4｜逆置链表的状态不变量（提高，12 分）

**题目。** 给定链表 <code>1→2→3→4→nullptr</code>，使用 prev、cur、next 三个工作指针原地逆置。初始 prev=nullptr、cur 指向首项。要求写出**每一轮**执行四条赋值后的 prev 链和 cur 链，并说明算法对空表与单结点表为何安全。分析时间和额外空间。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 先保存 <code>next=cur->next</code>，再改变 cur 的 next；每轮应恰好有一个结点从未处理部分进入已经逆置的部分。

**解答。** 第一轮 prev=1→null，cur=2→3→4；第二轮 prev=2→1→null，cur=3→4；第三轮 prev=3→2→1→null，cur=4；第四轮 prev=4→3→2→1→null，cur=null。空表不会进入 while；单结点表只执行一次，结果仍是该结点。每项只处理一次，时间 Θ(n)、辅助空间 Θ(1)。

**易错点。** 如果在保存 next 前就修改 cur->next，就可能失去原链剩余部分的地址。

</details>



#### 练习 5｜删除非尾结点的特殊技巧（提高，10 分）

**题目。** 已知一条只有 next 指针的单链表，手中只有指向某个非尾结点 q 的指针，没有 head 或 q 的前驱指针。允许改动数据域，结点数据可安全复制。能否在 O(1) 时间内实现“让链表在逻辑上不再包含 q 原来的数据项”？如果要求真正释放 q 这个对象本身，又会遇到什么障碍？

<details class="question"><summary>查看思路与解答</summary>

**思路。** 思考能否把 q 的后继结点内容覆盖到 q，然后删除原后继结点。注意这里需要特别声明 q 不是尾结点。

**解答。** 令 r=q->next，复制 <code>q->value=r->value</code>，再让 <code>q->next=r->next</code>，最后 <code>delete r</code>，常数次操作即可从逻辑数据序列中移除 q 原来的值。但实际删除的是 r 对象，q 地址仍然存在且内容被改变。这种技巧不适合尾结点，也不适合对象身份、外部指针或数据复制语义必须保持不变的场景。如果要求物理删除 q，通常需要先找到前驱以修改其 next，仅凭单向 q 指针一般做不到。

**易错点。** 把“删除逻辑数据项”与“释放指定地址的对象”当成同一个要求。

</details>

本章的检查标准很简单：给你两三个结点的链表，不看代码也能说明每条箭头为什么要先改、后改；在释放结点前能指出所有还需要读取的信息已经保存在哪里。这才说明我们真正准备好进入线性表。
