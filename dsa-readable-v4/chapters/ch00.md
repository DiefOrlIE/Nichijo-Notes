# 第 00 章　读懂内存、指针和结点

> **学习位置**：为线性表、树和搜索树建立 C++17 基础。讲义补充前置内容，不属于独立 PPT 章节。  
> **读者已会**：变量、函数、数组和基本循环。  
> **学完能做**：根据代码追踪指向关系；安全插入、删除和逆置链表结点；区分指针的复制与引用；解释越界与悬空。

## 00.1 变量和地址之间到底是什么关系 {#v4-memory}

写下 <code>int a=4;</code> 时，程序在某一块存储空间中保存整数 4。我们可以把它画成一个盒子，盒子有自己的地址。<code>&a</code> 取得这个地址，<code>int* p=&a;</code> 让 p 保存地址，而不是保存一份新的 4。之后 <code>*p</code> 就是通过这个地址访问原来的整数。

~~~cpp
int a=4, b=9;
int* p=&a;   // p 指向 a
*p=6;        // a 变成 6
p=&b;        // 现在 p 指向 b；a 仍然是 6
*p=2;        // b 变成 2
~~~

从上到下追踪得 a=6、b=2。尤其注意第三句：改变指针 <code>p</code> 中保存的地址，和通过 <code>*p</code> 改变它指向的值，是两种不同的操作。

一个容易犯的错误是写 <code>int* p;</code> 后立即用 <code>*p=5</code>。此时 p 没有被赋予有效对象的地址，解引用可能导致未定义行为。只有确认地址有效、对象仍存活，才有权使用 <code>*</code> 访问对象。

## 00.2 为什么函数里的指针修改可能带不出去 {#v4-pointer-passing}

普通形参是实参值的一份复制品。调用 <code>reset(p)</code> 时，函数里得到的指针值与外部 p 相等，都可以指向同一个对象；但函数内部给形参重新赋值，不会改变外部指针变量。若题目要求函数能够修改调用者的头指针，就必须用“指针的引用”或二级指针。

~~~cpp
void changeValue(int* p) { *p=7; }      // 修改所指整数
void wrongReset(int* p) { p=nullptr; }  // 只修改形参副本
void reset(int*& p) { p=nullptr; }      // 修改调用者的指针
~~~

假设外部 <code>int a=3; int* p=&a;</code>：调用 changeValue(p) 后 a=7；调用 wrongReset(p) 后 p 依然指向 a；调用 reset(p) 后 p 才为空。指针引用的类型写作 <code>int*&</code>，理解成“一个 int* 变量的引用”即可。

这里还需要区分“把链表头指针设为空”和“释放原来全部结点”。若链表通过 <code>new</code> 创建，直接把头指针改成空而不释放结点，会丢失内存对象的地址，造成泄漏。

## 00.3 把一个结点放进内存 {#v4-nodes}

链表结点不仅要保存数据，还要保存下一结点的位置。我们先把结点写成如下结构体：

~~~cpp
struct Node {
    int value;
    Node* next;
};
Node* a=new Node{10,nullptr};
Node* b=new Node{20,nullptr};
a->next=b;
~~~

箭头关系是 <code>a → [10|next] → [20|null]</code>。符号 <code>a->next</code> 是 <code>(*a).next</code> 的简写。注意 a、b 是指向结点的指针；真正的结点存储在动态分配的空间里。

如果现在要在 10 和 20 之间插入新结点 x，先想清楚必须保留什么：在修改 10 的 next 之前，必须先保证可以继续找到 20。因此操作顺序是：

~~~cpp
Node* x=new Node{15,nullptr};
x->next=a->next;    // 先把 20 的地址交给 x
a->next=x;          // 再让 10 指向 x
~~~

得到 10→15→20。若倒过来写，旧的下一结点地址可能丢失。这就是链表所有复杂操作都反复使用的局部不变量：**未处理部分始终仍然可达**。

## 00.4 删除和释放：为什么顺序很重要 {#v4-delete}

仍设 a 指向 10，a->next 指向 15，15 再指向 20。删除 a 后面的结点时，我们先用 q 保存 15 的地址；再让 a->next 跳过 15，直接接到 20；最后才释放 q。释放后不可以再通过 q 查看数据或 next。

~~~cpp
if (a && a->next) {
    Node* q=a->next;
    a->next=q->next;
    delete q;
}
~~~

如果先执行 <code>delete q</code>，再读 <code>q->next</code>，程序就访问了已结束生命周期的对象。这称为悬空指针或“释放后使用”（use after free）。

另外，数组下标越界、从数组首元素指针继续向前减，以及多次 delete 同一个结点，都可能引起未定义行为。考试读代码题应分别回答“作者意图是什么”和“根据 C++ 规则是否保证这样的行为”。

## 00.5 逆置链表：三个工作指针的角色 {#v4-reverse}

先不要急着背代码。面对 1→2→3，逆置前应保证还能找到原链后半段。让 <code>prev</code> 表示已经逆置好的前半段，<code>cur</code> 表示当前要处理的结点，<code>next</code> 暂存剩余链表的首结点。

第一轮保存 2，将 1 的 next 改成 null，得到“已逆置 1”和“待处理 2→3”；第二轮保存 3，将 2 指回 1；第三轮把 3 指回 2。结果 3→2→1。

~~~cpp
Node* reverse(Node* head) {
    Node *prev=nullptr, *cur=head;
    while(cur) {
        Node* next=cur->next; // 先保存未处理部分
        cur->next=prev;       // 反转当前链接
        prev=cur;             // 已完成部分扩大一个结点
        cur=next;             // 继续原链后半段
    }
    return prev;
}
~~~

每个结点恰处理一次，时间 Θ(n)；只有常数个工作指针，辅助空间 Θ(1)。空链表时 cur 一开始就为空，直接返回 nullptr。这类算法的完整性来自三件事：未处理部分没丢，已处理部分指向正确方向，循环结束时所有结点已处理。

## 00.6 什么时候该使用引用、指针和动态分配 {#v4-lifetime}

如果函数只需要读一个大的对象，用 <code>const T&</code> 可以避免复制并阻止修改；需要修改对象而不换对象时，用 <code>T&</code>；需要表达“可能没有对象”时，指针配合 nullptr 通常更直观。链表和树需要结点在多个函数调用后仍然存在，所以课堂示例常用 <code>new</code> 创建结点。但新建与删除必须成对考虑，实际工程常用智能指针来表达所有权。本课程先把原始指针语义学清楚，以便读懂课件的代码和考试题。
