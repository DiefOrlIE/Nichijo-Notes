# 第 10 章　堆：如何维护一组元素中的最大或最小值

> 来源：《DSA 5-Tree》堆部分。  
> 先修：完全二叉树及其数组下标规则、复杂度。

## 10.1 为什么反复取最大值时不必每次重新排序 {#v4-heap-motivation}

假设比赛成绩不断传入，系统反复要查询当前最大成绩，还会新增成绩或移除当前最大值。把所有分数始终完整排序当然可以，但插入时为了保持有序，常常要移动许多元素；若每次都遍历寻找最大，弹出又要花 Θ(n)。

有没有一种折中：只让**最大值随时在最前面**，而不强求其他元素严格排序？如果给完全二叉树中的每一条父子边加一条规则“父结点不小于孩子”，根自然不小于任何后代，因此根就是全局最大。这种结构叫**最大堆**（max-heap）；将规则反向得到最小堆。

## 10.2 堆必须同时满足形状和大小两个条件 {#v4-heap-definition}

堆有两条独立约束：第一，结构是一棵完全二叉树，可用数组紧凑存储；第二，每个父结点的关键码不小于子结点（最大堆）或不大于子结点（最小堆）。最大堆 [9,7,8,3,5,6] 合法，因为 9≥7,8；7≥3,5；8≥6，但 7 与 8、3 与 6 的相对大小并不受约束。

在 0-based 数组里，下标 i 的父结点为 (i−1)/2（i>0），左右孩子分别 2i+1、2i+2（如果没有超过数组最后下标）。这不是额外记忆的神秘公式，而是完全二叉树按层从左到右编号的结果。

## 10.3 插入一个新最大值为什么只需要向上走 {#v4-heap-insert}

例如已有最大堆 [9,7,8,3,5,6]，现在插入 10。为了保证完全二叉树形状，先把 10 放在数组末尾，得到 [9,7,8,3,5,6,10]。此时除了“新结点 10 可能比父结点更大”，其他原有父子关系都没被改变。

10 的父结点是下标 2 的 8，交换后变成 [9,7,10,3,5,6,8]；10 到了下标 2，再与根 9 交换，得到 [10,7,9,3,5,6,8]。现在 10 已经是根，整个堆恢复合法。

因此插入法只沿新结点到根的一条路径上浮，最多 O(log n) 层，不必重新整理全部数组。

## 10.4 删除根以后为什么需要向下筛选 {#v4-heap-pop}

要弹出最大值，先保存根；为保持完全二叉树形状，把**末尾元素**补到根，再将数组长度减一。新根可能比孩子小，于是选择较大的孩子交换，持续向下直到不再违反堆序。

例如从 [10,7,9,3,5,6,8] 删除根 10，末尾 8 补根得到 [8,7,9,3,5,6]。8 与孩子 7、9 比，较大的 9 应上来，得到 [9,7,8,3,5,6]；下标 2 的 8 只带孩子 6，已合法，结束。

~~~cpp
#include <vector>
#include <algorithm>
#include <stdexcept>
void pushMax(std::vector<int>& a,int x){
    a.push_back(x);
    int i=(int)a.size()-1;
    while(i>0){
        int p=(i-1)/2;
        if(a[p]>=a[i])break;
        std::swap(a[p],a[i]);
        i=p;
    }
}
int popMax(std::vector<int>& a){
    if(a.empty())throw std::underflow_error("empty heap");
    int result=a.front();
    a.front()=a.back();a.pop_back();
    int n=(int)a.size(),i=0;
    while(2*i+1<n){
        int c=2*i+1;
        if(c+1<n && a[c+1]>a[c])++c;
        if(a[i]>=a[c])break;
        std::swap(a[i],a[c]);i=c;
    }
    return result;
}
~~~

上面的 popMax 空间 O(1)，但它假定输入本身已经是合法堆；若从任意数组直接调用，结果没有保证。

## 10.5 两种建堆方法为什么会得到不同数组 {#v4-heap-build}

给 [1,2,5,8,3,6,10,14]。**逐项插入法**从空堆开始，依次插入每个元素并上浮，最终可以得到 [14,10,8,5,3,2,6,1]。

**底向上筛选法**先把全部数组放入完全二叉树位置，再从最后一个非叶结点 i=⌊n/2⌋−1 开始向左处理；每次把当前结点向下筛到合法位置。对相同输入，逐步得到：

<pre class="diagram">初始 [1,2,5,8,3,6,10,14]
i=3  [1,2,5,14,3,6,10,8]
i=2  [1,2,10,14,3,6,5,8]
i=1  [1,14,10,8,3,6,5,2]
i=0  [14,8,10,2,3,6,5,1]</pre>

两者都满足堆序，最终形态可以不同。作业若要求“每加入一个数据后的结果”，应使用逐项插入；若要求“用筛选法调整初始数组”，应使用底向上建堆，不能把两个结果混为一个唯一堆。

## 10.6 为什么底向上建堆只需要 O(n) {#v4-heap-build-cost}

逐项插入的简单上界是每项上浮 O(log n)，共 n 项 O(nlog n)。底向上建堆却可以更快：数组后半部分是叶子，完全不必下沉；底部倒数第二层的结点最多下沉一层，而越靠上的结点数量越少。若按结点**可下沉高度**分组，总工作至多为 <code>n Σ(h/2ʰ)</code> 的常数倍，该级数收敛，因此总时间 O(n)。必须访问初始 n 个项，整体为 Θ(n)。

## 10.7 Top-K：为什么找前 K 大要保存一个最小堆 {#v4-topk}

数据流中不断出现新成绩，目标是始终保存最大的 K 个值。若直接维护一个装有 K 个“赢家”的**最小堆**，堆顶就是这 K 项中最小者，也就是最容易被淘汰的一项。每来新值 x，如果赢家不足 K，直接加入；否则仅当 x 大于堆顶时，弹出最小赢家并加入 x。K=20、数据共 n=100000 项时，时间 O(nlog K)，额外空间 O(K)。

求最小 K 项则应维护最大堆，理由完全对称。选择堆类型时先问“应当迅速淘汰哪一项”，而不是机械地把“求最大”与“最大堆”配对。
