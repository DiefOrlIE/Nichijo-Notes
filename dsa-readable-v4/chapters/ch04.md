# 第 04 章　递归：函数怎样把没做完的工作留在栈里

> 来源：《DSA 3a-Recursion》（24 页），结合栈章节。  
> 本章会细讲过程，不预设读者已理解递归调用栈。

## 04.1 为什么一个函数可以调用自身 {#v4-recursive-task}

求 4! = 4×3×2×1。你可以写循环，也可以利用“要求 4!，先求 3!；要求 3!，先求 2!”这一重复模式。递归（recursion）就是把规模为 n 的任务化成同类但规模更小的任务，并明确一个不再继续拆分的出口。

~~~cpp
long long fact(int n){
    if(n<0) throw std::invalid_argument("negative n");
    if(n==0) return 1;       // 出口 0! = 1
    return n*fact(n-1);      // 规模下降 1
}
~~~

这里既有“规模持续减小”，也有“出口在 n=0”。只有定义自身，却没有保证向出口靠近的函数，不构成可靠的递归算法。

## 04.2 逐层展开：为什么会先算最小的任务 {#v4-recursion-frames}

调用 fact(3) 时，当前函数知道最后还需要“乘 3”，但暂时缺少 fact(2) 的返回值。计算机必须保留当前参数、局部状态与返回位置，这些信息形成一个**调用栈帧**。

<pre class="diagram">fact(3): 等待 3 × fact(2)
  fact(2): 等待 2 × fact(1)
    fact(1): 等待 1 × fact(0)
      fact(0): 返回 1
    fact(1): 返回 1×1=1
  fact(2): 返回 2×1=2
fact(3): 返回 3×2=6</pre>

看到这种图就应分清两条路径：调用向下深入，结果自底向上返回。复杂度的时间是所有层做的工作总和；栈空间只与同时存在的最大层数有关。fact(n) 要 n+1 次调用，因此时间 Θ(n)、栈空间 Θ(n)。

## 04.3 递归正确性：基例与归纳步怎样对应代码 {#v4-recursion-proof}

要证明 fact(n) 计算正确，可以沿 n 归纳。基例 n=0：程序返回 1，等于 0!。归纳假设：对任意小于 n 的非负整数，fact 都返回正确的阶乘。归纳步：对 n>0，程序返回 <code>n*fact(n−1)</code>；由假设 fact(n−1)=(n−1)!，得到 n×(n−1)!=n!。

你会发现：代码的出口对应基例，递归调用对应归纳假设，返回时的乘法对应归纳步。对更复杂的树递归也可以沿同一思路：假设对子树处理正确，再说明如何合并得到整棵树的正确答案。

## 04.4 递归与循环：哪些状态必须自己保存 {#v4-recursion-iteration}

求阶乘完全可以通过 for 循环积累，避免递归栈。但不是把函数中的递归调用简单替换成 while 就一定正确。观察下面输出的顺序：

~~~cpp
void print1ToN(int n) {
    if(n<=0) return;
    print1ToN(n-1);
    std::cout<<n<<" ";
}
~~~

调用 print1ToN(3) 会输出 1 2 3，因为输出发生在子调用返回之后。若写成“进入函数就输出 n，再递减 n”，反而会输出 3 2 1。转换为循环时，必须识别递归**返回之后还要做什么工作**；必要时显式建栈保存那些尚未完成的动作。

递归尾调用是另一种情形：函数最后一步直接返回递归结果，无须保存额外的返回后计算。某些尾递归更容易改成循环，但 C++ 编译器是否自动做尾调用优化不保证，应以实际栈空间需求分析为准。

## 04.5 汉诺塔：同一个子任务出现两次 {#v4-hanoi}

假设三根柱子 A、B、C，n 个大小不同圆盘都放在 A，目标是全部移到 C；一次只能移动一个盘，且大盘不能放小盘之上。要移动最底下最大的盘，必须先把上面 n−1 个小盘移到 B，才能把最大盘 A→C，然后把 B 上的 n−1 个小盘搬到 C。

由此得到“搬 n−1、搬一次最大盘、再搬 n−1”的递归结构。令 T(n) 为最少移动次数，则 T(0)=0，T(n)=2T(n−1)+1。展开有 T(1)=1、T(2)=3、T(3)=7、T(4)=15，一般为 2ⁿ−1。递归树有指数数量的动作，但最长的递归调用路径只有 n 层，因此时间 Θ(2ⁿ)、栈空间 Θ(n)。

## 04.6 Ackermann：嵌套递归为什么必须从内往外算 {#v4-ackermann}

课件和作业中的 Ackermann 函数对非负整数定义为：

- A(0,n)=n+1；
- 当 m>0 时，A(m,0)=A(m−1,1)；
- 当 m>0 且 n>0 时，A(m,n)=A(m−1,A(m,n−1))。

第三种情形的内层 A(m,n−1) 是外层调用的**第二个参数**，不是可以随意交换次序的两个子问题。先固定 m=1，可推出 A(1,0)=A(0,1)=2；再由 A(1,n)=A(0,A(1,n−1))=A(1,n−1)+1，得到 A(1,n)=n+2。之后 A(2,0)=A(1,1)=3，A(2,1)=A(1,A(2,0))=A(1,3)=5，A(2,2)=A(1,5)=7。

~~~cpp
long long ack(int m,long long n) {
    if(m<0 || n<0) throw std::invalid_argument("negative");
    if(m==0) return n+1;
    if(n==0) return ack(m-1,1);
    return ack(m-1,ack(m,n-1));
}
~~~

真实计算中该函数增长极快，递归深度、运行时间和整数溢出都会迅速成为问题。本章只要求理解定义、调用次序和低阶手算，不把大输入当作一般算法性能测试。

## 04.7 用树分析递归的时间与空间 {#v4-recursion-complexity}

面对递归式，先画三层展开：每次产生几个子问题？子问题是否重复？每一层的规模总和怎样变？例如 T(n)=2T(n/2)+n，每层总工作均为 n，约有 log₂n 层，因此 Θ(nlog n)。但树结点计数的递归虽然调用左右两棵子树，其输入结点互不重叠，总访问仍只有 n 次，Θ(n)。朴素 Fibonacci 的重复调用则会反复求相同 F(k)，运行时间呈指数增长。

**复盘：**任何递归程序都应能回答出口是什么、规模凭什么下降、调用前后各有什么状态、总共有多少工作，以及最大同时保留多少栈帧。
