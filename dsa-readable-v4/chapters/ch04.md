# 第 04 章　递归

<p class="chapter-epigraph">理解一次调用怎样等待另一次调用</p>

> **课程来源**：《DSA 3a-Recursion》，并衔接上一章的栈。  
> **先修要求**：会写函数、if 和循环，已经理解栈顶先处理的顺序。  
> **学习目标**：能画出递归调用与返回轨迹，解释基例及规模下降的必要性，独立设计并证明简单递归，手推汉诺塔和 Ackermann，区分时间工作量与调用栈空间。

上一章我们用栈保存尚未处理完的运算符和括号。现在来看一个更有意思的场景：当程序执行到一个函数调用，它也有可能尚未完成当前工作，就必须先去完成另一个函数。等被调用者返回，当前函数才知道下一步该做什么。这些“尚未完成”的函数之间有什么次序？一个函数如果调用的恰好又是它自身，会发生什么？从这里出发，我们才有充分理由学习递归。

## 04.1 递归问题的结构 {#v4-recursive-task}

<p class="section-epigraph">先不要写递归函数：从一个尚未完成的计算开始</p>

假设任务是计算 <code>4! = 4×3×2×1</code>。如果从头设计程序，我们当然可以写一个循环，把 1、2、3、4 依次乘起来。但不妨暂时换一种思路：要求 4!，我们只需要知道 3!，因为 <code>4!=4×3!</code>。而要求 3!，又只需要知道 2!。这意味着“计算 n 的阶乘”可以化为“计算 n−1 的阶乘”，两者是**相同类型、规模不同的任务**。

于是我们很自然地写下 <code>fact(n)=n×fact(n−1)</code>。这句话目前还没有成为完整的算法：它告诉我们如何把任务变小，却没有说明什么时候停止。继续展开 <code>fact(2)=2×fact(1)</code>、<code>fact(1)=1×fact(0)</code>，我们可以选取公认的 <code>0!=1</code> 作为最小任务，并在这里直接返回，不再调用任何函数。

这就是递归的两个基本部分。第一部分是**递归步骤**：把当前任务还原为更小的同类任务；第二部分是**基例**或终止条件：当任务小到足以直接给出答案时，停止继续分解。它们必须共同存在，函数才能完成工作。

~~~cpp
#include <stdexcept>

long long factorial(int n) {
    if (n < 0)
        throw std::invalid_argument("n must be nonnegative");
    if (n == 0)
        return 1;                   // 基例：0! = 1
    return n * factorial(n - 1);    // 缩小任务，并组合结果
}
~~~

请先分清三个角色。参数 n 表示当前任务的规模；<code>factorial(n−1)</code> 提供一个更小任务的结果；最外面的乘 n 则把小任务的结果组合成当前任务的答案。程序运行到 <code>factorial(n−1)</code> 时，当前函数的乘法实际上还没有完成，因为它等待一个返回值。

如果把 <code>n−1</code> 错写为 n，函数会不停地调用相同规模的任务，无法走向 n=0；如果把基例写成“n<0 返回 1”，从 n=4 出发仍可能要经过 n=0、−1 才停止，并且无法保持原来的阶乘定义。设计递归时，必须同时写清**合法输入的范围、基例、每一步如何向基例靠近**。

## 04.2 调用栈与返回 {#v4-recursion-frames}

<p class="section-epigraph">调用栈：谁在等待谁，谁先拿到答案</p>

现在真正追踪一次 <code>factorial(3)</code>。最外层函数想返回 <code>3×factorial(2)</code>，但 <code>factorial(2)</code> 还没有算出来，因此它暂时停在这里，等待下一层调用。下一层又想返回 <code>2×factorial(1)</code>，也只能等待。一直到最内层遇到 n=0，才第一次获得可以立即返回的答案。

把这条调用链看成三类信息：**当前参数、尚待完成的工作、返回位置**。每次调用都需要为自己的局部状态留出一份记录，称为调用栈帧。程序执行时，后调用的函数在栈顶，先调用的函数在栈底。最内层完成后，先弹出它的记录，让上一层继续。这与上一章的“最近压入、最先取出”完全一致。

<pre class="diagram">向下调用（当前函数等待下一层）：
factorial(3) 等待 3 × [factorial(2)]
  factorial(2) 等待 2 × [factorial(1)]
    factorial(1) 等待 1 × [factorial(0)]
      factorial(0) 直接返回 1

向上返回（后调用者先完成）：
    factorial(1) 得到 1，返回 1×1=1
  factorial(2) 得到 1，返回 2×1=2
factorial(3) 得到 2，返回 3×2=6</pre>

有时教材只展示第一半段函数不断调用自身的画面，让人误以为递归永远在“向下走”。实际上，**递归调用过程的一半时间花在返回阶段**：先前保存的工作在这时依次完成。只有把两半都看清，才能真正读懂那些“在递归调用之后再输出”的函数。

更重要的是，时间与空间的计数对象不同。对 <code>factorial(n)</code>，n 从 n、n−1、…、0 下降，共进行 n+1 次函数调用，每次除去子调用只做常数工作，因此时间 Θ(n)。但任何时刻存在的最大栈帧数量也是 n+1，因而额外栈空间 Θ(n)。如果我们将它写成循环，仍做 n 次乘法，但只需要一两个变量，额外空间就可降到 O(1)。

你可以在纸上尝试一个非数值的调用函数：<code>print(n)</code> 先递归调用 <code>print(n−1)</code>，再输出 n。如果传入 3，输出会是 1、2、3，因为输出被放在返回阶段；若把输出语句移动到递归调用之前，顺序立刻变成 3、2、1。这样的变化说明，递归里“语句写在调用之前还是之后”确实决定了算法行为。

## 04.3 递归正确性与归纳法 {#v4-recursion-proof}

<p class="section-epigraph">为什么可以相信下一层：递归正确性与归纳法</p>

到这里你可能会提出一个自然的疑问：写 <code>factorial(n)</code> 时，我们怎么有资格假定 <code>factorial(n−1)</code> 已经能够正确计算？如果连当前函数都还没证明正确，调用一个几乎相同的函数，看上去像在循环论证。

解决方法是数学归纳。对于规模为 0 的任务，程序明确返回 1，因此它计算正确。接下来假设对某个比 n 小的规模，程序可以正确给出阶乘；当程序处理 n>0 时，它先调用 <code>factorial(n−1)</code>。这个参数严格比 n 小，所以我们可以应用归纳假设：返回值为 (n−1)!。最外层再乘 n，就等于 n!。由此，规模 n 的任务也正确。

你可以把这种证明视为三个问题：

1. **基例正确吗？** 程序无需递归时，返回了题目要求的值吗？
2. **规模真的变小了吗？** 每次调用会严格向已知基例接近吗？
3. **组合步骤正确吗？** 假设子任务答案没错，当前层能否据此得到正确答案？

对树的递归也完全适用。假设一棵树有根和左右子树，要计算结点总数，可以假定两个子树递归得到各自正确的结点数，再用 <code>1+leftCount+rightCount</code> 得到整棵树的结点数。重要的前提是左右子树规模都比整棵树小，且不会无限循环。递归的思维习惯就是：**把已经严格缩小的子任务当作一个会返回正确答案的黑箱，再认真完成当前层剩下的工作**。

这一点也解释为什么“递归程序能终止”与“递归程序正确”必须分别证明。比如一个函数对 n=1 返回 7、对 n>1 返回 n×f(n−1)，它当然会终止，却无法计算真正的阶乘。终止只能说明答案会产生，并不能证明答案满足问题定义。

## 04.4 递归与迭代 {#v4-recursion-iteration}

<p class="section-epigraph">递归与循环：还没做完的工作究竟存在哪里</p>

既然很多递归程序能够用循环完成，为什么还要学习递归？因为递归提供了一种非常自然的**问题分解方式**：当当前任务结构本来就包含同类子任务，递归能够让代码结构直接反映问题结构。树的遍历就是典型例子。不过，递归也有成本：每次调用都要保存一份状态，极深的递归可能耗尽调用栈。

先看递归版“从 1 输出到 n”的函数：

~~~cpp
#include <iostream>
void printFromOne(int n) {
    if (n == 0) return;
    printFromOne(n - 1);
    std::cout << n << ' ';
}
~~~

为什么 n=4 时得到 1 2 3 4？因为输出语句位于递归调用之后，当前层必须等待 n−1 层先完成。若改为：

~~~cpp
void printFromN(int n) {
    if (n == 0) return;
    std::cout << n << ' ';
    printFromN(n - 1);
}
~~~

输出立即变成 4 3 2 1。由此可知，递归改循环时不能只把“再调用一次”替换成 while；必须先弄清楚当前层在子调用**之前**和**之后**各做什么。若返回后还有操作要执行，就需要考虑如何保存这些尚未完成的操作：可以让循环变量承担，也可能需要一个显式栈。

所谓**尾递归**，指当前层的最后动作直接返回下一次递归的结果，返回之后无事可做。例如：

~~~cpp
long long sumTail(int n, long long acc) {
    if (n == 0) return acc;
    return sumTail(n - 1, acc + n);
}
~~~

它利用 acc 保存已经累计的部分，很容易改成 <code>while(n>0){acc+=n;--n;}</code>。但是“尾递归”在 C++ 中不意味着编译器一定帮你消掉栈帧；空间分析仍须根据实现是否保证优化来判断。

更一般地说，递归和循环各自解决的是**控制过程**的问题，而算法时间高低仍取决于工作量。一个递归函数可以是 O(n)，也可以是 O(log n)，还有可能因为大量重复子问题而呈指数增长。看见递归语法就直接写 O(n) 或 O(2ⁿ)，都缺少必要依据。

## 04.5 汉诺塔问题 {#v4-hanoi}

<p class="section-epigraph">汉诺塔：为什么明明只有一根大盘，还要解决两次子问题</p>

考虑三根柱子 A、B、C。A 上套着 n 个从上到下逐渐变大的圆盘，目标是全部移到 C。规则是一次只能搬一个盘，搬动过程中任何大盘都不能压在小盘之上。这道题的困难从 n=3 就能看出来：最大的盘始终在最下方，若它上面还有任何小盘，就无法直接动它。

因此想搬走最大的盘，必须先把上面的 n−1 个小盘**全部**移动到一根临时柱子 B 上；这样 A 上只剩最大盘，才有资格把它移动到 C。最后还需要把 B 上的 n−1 个盘整体搬到 C，盖在最大盘之上。我们不得不依次完成三个任务：

- 把 n−1 个小盘从 A 移到 B，C 当辅助柱；
- 把最大盘从 A 移到 C；
- 把 n−1 个小盘从 B 移到 C，A 当辅助柱。

请留意第一个和第三个任务：它们都是“将 n−1 个盘从起点移动到终点，借助第三根柱子”，与原题同型，所以适合递归。柱子的名称只是在不同调用中交换角色。

~~~cpp
#include <iostream>
void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;
    hanoi(n - 1, from, to, via);
    std::cout << from << " -> " << to << '\n';
    hanoi(n - 1, via, from, to);
}
~~~

以 n=2 为例：先搬小盘 A→B，再搬大盘 A→C，最后搬小盘 B→C。n=3 时，最外层先完整执行“搬两个小盘到 B”，也就是 A→C、A→B、C→B；再搬最大盘 A→C；最后执行“从 B 搬两个小盘到 C”，也就是 B→A、B→C、A→C，合计七次。

若令 T(n) 表示最少搬运次数，则最外层恰执行两次规模 n−1 的任务以及一次最大盘移动，所以 <code>T(n)=2T(n−1)+1</code>，并且 <code>T(0)=0</code>。连续计算 T(1)=1、T(2)=3、T(3)=7、T(4)=15，可以猜测 <code>T(n)=2ⁿ−1</code>；代入递推验证：若 T(n−1)=2ⁿ⁻¹−1，则 T(n)=2(2ⁿ⁻¹−1)+1=2ⁿ−1。

这是指数级的动作数，意味着盘数稍微增大，实际搬运次数就会迅速增加。但请不要把时间 O(2ⁿ) 与调用栈空间混为一谈：任何一条递归链上，n 每次只下降 1，因此最大递归深度是 Θ(n)，并不同时保存指数个栈帧。

## 04.6 Ackermann 函数 {#v4-ackermann}

<p class="section-epigraph">Ackermann 函数：当子调用的结果还要作为另一个子调用的参数</p>

阶乘只含一层递归调用，汉诺塔在当前层顺次调用两次同类型子任务。课件还介绍了一个更不直观的例子：Ackermann 函数。它的价值在于让我们理解**嵌套递归调用的求值次序**，以及递归增长可能有多快。

本课程使用的定义是，对非负整数 m、n，

- 当 m=0 时，**A(m,n)=n+1**；
- 当 m>0、n=0 时，**A(m,0)=A(m−1,1)**；
- 当 m>0、n>0 时，**A(m,n)=A(m−1,A(m,n−1))**。

这是三种互斥的情况，每次调用先判断自己落在哪一种，再应用相应公式。

第三行最容易读错。比如 <code>A(2,1)=A(1,A(2,0))</code>，外层 A(1,·) 的第二个参数必须先由内层 A(2,0) 算出来。它不是两个平行子问题，不能把它们的结果随便相加、交换顺序。

我们先求出低层函数的规律。对 m=0，有 <code>A(0,n)=n+1</code>。当 m=1、n=0 时，<code>A(1,0)=A(0,1)=2</code>。对 n>0，

对 n>0，可依次改写为 <code>A(1,n)=A(0,A(1,n−1))=A(1,n−1)+1</code>。

因此 A(1,1)=3、A(1,2)=4、A(1,3)=5，归纳得 <code>A(1,n)=n+2</code>。有了这条规律，再求 A(2,1) 就不会陷入重复展开：

| 要求的值 | 展开 | 得到 |
|---|---|---|
| A(2,0) | A(1,1) | 3 |
| A(2,1) | A(1,A(2,0))=A(1,3) | 5 |
| A(2,2) | A(1,A(2,1))=A(1,5) | 7 |

因此 A(2,2)=7。这里每一行都依赖上一行的已知结果。遇到同类题时，不妨先把 m=0 与 m=1 的规律推出，再沿 n 从小到大计算目标，避免在巨大的调用树中迷失。

~~~cpp
long long ack(int m, long long n) {
    if (m < 0 || n < 0)
        throw std::invalid_argument("negative argument");
    if (m == 0) return n + 1;
    if (n == 0) return ack(m - 1, 1);
    return ack(m - 1, ack(m, n - 1));
}
~~~

Ackermann 的增长比普通阶乘递归更加迅猛，实际执行很快就会遇到运行时间、调用栈或整数表示范围的限制。这里展示的 C++ 代码是定义的直接翻译，适用于教学的小输入。考试手算时应先检查输入是否落在非负整数范围，再依定义逐步代入。

## 04.7 递归时间与空间复杂度 {#v4-recursion-complexity}

<p class="section-epigraph">递归时间与空间：应当数的是整棵调用树里的工作</p>

前面学过时间复杂度，但递归需要一种不同的计数视角。一个函数可能只做很少的本层工作，却调用很多子问题；只有把所有子调用的时间合在一起，才能知道整体代价。

先看 <code>T(n)=2T(n/2)+n</code>。它表示当前层花 n 次操作，然后处理两个规模各为 n/2 的问题。若 n=8，调用树第一层花 8；第二层有两个规模 4 的问题，总花 4+4=8；第三层四个规模 2 的问题，总花 2+2+2+2=8；第四层八个规模 1 的问题，总花 8。每层总工作都是 8，层数是 log₂8+1=4，所以总工作与 nlog n 同阶。

再看 <code>T(n)=T(n−1)+n</code>。它每层只递归一次，却依次做 n、n−1、…、1 次操作，总和 Θ(n²)。因此“递归分了几支”不足以直接决定时间；关键在于**各层问题规模的总和及有多少层**。

最需要区分的是**重复子问题**。比如朴素 Fibonacci 程序用 <code>F(n)=F(n−1)+F(n−2)</code>，两个调用分支都会反复计算 F(n−3)、F(n−4) 等相同问题，这会产生指数级的重复工作。如果把已经求得的 F(k) 保存起来，下次直接使用，就能显著减少重复计算，这便是记忆化的基本思想。

空间方面，递归使用的调用栈与**最大同时活动的调用链长度**有关。汉诺塔虽然总调用次数指数级，递归栈最多也只有 O(n) 层；二分递归深度可为 O(log n)；退化二叉树遍历深度可能为 O(n)。分析时始终分别写出“总共做了多少次操作”和“同一时刻保留多少层状态”。

#### 练习 1｜递归调用与返回（基础，8 分）

**题目。** 设函数 <code>f(0)=0</code>、<code>f(n)=n+f(n−1)</code>（n 为正整数）。从 <code>f(4)</code> 开始调用。写出所有调用参数的进入次序、各层返回值，以及最终结果；并分析时间和递归栈空间。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 先从外向内把尚未完成的加法写成“等待”，到 f(0) 后再逐层返回。不要只写一个算术和而省略返回过程。

**解答。** 进入次序 4→3→2→1→0。f(0) 返回 0；f(1)=1+0=1；f(2)=2+1=3；f(3)=3+3=6；f(4)=4+6=10。因此返回序列依次为 0、1、3、6、10，最终结果 10。输入规模 n 时共有 n+1 次调用，每层常数工作，时间 Θ(n)；最深时保留 n+1 层栈帧，额外栈空间 Θ(n)。

**易错点。** 把进入次序误当返回次序，或因为代码里只有一次递归调用就忽略每层保存的状态。

#### 练习 2｜递归语句放置位置与输出（作业同级，8 分）

**题目。** 观察以下函数，假设 <code>n=3</code>，请分别写出 <code>g(3)</code> 与 <code>h(3)</code> 的输出顺序，并解释为什么二者不同。

void g(int n) {

    std::cout << n << ' ';
    g(n - 1);
}
void h(int n) {
    if (n == 0) return;

~~~

<details class="question"><summary>查看思路与解答</summary>

**思路。** 记录每次输出发生在“继续调用前”还是“等待子调用返回之后”，并画出 3→2→1→0 的调用链。

**解答。** g 每进入一层就先输出，所以 g(3) 输出 <code>3 2 1</code>；h 在向下深入时不输出，直到 h(0) 返回后再从 1 层向上输出，因此 h(3) 输出 <code>1 2 3</code>。虽然两者的递归调用参数完全相同，但输出动作放在不同阶段，执行顺序就相反。

**易错点。** 仅根据“n 每次减一”判断输出一定是降序，忽略了递归返回。

</details>



#### 练习 3｜汉诺塔完整手工轨迹（作业同级，12 分）

**题目。** 三根柱子 A、B、C，三个大小不同的圆盘初始都在 A，目标全部移到 C，一次只允许移动一个，且大盘不能压小盘。请列出**完整七次移动**，求 n=4 的最少移动次数，并给出一般 n 的时间和递归栈空间阶。

<details class="question"><summary>查看思路与解答</summary>

**思路。** n=3 的第一次子任务是把上面的两盘 A→B（C 辅助）；随后搬最大盘 A→C；最后把两盘 B→C（A 辅助）。

**解答。** 七次移动依次是 A→C、A→B、C→B、A→C、B→A、B→C、A→C。n=4 时 T(4)=2T(3)+1=2×7+1=15。一般 T(n)=2ⁿ−1，因此时间 Θ(2ⁿ)，同时活动调用帧最多与 n 成正比，栈空间 Θ(n)。可以用“搬完前三步时两个小盘都在 B”检查轨迹没有违反规则。

**易错点。** 把第一次小问题误写成“直接移到终点 C”，却没有给最大盘留出合法移动位置。

</details>



#### 练习 4｜Ackermann 的嵌套调用（作业同级，12 分）

**题目。** 对非负整数 m、n，已知 A(0,n)=n+1；m>0 时 A(m,0)=A(m−1,1)；m>0、n>0 时 A(m,n)=A(m−1,A(m,n−1))。计算 A(2,2)，必须列出 A(1,n) 的规律和依次需要的中间值。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 先处理 m=0 的基例，接着推出 A(1,0)=2，再按 n 递增求 A(1,n)；之后逐个求 A(2,0)、A(2,1)、A(2,2)。

**解答。** A(1,0)=A(0,1)=2；对 n>0，A(1,n)=A(0,A(1,n−1))=A(1,n−1)+1，因此 A(1,n)=n+2。于是 A(2,0)=A(1,1)=3；A(2,1)=A(1,A(2,0))=A(1,3)=5；A(2,2)=A(1,A(2,1))=A(1,5)=7。答案 7。

**易错点。** 遇到 A(1,A(2,1)) 时把两个 A 函数当成并列任务，或者先把外层第二个参数臆测为 1。

</details>



#### 练习 5｜复杂度递推与空间（提高，12 分）

**题目。** 有两个递归程序，输入 n 为 2 的幂。程序甲先做 n 次常数操作，再各调用一次规模 n/2 的两个子问题；程序乙先做 n 次操作，再调用一次规模 n/2 的子问题。两者处理规模 1 时都做常数工作。求各自时间复杂度，并分析在深度优先递归执行下的最大调用栈深度。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 不要直接套公式。先列出前四层的总工作：甲每层问题数翻倍但单个规模减半；乙每层只有一个规模减半的子问题。

**解答。** 甲在每层的总工作均为 n，共 Θ(log n) 层，所以时间 Θ(nlog n)。乙各层工作依次为 n、n/2、n/4、…，几何级数和为 Θ(n)。两者沿任意一条递归路径都按 n→n/2→…→1 缩小，因此最大栈深度均为 Θ(log n)。甲有两个分支，不代表同时保存了整棵调用树的全部结点。

**易错点。** 把递归调用总次数当作递归空间；或只看到 n/2 就断言两者时间一样。

</details>



#### 练习 6｜从递归改成循环（提高，10 分）

**题目。** 下面的尾递归在非负整数 n 上计算 1+2+⋯+n：

~~~cpp
long long sumTail(int n, long long acc) {
    if (n == 0) return acc;
    return sumTail(n - 1, acc + n);
}
~~~

请给出一个不使用递归、等价的 C++ 函数 <code>sumLoop(int n)</code>，并说明循环每轮必须维持的关系，以及时间和额外空间阶。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 尾递归的每一次调用仅更新 n 和 acc，返回之后没有其他工作。把这两个状态直接作为循环变量即可。

**解答。**

~~~cpp
long long sumLoop(int n) {
    long long acc = 0;
    while (n > 0) {
        acc += n;
        --n;
    }
    return acc;
}
~~~

每轮循环把当前剩余的最大整数 n 加到 acc，然后把未处理范围缩减到 1..n−1；因此 acc 始终是**原始输入中已经处理过的那部分整数之和**。循环 n 轮，时间 Θ(n)；不依赖调用栈，辅助空间 Θ(1)。对于负数输入还需额外约定或报错，本题明确只处理非负整数。

**易错点。** 循环里先 <code>--n</code> 再累加，导致漏掉原始的 n。

</details>

**本章的真正收获。** 递归是一种把当前任务分解为同类较小任务的思维方法。调用栈保存尚未完成的当前工作；基例与规模下降保证能够停止；归纳法说明小问题的正确结果如何组合为大问题；递归树则帮助我们数清楚全部工作和同时活动的空间。理解这条完整链条之后，树的遍历和重建就会自然得多。
