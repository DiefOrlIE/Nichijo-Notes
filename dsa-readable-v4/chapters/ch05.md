# 第 05 章　队列、循环数组和优先处理

> 来源：《DSA 3-Stack&Queue》队列及优先级队列部分。  
> 前置：顺序表、链表与栈。

## 05.1 排队的限制为什么恰好与栈相反 {#v4-queue-meaning}

假设食堂的三位同学 A、B、C 按顺序排队。队伍若遵守先来先处理，那么先服务 A，再服务 B，最后服务 C；即使 D 在后面到来，也必须站到队尾。这种**先进先出**（First In, First Out，FIFO）的结构叫队列。它提供 enqueue（入队）、dequeue（出队）、front（查看队首）与 empty（判空）。

如果用栈保存订单，最近来的顾客会先被处理，明显不符合这里的规则。数据结构之所以分栈与队列，是因为操作约束对应了不同任务：函数返回需要“最近调用先结束”，服务排队需要“最早到达先处理”。

## 05.2 数组队列的第一个陷阱：不必把所有元素向左搬 {#v4-queue-array}

设数组长度 5，元素依次入队 2、4、6，三项存下标 0、1、2。出队 2 后，如果把 4 和 6 都搬到左边，虽然正确却浪费。可以只让队首下标 front 从 0 变为 1，此时 4 仍在下标 1、6 仍在 2。队尾之后的第一个空位下标记为 rear=3。

因此约定：**front 指向队首元素，rear 指向下一空位**。在没有回绕且无扩容时，当前有效元素位于 [front,rear) 之间。出队令 front++，入队令 a[rear++]=x。问题是 rear 到了数组末尾，即便前部早已空出来，也无法向右再放。为复用前端空槽，需要让下标回绕成环形。

## 05.3 循环队列：取模不是魔法，只是回到起点 {#v4-ringqueue}

把五个槽画成一个圈：下标 0、1、2、3、4，再从 4 继续前进就回到 0。此时移动下标用 <code>(index+1)%5</code>。如果 front=3、rear=1，说明有效元素可能分布在 [3,4,0] 这几处。

现在出现一个真正的问题：若只存 front、rear，空队列时二者相等；填满整个环形数组后，rear 也可能绕回 front。**同样的下标状态不能区分空与满**。常见解决方案有三种：牺牲一个空槽，或者增加 count 记录实际个数，或者再记一个满/空标记。课堂练习常问前两种，公式绝不能混用。

牺牲一格的版本，空为 <code>front==rear</code>，满为 <code>(rear+1)%m==front</code>，最多放 m−1 项。假设 m=5，front=3、rear=2，沿环形方向已有下标 3、4、0、1 的四项，因此已满；rear=2 是保留的下一空位。

## 05.4 只有 front 和 count：为什么这次可以装满 m 项 {#v4-front-count}

另一种表示只保存 front 和 count。front 仍然是队首，count 是实际元素数。沿环从 front 前进 count 个位置，就抵达**下一次要入队的位置**，所以 <code>rear=(front+count)%m</code> 是一个**可推导出的临时位置**，不需要单独存储 rear。

先做具体手算：m=5、front=3、count=3。有效下标是 3、4、0，下次入队应写下标 (3+3)%5=1。入队后 count=4；再写下标 2，count=5，此时恰好填满全部五格。因为 count 已能识别满和空，所以不必像上一种实现那样故意空出一格。

~~~cpp
#include <array>
template<class T,int M>
class Queue {
    static_assert(M>0);
    std::array<T,M> data{};
    int front=0, count=0;
public:
    bool empty() const{return count==0;}
    bool full() const{return count==M;}
    bool push(const T& x){
        if(full())return false;
        data[(front+count)%M]=x;
        ++count;
        return true;
    }
    bool pop(T& x){
        if(empty())return false;
        x=data[front];
        front=(front+1)%M;
        --count;
        return true;
    }
};
~~~

无论在数组哪个位置操作，入队、出队都执行常数次工作，时间 O(1)。这段实现的边界是：M 必须为正；空队列不能出队；满队列不能覆盖旧元素；它不能被多线程同时修改而不加同步。

## 05.5 链队列：队首和队尾指针要一起维护 {#v4-linkedqueue}

如果队列大小不断变化，链队列可以不预先固定最大容量。保存 first 指向最老数据结点、last 指向最新结点。入队时把新结点接到 last 后，更新 last；出队时保存 first，令 first 指向原来的后继，再释放旧首项。

特殊情况是队列只有一个结点时，出队后 first 会变成 null，此时 last 也必须置空。忘记这一步，会使 last 悬空。常规链队列（已保存首尾指针）的入队和出队均为 O(1)。

## 05.6 队列为什么能实现树的层序遍历 {#v4-queue-applications}

遍历树的一个自然要求是先访问第一层，再访问第二层，最后访问第三层。假设根为 A，两个孩子是 B、C；B 又有孩子 D、E。访问 A 后应先处理 B、C，不能马上深入 D。所以我们让“已经发现、尚未处理”的结点排进队列：A 出队时将 B、C 入队；B 出队时把 D、E 入队；接下来轮到 C，然后才轮到 D、E。最终次序 A,B,C,D,E。

这解释了广度优先搜索（Breadth-First Search，BFS）为何使用队列。相比之下，递归深度优先遍历自然使用调用栈。

## 05.7 优先级队列为什么不能只按到达顺序处理 {#v4-priorityqueue}

急诊分诊时可能要让病情更严重的患者先处理，尽管他们后来才到。这时“最先到达先出队”的规则不再符合任务，我们需要优先级队列（priority queue）：新数据可以入队，但每次弹出当前优先级最高者。课件把它归在队列之后，后面的堆章节会具体实现。

如果直接用无序数组，插入可能 O(1)，但弹出最高优先级需要扫描全部 n 项，O(n)。堆是一种常见平衡取舍：入队 O(log n)、弹出最高优先级 O(log n)、查看堆顶 O(1)。这里先建立动机，等学完完全二叉树再推堆的实现。
