# 第 05 章　队列：让最早等待的任务先得到处理

> **依据**：《DSA 3-Stack&Queue》队列与优先级队列部分。  
> **先修**：栈、数组、链表和取模运算。  
> **目标**：理解 FIFO 的操作语义；在三种数组队列表示中正确判空判满；推导 front/count 队列的位置；解释层序遍历与优先级队列。

上一章的栈把最后加入的元素放在最容易取到的位置。可是假设我们在管理排队取餐的订单，若总是先处理新来的订单，早到的人可能一直等下去。这说明线性结构的操作规则必须服从实际问题。这一次，我们把“谁先被处理”改成**最早加入的元素**。

## 05.1 从排队开始认识 FIFO {#v4-queue-meaning}

有三个任务按 A、B、C 的顺序提交。处理器若要公平地按照到达次序完成它们，应该先完成 A，再 B，最后 C。即使在 B 等待期间又来了 D，也不能把 D 塞到最前面。这种规则称为先进先出（FIFO，First In, First Out），对应的数据结构就是队列（Queue）。

队列有两端：**队尾**负责接收新元素，**队首**负责取出等待最久的元素。入队（enqueue）使数据加入队尾；出队（dequeue）从队首移除；front 查询下一次应出队的元素，但不改变结构。与栈不同，这两个操作端通常分开。

假设空队列依次执行 enqueue(2)、enqueue(4)、dequeue、enqueue(6)、front。状态依次是 [2]、[2,4]、[4]、[4,6]、[4,6]，dequeue 返回 2，front 返回 4。你可以把这个过程画成一条向右行进的队伍：新来的总站最右边，最左边的人先离开。

## 05.2 顺序数组里的空位为何不能一直浪费 {#v4-queue-array}

最直接的顺序队列用数组记录任务。让 front 指向当前队首、rear 指向**下一次入队的空槽**。空队列可以令 front=rear=0。依次入队三个元素以后，它们在数组下标 0、1、2，rear=3；出队一次只要 front 从 0 变为 1，就能把下标 1 的元素变成新队首。

这样做避免了每次出队都搬移剩余数据的代价，入队出队都只改变常数个变量。问题却随之出现：假设数组容量为 5，执行多次入队、出队以后，front 已经到了 3，而 rear 已经等于 5。前面下标 0、1、2 明明有可利用的位置，rear 却无法继续向右。单纯把 rear 一直增加，只能使用数组一次。

我们需要一种让空闲位置循环利用的办法。把数组的末端与首端在逻辑上相接，就得到下一节的循环队列。

## 05.3 为什么循环队列必须额外解决“满与空” {#v4-ringqueue}

把长度 m 的数组看成一个圆环：下标 0、1、…、m−1 后面又是下标 0。下标向前移动一步可以写成 <code>(index+1)%m</code>；取模只是在到达末尾时让下标回到起点，并不会自动移动任何数据。

现在想一想：若仍只记录 front、rear，空队列通常有 front==rear；但如果允许 m 个槽全部放满，rear 向前绕一圈以后也会再次等于 front。**两个完全不同的状态在两个下标上看起来一样**，程序无法区分。因此要在表示法里补充额外信息。

一个常见方案是**故意留出一个空槽**。规定 front 指向首项，rear 指向下一空位；空时 front==rear，满时 <code>(rear+1)%m==front</code>。以 m=5 为例，若 front=3、rear=2，实际有效下标为 3、4、0、1，已经保存 4 项；虽还有下标 2 未被占用，这个空格却必须保留，否则无法区分满与空。所以有效容量为 m−1。

这种表示法没有唯一正确性上的优势，它只是用一个可用槽位换取清晰的判满规则。如果题目给的队列可以装满 m 项，那么一定还采用了别的区分方式，不能再沿用这个满条件。

## 05.4 有 front 和 count 就不必浪费最后一格 {#v4-front-count}

另一种方案记录 front 和 count。仍让 front 指队首，count 指当前真实元素个数。只要有 count，就能直接判断空为 count=0、满为 count=m。由于队列从 front 开始占据连续的 count 个环形位置，**下一次入队位置**就是从 front 前进 count 步：

<code>rear=(front+count)%m</code>。

用实际数据检验。设 m=5、front=3、count=3。有效项占下标 3、4、0，下一空格为 (3+3)%5=1。入队一个新值后 count=4；再入队一个值，写下标 (3+4)%5=2，count=5，恰好五格全满。此时计算下一位置会绕回 front=3，但队列不会因此被认为是空，因为 count 明确记录为 5。

~~~cpp
#include <array>

template<class T, int M>
class CircularQueue {
    static_assert(M > 0);
    std::array<T,M> data{};
    int frontIndex = 0;
    int count = 0;

public:
    bool empty() const { return count == 0; }
    bool full()  const { return count == M; }

    bool enqueue(const T& value) {
        if (full()) return false;
        data[(frontIndex + count) % M] = value;
        ++count;
        return true;
    }
    bool dequeue(T& value) {
        if (empty()) return false;
        value = data[frontIndex];
        frontIndex = (frontIndex + 1) % M;
        --count;
        return true;
    }
};
~~~

出队为什么不用修改 rear？因为 rear 并未被保存为成员变量。front 前进一步、count 减一以后，下次计算的 <code>(front+count)%m</code> 已经自然对应新的空位。队列的全部逻辑状态只由这两个变量确定。

对考试题最可靠的检查方式，是把环形数组画成带下标的格子，然后逐步标出 front、count、有效项与下次写入位置。不要在做题中途把一种表示法换成另一种。两种都称为“循环队列”，但满容量和判满条件不同。

## 05.5 用链表实现队列时，最后一个元素出队最危险 {#v4-linkedqueue}

若队列元素数量变化很大，可能希望按需创建结点。链队列可让 first 指向最早进入的结点，last 指向最后进入的结点。每次入队把新结点接在 last 后面，再更新 last；出队则移除 first 指向的结点，并令 first 移向原后继。

普通情况下这只需要常数次指针更新。但若原队列只有一个元素，例如 first、last 都指向结点 A，出队后 first 会变成 nullptr。此时还必须把 last 也置为 nullptr，否则 last 会继续指向刚刚释放的结点。下次入队若沿 last 写 next，就可能访问失效内存。

空队列第一次入队时，也不能做 <code>last->next=newNode</code>，因为 last 为空；应该同时将 first、last 设置成新结点。把这两个边界与正常情况区分清楚，链队列的逻辑就完整了。

## 05.6 为什么二叉树的层序遍历自然使用队列 {#v4-queue-applications}

假设一棵树的根是 A，下一层为 B、C；B 的孩子是 D、E。我们希望按 <code>A,B,C,D,E</code> 的次序访问，也就是先处理所有较浅层，再逐渐处理较深层。

访问 A 时可以发现 B、C，把它们按顺序入队。接着出队 B，并将 B 的孩子 D、E 入队。此时队列从队首到队尾是 [C,D,E]，所以 C 一定先于 D、E 被处理。这恰好保证了层序遍历的要求。若改成栈，刚发现的 D、E 反而可能压过等待中的 C，顺序就会偏向深度优先。

这也是图搜索中的广度优先搜索（BFS）为什么依赖队列：队列保存已经发现但尚未扩展的结点，最早发现者先得到处理。在无权图里，这种一层层扩展的过程还与从起点的最短边数有关。当前课程中先掌握二叉树层序遍历即可。

## 05.7 有些工作需要按重要程度处理：优先级队列 {#v4-priorityqueue}

医院的普通挂号可以按先到先服务，但急诊分诊必须考虑病情严重程度。此时队列中下一个被取出的对象由优先级决定，输入时间只可能用于相同优先级时的次级规则。这类结构称为**优先级队列**。

最朴素的实现可以保存一个无序数组，每次取出时扫描找到最高优先级，代价 O(n)；也可让数组始终有序，取最高者很快，但插入可能搬移 O(n) 项。后面学习的堆正好在二者之间做出权衡：通常以 O(log n) 插入和移除最高优先级，以 O(1) 查看最高优先级。

它仍然是一类“决定谁接下来出队”的抽象接口，内部如何组织记录则可以按需要选择。关键是先区分题目到底要求“按到达先后”还是“按优先级”。

## 05.8 章节练习：先确认队列状态约定 {#v4-queue-exercises}

<details class="question"><summary>练习 1｜基本 FIFO 与查看队首（基础，8 分）</summary>

**题目。** 一个初始为空的整数队列依次执行 enqueue(1)、enqueue(2)、enqueue(3)、dequeue、enqueue(4)、front。请写出每次操作之后从队首到队尾的有效内容、dequeue 返回值及 front 返回值。

**思路。** 新元素始终接到队尾，出队从最先加入者开始；front 不改变队列。

**解答。** 各步有效队列依次为 [1]、[1,2]、[1,2,3]、[2,3]、[2,3,4]、[2,3,4]。dequeue 返回 1，front 返回 2。不能因为最近加入 4 就优先取走 4，那是栈的行为。

</details>

<details class="question"><summary>练习 2｜容量为 m 的 front/count 队列（作业同级，10 分）</summary>

**题目。** 采用长度 m=6 的循环数组，front 指向队首有效元素，count 指有效元素数，允许全部 6 格被使用。已知 front=4、count=3。求有效元素的数组下标、下一次入队位置、入队成功后的 count 以及此时是否已满。

**思路。** 从 front 顺环前进 count 个位置就是下一空格；有效范围包含从 front 起的 count 个下标。

**解答。** 有效下标是 4、5、0；下一次入队位置 (4+3)%6=1。入队后 count=4，还未满；仅当 count=6 才满。rear 位置是临时计算出的空槽，不能把它当成当前队尾元素。

</details>

<details class="question"><summary>练习 3｜环形回绕的完整过程（作业同级，12 分）</summary>

**题目。** 使用 m=4、front/count 表示的空队列，初始 front=0、count=0。依次入队 A、B、C、D，随后连续出队两次，再依次入队 E、F。写出每个阶段的 front 与 count，最终给出数组下标 0–3 保存的有效值，以及队首到队尾的顺序。

**思路。** 出队后 front 前进并取模；入队时写下标 (front+count)%m。只根据数组从左到右打印，未必等于队列逻辑顺序。

**解答。** 四次入队后 front=0、count=4，数组为 [A,B,C,D]；两次出队返回 A、B，front=2、count=2。入 E 时写下标 (2+2)%4=0，count=3；入 F 时写下标 (2+3)%4=1，count=4。最终数组槽位依次为 [E,F,C,D]，逻辑队首到队尾是 C,D,E,F。队列已满。

</details>

<details class="question"><summary>练习 4｜另一种判满约定（作业同级，8 分）</summary>

**题目。** 一个 m=8 的循环队列只保存 front、rear，并**浪费一格**，约定 front 指队首，rear 指下一空位。若 front=6、rear=3，求当前有效元素个数、还能再容纳几项以及判满条件。

**思路。** 有效下标从 6 走到 3 之前，经历 6、7、0、1、2；这个版本总容量只有 m−1。

**解答。** 元素个数 <code>(rear−front+m)%m=(3−6+8)%8=5</code>；可用容量 7，因此还可容纳 2 项。满条件是 <code>(rear+1)%m==front</code>。若误按 count 版满容量 m 计算，会多算一项。

</details>

<details class="question"><summary>练习 5｜两个栈模拟队列（提高，12 分）</summary>

**题目。** 只能使用两个具有 push、pop、top、empty 操作的栈 <code>in</code> 与 <code>out</code>，要求实现先进先出队列的 enqueue 和 dequeue。请给出完整操作思路，说明在 enqueue(A)、enqueue(B)、enqueue(C)、dequeue、enqueue(D)、dequeue 时两个栈的状态，并分析单次最坏和均摊时间。

**思路。** 入队始终压入 in；只有 out 为空且需要出队时，才将 in 的元素逐个弹出并压进 out，使次序反转。

**解答。** 压 A、B、C 后 in 底到顶为 [A,B,C]，out 空。首次出队时把 C、B、A 依次移到 out，out 底到顶为 [C,B,A]，弹出 A；此时 out=[C,B]。再入 D 后 in=[D]。第二次出队直接从 out 弹 B，得到 out=[C]、in=[D]。某次集中倒栈可花 Θ(n)，但每个元素最多被压入/弹出两个栈常数次，一长串操作总时间 O(操作数)，均摊 O(1)。

</details>

读完本章应能用自己的话说明：循环队列的取模只解决空间回绕，满与空还需要表示约定；front/count 与浪费一格方案的区别来自状态信息量；层序遍历使用队列的原因来自“先发现、先处理”的逻辑顺序。
