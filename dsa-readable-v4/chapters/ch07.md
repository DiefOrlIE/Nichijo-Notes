# 第 07 章　串与 KMP：从反复比较走到能够安全跳过的比较

> **来源**：《DSA 4-String》的字符串部分与《DSA 4a-KMP Algorithm》。  
> **先修**：数组、下标、循环与字符串。  
> **本章要求**：理解子串与子序列的差别；独立手算 LPS；解释失配回退的合法性；区分 LPS 和课件中不同的 next 约定；写出完整的 KMP 匹配过程。

我们经常会在一段长文本里寻找某个短字符串，比如在文档里查找一个单词。最容易想到的方法是从文本每个位置出发，依次比较是否匹配。它的正确性很直观，但如果有许多重复字符，就会不断比较相同的部分。KMP 算法的意义正是让程序利用已经得到的信息，避免无意义的回头。理解它的关键问题只有一个：**失配以后，我们究竟凭什么知道某些起点不可能成功？**

## 07.1 先弄清楚我们到底在寻找什么 {#v4-string-basics}

字符串是按顺序排列的字符序列，可以为空，也可以包含空格。空串 <code>""</code> 的长度为 0，而 <code>" "</code> 包含一个空格，长度是 1。若主串为 <code>ABCDEFG</code>，<code>BCD</code> 是它的子串，因为这三个字符在原文中连续出现；<code>BD</code> 虽然也保持了相对顺序，却跳过了 C，它只是子序列，不属于连续子串。

字符串匹配要找的是**模式串 P 在主串 S 中连续出现的位置**。这里下标非常容易混淆：课程中的某些 SubString 函数使用 1-based 起点，<code>SubString("ABCDEFG",2,3)</code> 就表示从第二个字符 B 开始取三个，得到 BCD；C++ 的 <code>std::string::substr(pos,len)</code> 使用 0-based 起点，同一任务要写成 <code>s.substr(1,3)</code>。

之后本章统一使用 C++ 的 **0-based 下标**，长度为 m 的模式 P 的合法字符位置是 0 到 m−1。若匹配从 S 中的下标 k 开始，含义是 <code>S[k+j]==P[j]</code> 对所有 0≤j<m 成立。明确这一点，是理解 KMP 返回位置和 next 数组的前提。

## 07.2 朴素算法为什么反复回到文本旧位置 {#v4-naive}

我们先用主串 S=<code>ababac</code>、模式 P=<code>abac</code> 手算最直观的方法。尝试从 S 的下标 0 开始：比较 a=a、b=b、a=a，第四个字符却是 S[3]=b 与 P[3]=c，失配。朴素方法放弃起点 0，改从起点 1 重新比较，立即发现 S[1]=b 与 P[0]=a 不同；接着尝试起点 2，此时连续比较 a、b、a、c 全部相等，于是找到首次匹配位置 2。

这里需要把“主串当前位置”与“当前候选起点”分开。第一次失败时我们已经检查到了 S[3]，但第二次又回头访问 S[1]，第三次再访问 S[2]。这种重复访问并非错误，却可能成为性能瓶颈。

~~~cpp
#include <string>
int naiveFind(const std::string& s, const std::string& p) {
    if (p.empty()) return 0;
    for (int start=0; start+(int)p.size()<=(int)s.size(); ++start) {
        int j=0;
        while (j<(int)p.size() && s[start+j]==p[j]) ++j;
        if (j==(int)p.size()) return start;
    }
    return -1;
}
~~~

设主串长 n、模式长 m。最坏情况下，每个可能起点都比较接近 m 次才失配，总时间 O(nm)。例如主串里有许多 a、模式是许多 a 后接一个 b，就会反复比较前面那些已经比较过的 a。我们想省下这些重复工作，但必须拿出可靠理由，否则跳过一个候选起点可能漏掉真正的匹配。

## 07.3 失配之前匹配的那一段，蕴含了什么信息 {#v4-border-intuition}

假设模式开头一段为 <code>ABAB</code>，主串某处已经连续匹配出这四个字符，紧接着下一字符才失配。我们不妨把这段已经确认的文本单独取出：它的前两项是 AB，后两项也是 AB。因此若把模式向右滑动两格，模式开头的 AB 正好可以与旧匹配段尾部的 AB 对齐。这两项**必然相等**，因为它们本来都已经与同一段模式字符匹配过。

于是出现两个术语：一个字符串从首项开始截取的片段叫前缀；到末项结束的片段叫后缀。排除整个字符串自身后，叫真前缀、真后缀。对 <code>ABAB</code> 而言，长度 2 的前缀 AB 与长度 2 的后缀 AB 相等，这段相等的边界信息可以被重复利用。

为什么强调“真”？如果允许把整串自身既看成前缀又看成后缀，那么每个字符串都拥有与自身同长的边界，根本无法告诉我们失配后应该向右移动多少。我们必须寻找**比当前已匹配长度短**的边界，才能产生一个新的候选对齐位置。

有些已匹配段完全没有非空公共真前后缀，例如 ABC。若下一字符失配，说明找不到“旧匹配段的末尾已经等于模式开头”的非空片段，于是只能从模式开头重新尝试当前主串字符。KMP 便围绕这条边界信息设计。

## 07.4 一张表里每个数字究竟代表什么 {#v4-lps}

定义 LPS（Longest Proper Prefix which is also Suffix）数组：对于模式 P 的每个下标 i，<code>lps[i]</code> 是**子串 P[0..i] 的最长相等真前缀和真后缀的长度**。这句话有三个重要限制：研究对象是从 P[0] 开始到 P[i] 的片段；前后缀长度相同；它们必须比整个片段短。

例如 P=<code>aabaaca</code>。我们不要急着看构造代码，先逐项求值：

| i | 当前片段 | 最长相等真前后缀 | lps[i] |
|---:|---|---|---:|
| 0 | a | 无 | 0 |
| 1 | aa | a | 1 |
| 2 | aab | 无 | 0 |
| 3 | aaba | a | 1 |
| 4 | aabaa | aa | 2 |
| 5 | aabaac | 无 | 0 |
| 6 | aabaaca | a | 1 |

得到 <code>[0,1,0,1,2,0,1]</code>。在 i=4 时，前缀的两个 a 与末尾的两个 a 相同，所以值为 2；在 i=5 时，尽管此前有长度 2 的边界，新字符 c 破坏了可扩展性，而且短一点的候选也不成立，结果回到 0。每个数字的含义都是相同的，不随算法实现改变。

这个数组只依赖模式 P，与主串 S 完全无关。因此我们可以在正式匹配前先将 P 自己分析一遍，以后遇到失配时就能快速知道可继续利用多少字符。

## 07.5 为什么回退到 lps[len−1]，而不能随便减一 {#v4-lps-fallback}

现在进入 KMP 最关键的推理。假设我们已经算完 <code>lps[0..i−1]</code>，而 <code>len=lps[i−1]</code>，表示此前已经有长度 len 的最长公共边界。若新字符 P[i] 恰好等于 P[len]，新边界便能延长一位，所以令 len++、lps[i]=len。

若 P[i] 与 P[len] 不同，长度 len 不能继续延伸。下一次尝试的长度应该是多少？我们必须寻找**既是旧已匹配片段的后缀，又是模式前缀**的候选。若某个长度根本不满足这个条件，那么不论新字符是什么，也没有必要试它。

举一个能真正展示跳跃原因的例子。设模式为 <code>ababd</code>。处理到最后的 d 之前，已处理的部分为 <code>abab</code>，其最长公共边界是 <code>ab</code>，所以 len=2。现在 P[4]='d'，它不等于 P[2]='a'，长度 2 的边界无法延长。能否改试 len=1？不能，因为旧片段 <code>abab</code> 的最后一位是 b，而长度 1 的模式前缀是 a，它们本来就不相等。长度 1 从一开始就不是候选。

再想想，旧的长度 2 边界是 <code>ab</code>。如果还存在更短的合法候选，那么它也必须是字符串 <code>ab</code> 自己的相等真前后缀；其中最大的长度恰好是 <code>lps[len−1]=lps[1]=0</code>。因此可以从 len=2 **直接跳到 0**，跳过中间不可能成立的长度 1。

这就是 <code>len=lps[len−1]</code> 的由来：它始终让 len 保持为一个真实存在的公共边界长度，回退直接找到下一大候选，而不会漏掉任何合法的较短边界。随便做 <code>len--</code> 可能多尝试许多已经确定不合法的长度；更严重的是，如果没有维护边界候选这个不变量，就很难证明整个构造过程正确。

~~~cpp
#include <vector>
#include <string>
std::vector<int> buildLps(const std::string& p) {
    std::vector<int> lps(p.size(), 0);
    int len=0;
    for (int i=1; i<(int)p.size(); ) {
        if (p[i]==p[len]) {
            lps[i]=++len;
            ++i;
        } else if (len>0) {
            len=lps[len-1]; // i 不变，再试较短的真实边界
        } else {
            lps[i]=0;
            ++i;
        }
    }
    return lps;
}
~~~

注意两个细节。第一，回退分支不增加 i：当前字符 P[i] 还没完成全部候选的比较。第二，len 最终降到 0 也失配时，才可确定没有非空公共真前后缀，让 lps[i]=0 并前进。这两条规则共同保证每一项都有明确含义。

## 07.6 用 LPS 匹配主串：为什么主串 i 不回头 {#v4-kmp}

构造完 lps 后，我们正式扫描主串。设 i 是**尚未处理完的主串字符下标**，j 是当前已经匹配的模式前缀长度。当 S[i]==P[j] 时，当前比较成功，二者都前进。如果 j 达到模式长度 m，说明此前连续 m 个字符已匹配成功，起点是 i−m。

困难仍在失配。假设此前有 j 个字符连续匹配成功，那么主串的 <code>S[i−j..i−1]</code> 已经等于模式的 <code>P[0..j−1]</code>。如果它具有一个长度 <code>lps[j−1]</code> 的公共边界，我们便知道旧匹配段尾部已经等于模式开头这段内容，所以可以把模式的新起点直接对齐到那里。

此时**主串当前字符 S[i] 还没有得到正确匹配结果**，它只是和旧的 P[j] 不相等。回退 j 后，仍须用同一个 S[i] 去比较新的 P[j]，所以 i 保持不动。只有在 j=0 的情况下仍发生失配，才能断定从当前字符开始无法匹配模式，于是 i++。

~~~cpp
int kmpFind(const std::string& s, const std::string& p) {
    if (p.empty()) return 0;
    auto lps=buildLps(p);
    int i=0,j=0;
    while (i<(int)s.size()) {
        if (s[i]==p[j]) {
            ++i; ++j;
        } else if (j>0) {
            j=lps[j-1];
        } else {
            ++i;
        }
        if (j==(int)p.size()) return i-j;
    }
    return -1;
}
~~~

用 S=<code>ababababca</code>、P=<code>abababca</code> 手算：模式前六项 <code>ababab</code> 先与主串前六项匹配成功，来到 i=6、j=6。此时 S[6]='a'，P[6]='c'，失配。已经匹配的六项 <code>ababab</code> 具有长度 4 的边界 <code>abab</code>，所以令 j=lps[5]=4，而 i 仍为 6。新比较变成 S[6]='a' 与 P[4]='a'，成功。后续继续推进，最终在主串下标 2 找到模式的首次匹配。

这里跳过的是那些已经通过已匹配文本的内部结构证明不可能成功的候选起点。理解这个证明，KMP 就不再只是两条难记的 while 分支。

构造 LPS 的时间 O(m)，主串匹配时间 O(n)，总时间 O(n+m)。尽管 j 会多次回退，但它增加的总量与已经扫描的字符数量受同阶约束，回退工作不可能无限累积；主串下标 i 则始终不减。辅助 LPS 数组占 O(m)。

## 07.7 next、nextval 与 LPS：为什么不同课件里的数字不能直接照抄 {#v4-next}

学习 KMP 时经常遇到第二个麻烦：有些教材把失配数组称为 next，另一些称为 LPS，同一个模式却得到不同数列。这通常来自下标及存储语义的差异，并不说明算法互相矛盾。

本章的 LPS 定义是 <code>lps[i]</code> 对应模式前缀 P[0..i] 的公共真前后缀长度。另一种常见 **−1 型 next** 的约定是 <code>next[0]=−1</code>，当 j≥1 时 <code>next[j]=lps[j−1]</code>；匹配失败时将 j 设为 next[j]，若 j=−1，再同步前进主串和模式指针。

对 P=<code>aabaaca</code>，本章 LPS=[0,1,0,1,2,0,1]；按刚刚明确规定的 −1 型约定，长度为 7 的 next 是 [−1,0,1,0,1,2,0]。这两个数组描述的是同一类边界信息，但放在了不同位置。还有进一步针对连续重复字符优化的 nextval 变体，数值可能再次不同。

考试遇到 next 填表时，正确的第一步是**看题目给的定义或匹配代码**，确认失败时写的是 <code>j=next[j]</code>、<code>j=lps[j−1]</code> 还是其他形式。不能凭某个数组名称决定下标约定。只有先确认约定，后面的手算才有唯一意义。

## 07.8 章节练习：每个下标都要有来历 {#v4-kmp-exercises}

<details class="question"><summary>练习 1｜子串与课程编号（基础，8 分）</summary>

**题目。** 字符串 S="ABCDEFG"。课程接口 <code>SubString(S,start,len)</code> 使用 **1-based** 起点、len 表示长度；C++ <code>substr(pos,len)</code> 使用 0-based 起点。求 SubString(S,3,3)，写出对应 C++ 表达式，并判断 "BE" 是否为 S 的子串。

**思路。** 分清“起点是第几项”与“起点是哪个数组下标”，并记住子串必须连续。

**解答。** 从第 3 个字符 C 起取三个得到 "CDE"，C++ 写 <code>S.substr(2,3)</code>。"BE" 不是连续子串，因为 B 与 E 之间隔着 C、D；它可以是一个不连续子序列。

</details>

<details class="question"><summary>练习 2｜完整构造 LPS（作业同级，12 分）</summary>

**题目。** 模式 P="aabaaca"，下标从 0 到 6。对每个前缀 P[0..i] 求最长相等真前后缀长度，写出全部 LPS；特别解释 i=4 与 i=5 的结果。

**思路。** 每次比较从开头与从末尾截取的同长度片段，禁止把整个前缀自己当成“真”前后缀。

**解答。** LPS=[0,1,0,1,2,0,1]。i=4 的片段 "aabaa" 以 "aa" 开头也以 "aa" 结尾，所以值为 2；i=5 的片段 "aabaac" 以 c 结尾，没有任何非空前缀能够与同长后缀相等，所以值为 0。最后 i=6 的片段以 a 结尾，又恢复长度 1 的公共边界。

</details>

<details class="question"><summary>练习 3｜KMP 失配中的 i、j（作业同级，12 分）</summary>

**题目。** 主串 S="ababababca"，模式 P="abababca"，下标都从 0 开始。KMP 已经匹配前六个字符，即处于 i=6、j=6。假设该处比较失配，写出失配的具体字符、所使用的 LPS 项、下一次要比较的两个字符，并求最终首次匹配下标。

**思路。** 此时已匹配段为 "ababab"，它的最长相等真前后缀长度为 4；S[i] 尚未被新的模式位置比较。

**解答。** S[6]='a'、P[6]='c'，因此失配；读取 lps[5]=4，使 j 变为 4，i 保持 6。随后比较 S[6]='a' 与 P[4]='a'，成功，再正常前进。最终整个 P 首次匹配从 S 的下标 2 开始。若同时让 i 加一，可能直接跳过正确匹配起点。

</details>

<details class="question"><summary>练习 4｜数组约定的转换（作业同级，10 分）</summary>

**题目。** 已知模式 P="aabaaca" 的 LPS=[0,1,0,1,2,0,1]。现在换用一种明确规定的 −1 型 next：next[0]=−1，next[j]=lps[j−1]（1≤j<7）。请写出全部 next 数组，并解释为什么不能把 LPS 原样复制到 next。

**思路。** next[j] 保存的是失配发生在模式 j 位置时应该回退到的前一段边界长度。

**解答。** next=[−1,0,1,0,1,2,0]。其中 next[0]=−1 是约定的特殊状态，其余各项依次取前一位置的 LPS。两个数组的索引意义不同，直接照搬会让某些失配位置回退错误。

</details>

<details class="question"><summary>练习 5｜重叠匹配与匹配完成后的回退（提高，10 分）</summary>

**题目。** 主串 S="aaaaaa"，模式 P="aaaa"。要求找出所有允许**重叠**的匹配起点。先求 P 的 LPS，再说明第一次完整匹配后若继续搜索，下一个模式长度 j 应设为多少。

**思路。** 首次匹配结束时，已经匹配了 4 个 a；它们末尾的三个 a 同时也是模式的前三个 a。

**解答。** P 的 LPS=[0,1,2,3]。首次匹配起点为 0，随后应令 j=lps[3]=3 继续，继续扫描主串剩余字符可得到起点 1 和 2，所以所有匹配起点为 {0,1,2}。若每次匹配成功都将 j 清零，就会错过重叠出现的结果。

</details>

**最后检验。** 如果你能够自己解释“公共边界为什么可以被利用”“构造 LPS 时为什么跳到 lps[len−1]”“主串匹配时为什么 i 不回退”，便掌握了 KMP 的核心推理。这些解释比死记某个 next 数组更有迁移价值。
