# 第 07 章　字符串与 KMP：为什么失配时主串不必回头

> 来源：《DSA 4-String》（字符串部分）及《DSA 4a-KMP Algorithm》（24 页）。  
> KMP 是考试里需要真正理解“为什么”的算法，本章从朴素匹配逐步推导。

## 07.1 字符串和子串：下标约定先讲清 {#v4-string-basics}

字符串是字符组成的有限序列，可为空。空串 <code>""</code> 长度为 0，含一个空格的串 <code>" "</code> 长度为 1。**子串**必须是原串中一段连续字符；例如 ABCDE 中 BCD 是子串，而 BD 只是子序列，并非连续子串。

课程某些函数写 <code>SubString(S,i,j)</code>，约定 i 从 1 开始编号，j 是截取长度；C++ 的 <code>std::string::substr(pos,len)</code> 用 0-based 起点。比如 S="ABCDEFG" 时课程式 SubString(S,2,3) 得 "BCD"，C++ 要写 <code>S.substr(1,3)</code>。字符串连接 Concat(X,Y) 按顺序把 Y 放在 X 之后，不会自动去重。

## 07.2 最直接的匹配法：每个起点都试一遍 {#v4-naive}

给主串 S="ababac"、模式 P="abac"，要找到 P 在 S 中第一次连续出现的位置。最直观的方法从 S[0] 开始对齐 P[0]，一个个比较，失配就换主串的下一个起点。

从起点 0：a=a、b=b、a=a，但第四个主串字符是 b、P[3] 是 c，失配；接着起点 1 的 b 与 P[0] 的 a 立即失配；起点 2 开始 a=b? 具体是 S[2]='a'，与 P[0]='a' 相等；后续 b=b、a=a、c=c，于是首次匹配下标 2。

~~~cpp
#include <string>
int naiveFind(const std::string& s,const std::string& p) {
    if(p.empty())return 0;
    for(int start=0;start+(int)p.size()<=(int)s.size();++start) {
        int j=0;
        while(j<(int)p.size()&&s[start+j]==p[j])++j;
        if(j==(int)p.size())return start;
    }
    return -1;
}
~~~

如果主串中很多窗口与模式前半段相同、接近末尾才失配，这种方法会重复比较早已比较过的主串字符，最坏 O(nm)，其中 n、m 分别是主串和模式长度。KMP 想解决的浪费就在这里。

## 07.3 已经匹配的前缀并非毫无价值 {#v4-border-intuition}

把模式 P="ABAB" 画出来。它的前两个字符 "AB" 与最后两个字符 "AB" 相同。假如主串某个窗口已经与 "ABAB" 完全一致，但下一个字符失配，那么这四个已确认字符的末尾 "AB" 已经确定与模式开头 "AB" 相同，我们可以让模式重新对齐到这个已知边界，而不从模式首项重头比较。

这里用到两个词：**前缀**是从串首开始的一段，**后缀**是到串尾结束的一段。所谓**真前缀/真后缀**，要求长度比整个字符串短，不能把整串自身算进去。对 "ABAB"，最长相等真前后缀为 "AB"，长度 2；对 "ABC" 没有非空公共真前后缀，长度 0。

KMP 的基本事实是：已匹配的这段文本既然等于模式的一个前缀，它自己的尾部自然也具有该前缀的后缀信息。重复利用相等的边界，不会丢掉可能的新匹配位置。

## 07.4 LPS 数组先定义，再用实例一点点填写 {#v4-lps}

LPS（Longest Proper Prefix which is also Suffix，最长相等真前后缀长度数组）规定 <code>lps[i]</code> 是模式前缀 <code>P[0..i]</code> 的最长相等真前后缀长度。以 P="aabaaca" 为例：

| i | 当前前缀 P[0..i] | 最长相等真前后缀 | lps[i] |
|---:|---|---|---:|
| 0 | a | 无 | 0 |
| 1 | aa | a | 1 |
| 2 | aab | 无 | 0 |
| 3 | aaba | a | 1 |
| 4 | aabaa | aa | 2 |
| 5 | aabaac | 无 | 0 |
| 6 | aabaaca | a | 1 |

因此 lps=[0,1,0,1,2,0,1]。可以先不看程序，逐位置寻找真前缀与真后缀，确保“真”的含义已经清楚。

## 07.5 失配时为何 len=lps[len−1]，而不是任意减一 {#v4-lps-fallback}

现在从手算走向线性算法。假设已经处理到前缀 P[0..i−1]，最长相等边界长度为 len，我们打算比较新字符 P[i] 与 P[len]。若相等，可扩成 len+1；若不等，当前长度 len 不可继续扩展。

接下来的候选长度并非任意的 len−1。它必须既是“此前匹配前缀”的**后缀**，也是整个模式开头的**前缀**。因此候选必然是当前已知边界字符串自己的某个边界；其中最长者的长度恰为 <code>lps[len−1]</code>。直接从这里继续，不会漏过可能成功的候选，且能一次跳过不可能的长度。

~~~cpp
#include <vector>
#include <string>
std::vector<int> buildLps(const std::string& p){
    std::vector<int> lps(p.size(),0);
    int len=0;
    for(int i=1;i<(int)p.size();){
        if(p[i]==p[len]) lps[i++]=++len;
        else if(len>0) len=lps[len-1];
        else lps[i++]=0;
    }
    return lps;
}
~~~

注意失配分支回退 len 时**没有增加 i**：当前字符尚未与新的边界候选比较。只有成功扩展或已无非空候选时，才完成当前 i 的计算、进入下一位置。

## 07.6 在主串上匹配：为什么 i 不回退 {#v4-kmp}

匹配时 i 指当前尚未处理的主串字符位置，j 指已经连续匹配的模式前缀长度。若 S[i]==P[j]，二者共同向前走；如果失配但 j>0，便令 j=lps[j−1]。**主串 i 保持不变**，因为 S[i] 还未与新的 P[j] 比较。如果 j=0 仍失配，才让 i++，因为不可能从当前位置以模式首字符开头。

~~~cpp
int kmpFind(const std::string& s,const std::string& p){
    if(p.empty())return 0;
    auto lps=buildLps(p);
    int i=0,j=0;
    while(i<(int)s.size()){
        if(s[i]==p[j]){++i;++j;}
        else if(j>0)j=lps[j-1];
        else ++i;
        if(j==(int)p.size())return i-j;
    }
    return -1;
}
~~~

KMP 的总时间为 O(n+m)。直观上构造 lps 时 i 只前进、len 虽能回退但回退的总工作受此前增加次数约束；主串匹配时 i 从不后退，j 的回退同样不可能无限超过它此前上升的次数。

## 07.7 next 与 LPS 为什么经常差一个下标 {#v4-next}

不同课件把失配信息存成不同约定的 next，题目必须看数组首值和匹配代码。有一种常见的 **-1 型 next** 为前 m 个位置定义 <code>next[0]=-1</code>、<code>next[j]=lps[j−1]</code>（1≤j<m）；匹配失败时设置 <code>j=next[j]</code>，若 j 变成 -1，再让 i++、j++。它和直接使用 <code>j=lps[j−1]</code> 的代码语义相近，但数值位置不同。

对于模式 P="aabaaca"，本章的 lps 是 [0,1,0,1,2,0,1]；按上述 *指定的* -1 型约定，长度 m=7 的 next 可写成 [-1,0,1,0,1,2,0]。有些教材还定义 nextval（考虑当前模式字符重复的进一步优化）；不能只凭数组叫 next 就认定相同。
