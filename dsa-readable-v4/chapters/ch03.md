# 第 03 章　栈：为什么最后压入的东西先被处理

> 来源：《DSA 3-Stack&Queue》（栈、表达式和栈应用）。  
> 先修：线性表和数组。

## 03.1 一个从顶端取盘子的现实限制 {#v4-stack-model}

餐厅堆盘子时，只能在最上面放新盘子，也只能先拿走最上面的盘子。这个限制比“一般线性表”的任意位置插删更强：它让后进入的东西先被处理。栈（Stack）正是这种**后进先出**（Last In, First Out，LIFO）的线性结构。

依次 <code>push(3)、push(8)、pop()、push(5)</code>：先存 [3]，再 [3,8]，弹出 8 后剩 [3]，最后 [3,5]。这里方括号从栈底到栈顶写，top=5。严格按照“只碰顶端”这条规则，便不需要记忆额外特例。

## 03.2 用数组实现时 top 是最后元素下标还是下一空位 {#v4-stack-array}

这两种约定都可以，必须事先固定。若约定 <code>top</code> 指**最后一个有效元素下标**，空栈 top=−1。容量 m 的数组栈满条件 top=m−1；push 时先判断满，再执行 <code>a[++top]=x</code>；pop 先检查空，取 <code>a[top--]</code>。

~~~cpp
#include <vector>
#include <stdexcept>
class IntStack {
    std::vector<int> a;
    int top=-1;
public:
    explicit IntStack(int capacity){
        if(capacity<=0) throw std::invalid_argument("capacity");
        a.resize(capacity);
    }
    bool empty() const {return top<0;}
    bool full() const {return top+1==(int)a.size();}
    bool push(int x){
        if(full())return false;
        a[++top]=x;
        return true;
    }
    int pop(){
        if(empty())throw std::underflow_error("empty");
        return a[top--];
    }
};
~~~

如果课件另一段代码把 top 指下一空位，则空栈 top=0，push 先放 a[top] 再 top++，pop 先 --top 再取；两者逻辑一致，任何代码题都应先写清约定再填空。

## 03.3 括号匹配：为什么仅计数不够 {#v4-brackets}

处理 <code>{[()]}</code> 时，见到左括号就把它放进栈；遇右括号，应与栈顶左括号匹配，成功后弹出。比如 { 入栈， [ 入栈， ( 入栈；遇 ) 对上 (；遇 ] 对上 [；遇 } 对上 {，最终空栈即合法。

如果只统计左括号与右括号数量，字符串 <code>(]</code> 左右数量都为 1 却不匹配。栈保存的是未闭合括号的类型和嵌套顺序，能解释为什么该算法正确。结束时若栈非空，也表示还有未配对的左括号。

## 03.4 为什么要把中缀表达式转成后缀 {#v4-postfix}

中缀式 <code>A+B*C</code> 必须靠优先级知道先乘后加。后缀式把运算符放在操作数后面，变成 <code>A B C * +</code>；计算器从左到右扫描，遇值入栈，遇二元运算符取出两个操作数运算，将结果再压回栈。乘号弹出 B、C，结果 BC 入栈；加号再把 A 与 BC 相加。

注意弹出顺序：若从运算数栈先弹出 b、后弹出 a，那么应执行 **a op b**，尤其减法与除法不能反过来算。

## 03.5 中缀转换完整轨迹：符号为什么会出栈 {#v4-conversion}

为转换 <code>A+B*C-D</code>，维护一个**运算符栈**和直接输出的后缀串。遇操作数直接输出；遇运算符，与栈顶比较优先级，若栈顶优先级更高或相等且运算符左结合，则先弹出栈顶，最后压入当前符号。括号是额外的分组约束。

<pre class="diagram">读到        输出后缀          运算符栈（底→顶）
A           A                 空
+           A                 +
B           A B               +
*           A B               + *
C           A B C             + *
-           A B C * +         -
D           A B C * + D       -
结束        A B C * + D -     空</pre>

当读到减号时，为什么弹出两次？* 和 + 都先于减号作用，而且当前减号不在括号里。这样后缀表达式的顺序忠实地反映运算顺序。

有两个非常重要的边界：乘方若约定右结合，例如 <code>2^3^2</code> 通常解释为 <code>2^(3^2)</code>，遇相等优先级不能照左结合规则弹出；一元负号 <code>-A</code> 与二元减法 <code>A-B</code> 必须在读入时区分，在后缀式中可将前者写成 NEG。

## 03.6 列车调度：怎样判断目标出栈序列是否可能 {#v4-trains}

假设五节车厢按 1、2、3、4、5 固定次序进入旁线栈，题目要求它们按 3、2、5、4、1 出站。为先输出 3，必须依次入栈 1、2、3，再弹 3、2；随后入栈 4、5，弹 5、4，最后弹 1，得到操作轨迹：

<pre class="diagram">I1 I2 I3 O3 O2 I4 I5 O5 O4 O1
I：入栈，O：出栈，数字为车厢编号。</pre>

判断另一序列是否可行时，每一步都尝试：如果栈顶就是下一目标，立刻弹；否则按固定顺序继续入栈，直到栈顶等于目标或无车可入。若目标被某节仍在栈内的车压住、同时没有合法办法将上方车先移出，序列不可能。这套模拟胜过凭图形猜测。

对于 n 个互异元素按固定次序进栈，所有合法出栈次序的数量等于第 n 个 Catalan 数 <code>Cₙ=1/(n+1)·binom(2n,n)</code>。当 n=6，C₆=132。初学时先学会判断具体出栈序列，计数公式的证明可留作深化。

## 03.7 两个栈共享一段存储空间 {#v4-sharedstack}

如果两个栈分别固定容量 10，左栈满了而右栈只用了 1 项，右侧大量空间却无法给左栈借用。共享栈用一根数组，栈 A 从左向右增长，栈 B 从右向左增长。A 的 topA 初始 −1，B 的 topB 初始 m；只在 <code>topA+1==topB</code> 时真正满。入 A 先 ++topA；入 B 先 --topB。

这里要区分“当前栈顶下标”和“两个栈之间的空闲位置”。当 topA=2、topB=6 时，槽 3、4、5 还剩 3 个空位；两个栈都可以继续增长，直到相遇。
