# 第 09 章　线索树、普通树与森林：把一条链接的意义弄清楚

> **资料**：《DSA 5-Tree》中线索二叉树、普通树与森林部分，以及森林静态表作业。  
> **已学知识**：二叉链表、前中后序遍历、树的父子关系、指针域。  
> **目标**：解释线索化为什么利用空指针；根据 tag 查中序前驱后继；从首孩子—兄弟表示恢复一般树和森林；推导 Catalan 递推。

上一章我们用 left 和 right 表示二叉树的左右孩子，并借助递归或栈完成遍历。这时有两个值得继续研究的问题：一是遍历时经常需要知道“当前结点的下一个结点”，可是普通二叉树指针没有直接保存它；二是普通树的每个结点可能拥有不止两个孩子，怎样才能仍然使用只含两条指针的结点结构？本章围绕这两种“重新利用链接”展开。

## 09.1 为什么二叉树里恰好有 n+1 条空孩子链接 {#v4-thread-motivation}

一棵包含 n 个结点的二叉链表，每个结点固定分配 left、right 两个指针域，共 2n 个。真正连接到孩子的边有多少？由于树的根没有父亲，其他 n−1 个结点各由父亲的一条孩子边指向，所以有效孩子链接总数恰好为 n−1。剩余的空指针域数量便是 <code>2n−(n−1)=n+1</code>。

例如一棵只有根 A、左孩子 B 的二叉树，共 2 个结点、4 个指针域，真实连接只有 A.left→B 一条，其余 3 条为空，符合 n+1=3。你可以注意到：空指针并不只存在于叶子；某个仅有左孩子的结点，其 right 也为空。

我们能否利用这些空指针记录中序遍历意义上的前驱和后继？如果当前结点原本没有右孩子，就让右指针指向中序遍历中的下一个结点；没有左孩子时，便让左指针指向前一个结点。这样就产生了**线索二叉树**。但要注意，这些新指针与真正的父子边拥有不同含义，因此需要额外的标志位来区分。

## 09.2 什么是真实孩子，什么又是中序线索 {#v4-threading}

设二叉树为根 A，左孩子 B、右孩子 C，B 的左右孩子 D、E。中序遍历依次访问 <code>D B E A C</code>。对于叶子 D，原本右指针为空，而它的中序后继恰好是 B，因此可以把 D.right 改为指向 B；同样 E 没有左孩子，E 的中序前驱是 B，于是可以让 E.left 指向 B。

但现在如果程序仍按普通二叉树遍历：看到 D.right 非空就沿它递归，会回到 B，可能形成重复访问。为避免混淆，可以给每个结点添加 <code>ltag</code>、<code>rtag</code>。本章采用一种常见约定：**tag=0 表示真实孩子链接，tag=1 表示线索**。因此只有 ltag=0 时 left 才能被视为左子树根，rtag=0 时 right 才能被视为右子树根。

线索化的实现过程其实可以跟随一次中序遍历进行：维护指针 prev 指向刚刚访问过的结点，访问当前 p 时，若 p 的 left 原本为空，就让它的左线索指向 prev；若 prev 存在且 prev 的 right 原本为空，就把 prev 的右线索指向 p；然后令 prev=p。这样一次遍历就把真实前后关系填入可利用的空指针域。

不同教材还可能加入头结点，使第一个结点的前驱、最后一个结点的后继指向这个头结点；没有头结点的实现则可能使用 nullptr。手工题必须确认其规定，才能判断边界线索的最终值。

## 09.3 中序后继为什么要分为两种情况 {#v4-thread-successor}

假设已经得到中序线索二叉树，要找结点 p 的下一个中序访问结点。先读 p 的 rtag。如果 rtag=1，right 已被明确规定为中序后继线索，那么可以直接沿 right 找到答案。

如果 rtag=0，则 right 指向一个**真实的右子树**。中序遍历先左、再根、后右，所以访问 p 后应该进入它的右子树；而在右子树内部，第一个要访问的是其中最左边的结点。因此算法是：先进入 p.right，再只沿真实左孩子不断向左走，直到找不到更左的孩子。

举个反例说明为何不能直接返回 p.right。假设 p=A，右孩子是 C，而 C 还有左孩子 B，那么中序为 A、B、C。A 的后继应是 B，直接返回右孩子 C 就跳过了 B。只有走到右子树最左边，才符合遍历顺序。

找中序前驱是完全对称的：若 ltag=1，沿 left 线索直接取得；若 ltag=0，必须进入真实左子树并一直沿真实 right 走到最右结点。这里再一次说明：**判断 tag 必须在解释指针之前发生**。

**用具体的树跟踪每条线索。** 设 A 左孩子为 B、右孩子为 C；B 只有右孩子 D；C 只有左孩子 E。画出普通二叉树：

<pre class="diagram">       A
      / \
     B   C
      \ /
       D E

中序输出：B → D → A → E → C</pre>

按照中序顺序访问 B 时，B 的左孩子原本为空，可以用左指针指向中序前驱（本例为空），并将 ltag 设为 1。但 B 右指针还指向真实孩子 D，它必须保留，rtag=0。访问 D 时，它原本没有左孩子，于是把 D.left 作为前驱线索指向 B；之后访问 A 时，再把 D 原本为空的右指针改为指向后继 A。再访问 E 时，E 的前驱线索指向 A，后继线索将在访问 C 时指向 C。整轮结束后，最后访问的 C 的右线索可以保留为空。

现在求 D 的中序后继：它的 rtag=1，right 直接给出 A。求 A 的中序后继：A 的 rtag=0，右边是**真实右子树** C，要从 C 开始沿真实左孩子走到 E，因此 A 的后继是 E。反过来，E 的 ltag=1，left 直接给出 A；A 的左指针指向真实子树 B，从 B 向右走到 D，所以 A 的前驱是 D。请始终区分 tag=0 所表达的孩子与 tag=1 所表达的线索，否则很容易把指向祖先的线索当孩子再次遍历而陷入循环。

下面的 C++17 版本假设开始时所有 tag 为 0、left/right 仅表示真实子女，且整棵树只进行一次线索化：

~~~cpp
struct ThreadNode {
    char value;
    ThreadNode *left = nullptr, *right = nullptr;
    int ltag = 0, rtag = 0;    // 0: 孩子; 1: 前驱/后继线索
};
void makeThreads(ThreadNode* cur, ThreadNode*& prev) {
    if (!cur) return;
    makeThreads(cur->left, prev);
    if (!cur->left) {
        cur->ltag = 1;
        cur->left = prev;      // 中序前驱
    }
    if (prev && !prev->right) {
        prev->rtag = 1;
        prev->right = cur;     // prev 的中序后继就是 cur
    }
    prev = cur;
    makeThreads(cur->right, prev);
}
void threadInorder(ThreadNode* root) {
    ThreadNode* prev = nullptr;
    makeThreads(root, prev);
    if (prev && !prev->right)
        prev->rtag = 1;       // 中序最后一项的后继为空
}
ThreadNode* nextInorder(ThreadNode* p) {
    if (!p) return nullptr;
    if (p->rtag == 1) return p->right;
    p = p->right;             // 此时为真实右孩子
    while (p && p->ltag == 0) p = p->left;
    return p;
}
~~~

线索化过程会访问每个结点一次，时间 O(n)，使用递归调用栈 O(h)。若结点右指针已是后继线索，nextInorder 为 O(1)；若有真实右子树，则可能沿左链走 O(h)。这里没有课件部分版本使用的辅助头结点，若题目明确规定头结点和首尾循环线索，必须遵守那组额外约定。**对已经线索化的树绝不能再直接执行此处的递归线索化**，因为修改后的指针包含指向前驱、后继的回边。

## 09.4 为什么两条指针就能表示拥有多个孩子的一般树 {#v4-firstchild-nextsibling}

现在切换到第二个问题。假设一般树的根 A 有三个孩子 B、C、D，而 D 又有孩子 E。若每个结点只有固定的 left、right 两条指针，似乎不足以直接存放 A 的三个孩子地址。

解决方法是重新定义指针含义：让 left 保存**第一个孩子**，right 保存**下一个兄弟**。这样 A.left=B，B.right=C，C.right=D；而 D.left=E。想枚举 A 的全部孩子，就先走 A.left 得 B，再沿 B.right 得 C，继续沿 C.right 得 D。只要兄弟链没有结束，孩子列表就没有遍历完。

<pre class="diagram">原一般树：             孩子兄弟链接：
       A                 A.left → B
     / | \               B.right → C
    B  C  D              C.right → D
          |              D.left → E
          E</pre>

这里最容易混淆的一件事是：在转换后的二叉链表中，B.right 指向的是**B 的兄弟 C**，它在原一般树里并不表示 B 的右孩子。你必须始终知道一条指针使用的是哪一种语义。二叉树的左孩子/右孩子规则与一般树的 firstChild/nextSibling 规则在物理形态上都用两条指针，但它们表达的逻辑关系完全不同。

## 09.5 从第一棵根沿兄弟链还原森林 {#v4-forest}

森林是一组互不相交的树。若它们的根依次为 A、F、H，可以把根也看成一条兄弟链：A.right=F，F.right=H。于是一个孩子兄弟二叉表示既能表示单棵普通树，也能通过根的兄弟关系连接多棵树。

面对一张静态表，里面可能包含结点编号、data、llink、rlink。想恢复森林，建议采用两层扫描。第一层沿最上层根的 rlink 找到森林中每棵树的根；第二层对每个根，沿 llink 找其首孩子，再沿这些孩子的 rlink 找同父亲的其他孩子。对于孩子结点还要递归重复这一过程。

例如课后题中，森林包含三棵根树 A、F、H。A 的直接孩子 B、C、D，其中 D 的孩子 E；F 的孩子 G；H 的直接孩子 I、J，其中 I 的孩子 K。如果将这些关系写回孩子兄弟链接，A.left=B、B.right=C、C.right=D、D.left=E；A.right=F、F.left=G、F.right=H；H.left=I、I.right=J、I.left=K。

这样还原时，任何一个 rlink 的含义都是“同层的下一个兄弟”，而非“原树的右子树”。如果忘记这个规定，把 A.right=F 画成 A 的孩子，就会把森林的棵数也画错。

## 09.6 二叉树形态的数量为什么会服从递推 {#v4-catalan}

最后研究一个组合问题：如果只有 n 个结点，先不考虑标签究竟是什么，只想知道二叉树可能有哪些不同的**结构形态**。n=0 时可以把空树视为一种合法形态；n=1 时只有一个根；n=2 时，第二个结点可以是根的左孩子或右孩子，故有两种。

对 n=3，我们可以不直接逐个画，而是先枚举**根的左子树用了多少结点**。根本身占去一个结点，剩余 n−1 个可以分给左右子树。若左边有 k 个，右边就有 n−1−k 个。左边有 T(k) 种形态、右边有 T(n−1−k) 种，组合数相乘；对全部 k 相加：

<code>T(n)=Σ[k=0..n−1] T(k)T(n−1−k)，T(0)=1</code>。

所以 T(1)=1，T(2)=2，T(3)=T(0)T(2)+T(1)T(1)+T(2)T(0)=2+1+2=5。这些数叫 Catalan 数，闭式为 <code>Cₙ=binom(2n,n)/(n+1)</code>。你可能还记得第三章的合法出栈序列计数也出现了相同数列；它们背后具有可以建立对应的组合结构，但在考试中必须先说明当前到底在数“树形”还是“合法出栈序列”。

## 09.7 章节练习：还原关系时先解释链接语义 {#v4-thread-forest-exercises}



#### 练习 1｜空指针域数量（基础，8 分）

**题目。** 一棵非空二叉树有 n=12 个结点，每个结点都保存 left、right 两个孩子指针，缺失的孩子用 nullptr 表示。请从“结点有多少指针域”和“树有多少真实边”两个角度，求空指针域的准确个数。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 总共 2n 个指针域；真实父子边数 n−1。

**解答。** 总指针域 24 个，真实孩子链接 11 条，所以空指针域为 24−11=13，即一般公式 n+1。这个结论与树是否满、是否平衡无关。

</details>



#### 练习 2｜从孩子兄弟链接画原树（作业同级，10 分）

**题目。** 使用 firstChild/nextSibling 语义：A.firstChild=B，B.nextSibling=C，B.firstChild=D，其余相关链接均为空。请还原一般树，指出 A 和 B 的直接孩子分别是谁，并写出从 A 开始按孩子从左到右的先序。

<details class="question"><summary>查看思路与解答</summary>

**思路。** B.nextSibling=C 表示 C 与 B 同父；B.firstChild=D 才表示 D 是 B 的孩子。

**解答。** A 的直接孩子为 B、C；B 的直接孩子为 D；C、D 都没有其他孩子。先序为 A、B、D、C。若把 C 画成 B 的右孩子，则误解了 nextSibling 的定义。

</details>



#### 练习 3｜森林棵数与根链（作业同级，10 分）

**题目。** 一份孩子兄弟表示中，根链按 A.nextSibling=F、F.nextSibling=H 相连，A 的孩子为 B、C，F 没有孩子，H 的孩子为 I。请说明森林含几棵树、各树根与直接孩子，不能因为某个根没有孩子就将它忽略。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 根的 nextSibling 负责枚举森林里的下一棵树，而 firstChild 才进入当前树内部。

**解答。** 森林含三棵树，根分别为 A、F、H；A 的孩子 B、C，F 是只有一个根的单结点树，H 的孩子 I。F 没有孩子不影响它是一棵独立的树。

</details>



#### 练习 4｜中序线索树中的后继（作业同级，10 分）

**题目。** 某结点 p 采用 tag=0 表示真实孩子、tag=1 表示线索。已知 p.rtag=0，且 p.right 指向结点 C，C 有左孩子 B，而 B 没有左孩子。求 p 的中序后继并说明推导过程。再说出若 p.rtag=1，寻找规则如何改变。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 真右子树需要找最左结点，线索则已经直接保存后继。

**解答。** p.rtag=0 表示 C 是右子树根；中序处理该子树时先沿左边访问 B，所以 p 的后继是 B。若 p.rtag=1，p.right 直接保存后继线索，应直接读取，不能当作真实右孩子继续往下遍历。

</details>



#### 练习 5｜Catalan 形态计数（提高，10 分）

**题目。** 不给结点附加互异标签，只把含 n 个结点的二叉树左右形状视为不同形态。设 T(0)=1。请列出 n=3 时根的左子树分别含 0、1、2 个结点时的形态数贡献，并求 T(3)。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 当左边有 k 个结点时，右边有 2−k 个，形态数相乘。

**解答。** k=0 时 T(0)T(2)=1×2=2；k=1 时 T(1)T(1)=1；k=2 时 T(2)T(0)=2×1=2。合计 T(3)=5。T(0)=1 表示空子树是一种可能的结构选择，不意味着它有一个实际结点。

</details>

本章的关键在于“同一条链接在不同结构里代表什么”。普通二叉树的 right 是右孩子，线索树要看 rtag 才能决定 right 的用途，孩子兄弟表示中的 right 则是下一个兄弟。明确含义以后，森林还原和中序后继查询才会自然。
