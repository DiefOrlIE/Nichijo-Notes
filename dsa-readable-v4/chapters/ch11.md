# 第 11 章　哈夫曼树：让常见符号走更短的路

> **来源**：《DSA 5-Tree》与《DSA 5a-HuffmanTree》，结合原作业八权值构造题。  
> **先修**：二叉树、路径长度和最小堆。  
> **目标**：理解前缀码；用带权路径长度表达总编码成本；逐次构建哈夫曼树、计算 WPL；解释为什么贪心合并能够得到最优解。

上一章我们把最大值或最小值放在堆顶，便于反复取出。这一章将利用“反复提取最小的两个值”来解决一个编码问题。为什么会需要这样的操作？因为不同字符出现的频率不同，如果让最常见的字符使用更短的二进制码，就可能节省整个文件的存储空间。但码长又不能随意分配，否则接收方不知道一段比特究竟应该怎样切成字符。

## 11.1 编码为什么不能只靠短和长的任意组合 {#v4-huffman-problem}

假设有字符 A、B、C、D，出现次数分别为 10、4、2、1。如果统一用两位编码四个字符，总共需要 (10+4+2+1)×2=34 位。直觉告诉我们：A 出现十次，如果能用一位表示它，而把只出现一次的 D 分配较长码，总位数就可能减少。

但我们不能随意设置 A=0、B=01。连续比特流读到 0 的时候，接收方无法立即判断它代表完整的 A，还是接下来还有 1 才表示 B。这说明**编码是否能无歧义解码**是必须先满足的约束，节省位数只能在合法编码的范围内追求。

一种足够简单的合法规则称为前缀码：任何完整字符码字都不能是另一字符码字的开头。比如 A=0、B=10、C=110、D=111 满足该条件；读到 0 就能确定 A，读到 10 就能确定 B，而 11 后必须继续区分 C 或 D。这样的编码可以从左到右逐步解码，无需先知道每个字符码字的具体终点位置。

## 11.2 从码字到二叉树：为什么字符必须放在叶子 {#v4-prefix-code}

把每个码字解释为二叉树的一条路径。从根出发，向左走记 0，向右走记 1。当一条路径到达某个字符结点时，读到的整段 0/1 就是该字符的码字。

为了保证前缀性质，我们让每个字符出现在**叶结点**。这样任何字符结点都不可能是另一个字符结点的祖先，因此一个完整码字也就不可能成为另一完整码字的前缀。反过来，一个前缀码也可以用类似的二叉树表示。

码字长度等于从根到叶子经历的边数。若字符 i 出现频数 wᵢ，所在叶深度为 dᵢ，它为总编码长度贡献 wᵢdᵢ 位。将所有字符贡献相加，得到带权路径长度（Weighted Path Length，WPL）：

<code>WPL=Σᵢ wᵢdᵢ</code>。

这里的权值可以是字符出现频数，也可以是某个叶结点的其他成本权重。频数越大，增加一层带来的总成本越高，因此优化目标自然是让大权值尽可能靠近根，让小权值承担较长路径。

## 11.3 为什么每次都选两个最小权值合并 {#v4-huffman-greedy}

先从四个权值 2、3、5、8 出发。我们可以想象构造树时，最深处必然存在一对兄弟叶。若一个深处叶权值为 8，而较浅处叶权值为 2，交换它们后，权值 2 承担更长路径、8 承担更短路径，总 WPL 不会增加。这提示我们：最小的两个权值应有机会在一棵最优树的深处相邻放置。

于是做出一个局部选择：先把当前最小的 2 和 3 放到同一个新父结点下，新父权值设为 2+3=5。此时我们面对的是三个“待连接的树”，其权值分别是新 5、原 5、8；再次取最小的两个 5 合并得 10；最后把 8 与 10 合并成根 18。完成构造。

<pre class="diagram">初始权值候选：2,3,5,8
合并 2 与 3 → 新父权 5，候选 5,5,8
合并 5 与 5 → 新父权 10，候选 8,10
合并 8 与 10 → 新父权 18，候选只有根
</pre>

每次将两棵树挂到新父亲下面，它们内部所有叶子的深度都增加 1，因此整个 WPL 的增加量恰好等于**两棵树原权值之和**。所以即使还没有逐叶算深度，也可把每次合并成本相加得到 WPL=5+10+18=33。

这就是哈夫曼构造法：反复合并当前权值最小的两棵树，直到只剩一棵。若有多个相同权值，左右次序或选择顺序可能产生不同形状，但最终 WPL 可以相同；题目若指定平局处理规则，应据此作图。

## 11.4 八个权值怎样一步步合并到 229 {#v4-huffman-trace}

原作业给出八个权值 {15,3,14,2,6,9,16,17}。先按从小到大排列为 2、3、6、9、14、15、16、17。每一次从**包括刚刚合成的内部结点**在内的候选中选两个最小值：

| 轮次 | 取出的两个最小权值 | 产生的新父结点权值 | 累计合并成本 |
|---:|---|---:|---:|
| 1 | 2 和 3 | 5 | 5 |
| 2 | 5 和 6 | 11 | 16 |
| 3 | 9 和 11 | 20 | 36 |
| 4 | 14 和 15 | 29 | 65 |
| 5 | 16 和 17 | 33 | 98 |
| 6 | 20 和 29 | 49 | 147 |
| 7 | 33 和 49 | 82 | 229 |

为什么最后根权值应为 82？因为每个内部结点的权值是其全部叶子权值之和，最终根包含所有八个叶，根权就是 15+3+14+2+6+9+16+17=82。这是一个重要的过程检查：如果根权与原叶权总和不等，说明某一轮漏掉或重复使用了候选。

WPL 则是各次合并成本 5、11、20、29、33、49、82 之和，即 229。**根权值和 WPL 代表不同的量**：根权是全部叶权总和，WPL 是叶权乘路径长度的加权成本。两者不能混淆。

## 11.5 这套贪心为什么能保证最优 {#v4-huffman-proof}

只看一个例题得到更小成本，还不能证明每次合并最小权值一定正确。哈夫曼算法背后的理由有两步。

第一步是交换论证。在任何一棵合法的最优前缀码树中，取一对最深的兄弟叶。若两个最小权值没有位于这样的深处位置，就可以通过交换权值安排，让更小的权值来到不浅于较大权值的深度；由于总成本是权值乘深度，小权去深、大权去浅，不会让 WPL 增加。因此我们总能够选择一棵最优树，让最小的两个权值成为最深的一对兄弟叶。

第二步是缩小问题。把这对兄弟叶合成一个权值为两者之和的叶，就得到一个少一项的同类问题。若这个缩小后的问题存在更低成本的树，把合并结点再展开回原来的两个叶，就会得到成本更低的原问题方案，违背最优性。因此缩小后的问题也必须有最优解，且可以继续采用相同策略。

这两步合起来说明：每一轮选择两个最小权值，都不会把最优解排除掉。正是这个贪心选择性质，让我们能够放心地连续做局部合并。

## 11.6 最小堆怎样让反复合并变得高效 {#v4-huffman-code}

如果每次都用普通数组扫描剩余候选，寻找两个最小值会反复做很多工作。上一章已经学到最小堆可以 O(log n) 弹出最小项、O(log n) 插入新项，所以它正好服务于“每轮取两个最小，再放回一个合并值”的过程。

如果只要求计算 WPL，无需真正保存树的左右孩子。每次取出两个最小权值，求和并累加到 cost，然后将和放回堆，直到仅剩一项：

~~~cpp
#include <vector>
#include <queue>
#include <functional>
#include <stdexcept>

long long huffmanWpl(const std::vector<int>& weights) {
    if (weights.empty()) return 0;
    std::priority_queue<long long,
        std::vector<long long>,
        std::greater<long long>> pq;
    for (int w: weights) {
        if (w<0) throw std::invalid_argument("negative weight");
        pq.push(w);
    }
    long long cost=0;
    while (pq.size()>1) {
        long long a=pq.top(); pq.pop();
        long long b=pq.top(); pq.pop();
        long long merged=a+b;
        cost+=merged;
        pq.push(merged);
    }
    return cost;
}
~~~

n 个初始叶需要 n−1 次合并，每轮两次弹出一次插入，时间 O(nlog n)，额外堆空间 O(n)。如果题目还要求输出每个字符的编码，就必须把各个堆元素换成树结点地址或索引，合并时明确记录两个孩子，再从根到各叶沿左 0、右 1 生成码字。上面的代码计算 WPL 正确，但没有保存完整的树形，也就不能直接输出码字。

**从计算 WPL 走到真正保存和使用编码树。** 原先的最小堆只保留合并权值，能求出总成本，但找不到字符对应的左、右路径。若要输出每个字符的码字，就必须把每轮产生的新结点的左右孩子保存下来，并且在堆中放入结点地址。

我们按专题 PPT 的五字符例子操作：A(5)、B(2)、C(9)、D(6)、E(3)。先把 B(2) 与 E(3) 合并为新结点 5，再与 A(5) 合并为 10；D(6) 与 C(9) 合并为 15；最后 10 与 15 合并为 25。若相同权值时优先取创建更早的结点，且每次取出的第一个结点放左、第二个放右，就得到：

| 符号 | 权值 | 二进制码 | 路径长度 | WPL 贡献 |
|---|---:|---|---:|---:|
| A | 5 | 00 | 2 | 10 |
| B | 2 | 010 | 3 | 6 |
| E | 3 | 011 | 3 | 9 |
| D | 6 | 10 | 2 | 12 |
| C | 9 | 11 | 2 | 18 |

逐项相加得到 WPL=10+6+9+12+18=55，也等于四轮合并成本 5+10+15+25=55。左右枝顺序改变时，具体码字可能改变，但叶子深度不变就不会影响 WPL。解码则从树根开始读 0 向左、读 1 向右，到叶子输出字符并返回根。例如 0101100 可分成 010、11、00，依次解出 B、C、A。若比特串在内部结点处结束，则最后一个字符尚未完整编码，应该报告错误。

下面展示完整的 C++17 建树、编码、解码。每个结点由 unique_ptr 负责释放；堆只保存不会悬空的结点指针。对相同权值用创建序号固定顺序，让上表的码字可以重现：

~~~cpp
#include <map>
#include <memory>
#include <queue>
#include <vector>
#include <string>
#include <functional>
#include <stdexcept>

struct CodeNode {
    long long weight;
    char symbol;
    int serial;
    CodeNode *left, *right;
    bool leaf() const { return !left && !right; }
};
struct HuffmanTree {
    std::vector<std::unique_ptr<CodeNode>> nodes;
    CodeNode* root = nullptr;
};
struct CodeNodeCompare {
    bool operator()(const CodeNode* a, const CodeNode* b) const {
        if (a->weight != b->weight) return a->weight > b->weight;
        return a->serial > b->serial;
    }
};
HuffmanTree makeHuffman(const std::map<char, long long>& frequency) {
    HuffmanTree tree;
    std::priority_queue<CodeNode*, std::vector<CodeNode*>,
                        CodeNodeCompare> pq;
    int serial = 0;
    auto add = [&](long long w, char symbol, CodeNode* left,
                   CodeNode* right) {
        tree.nodes.push_back(std::make_unique<CodeNode>(
            CodeNode{w, symbol, serial++, left, right}));
        return tree.nodes.back().get();
    };
    for (auto [symbol, count] : frequency) {
        if (count <= 0)
            throw std::invalid_argument("frequency must be positive");
        pq.push(add(count, symbol, nullptr, nullptr));
    }
    while (pq.size() > 1) {
        CodeNode* a = pq.top(); pq.pop();
        CodeNode* b = pq.top(); pq.pop();
        pq.push(add(a->weight + b->weight, '\0', a, b));
    }
    if (!pq.empty()) tree.root = pq.top();
    return tree;
}
std::map<char, std::string> makeCodes(const CodeNode* root) {
    std::map<char, std::string> codes;
    std::function<void(const CodeNode*, std::string)> walk =
        [&](const CodeNode* p, std::string bits) {
            if (!p) return;
            if (p->leaf()) {
                codes[p->symbol] = bits.empty() ? "0" : bits;
                return;
            }
            walk(p->left, bits + "0");
            walk(p->right, bits + "1");
        };
    walk(root, "");
    return codes;
}
std::string decodeCodes(const CodeNode* root, const std::string& bits) {
    if (!root) {
        if (!bits.empty()) throw std::invalid_argument("empty codebook");
        return "";
    }
    if (root->leaf()) {
        for (char bit : bits)
            if (bit != '0') throw std::invalid_argument("invalid bit");
        return std::string(bits.size(), root->symbol);
    }
    std::string result;
    const CodeNode* cur = root;
    for (char bit : bits) {
        if (bit != '0' && bit != '1')
            throw std::invalid_argument("invalid bit");
        cur = bit == '0' ? cur->left : cur->right;
        if (!cur) throw std::invalid_argument("invalid path");
        if (cur->leaf()) {
            result.push_back(cur->symbol);
            cur = root;
        }
    }
    if (cur != root) throw std::invalid_argument("unfinished codeword");
    return result;
}
~~~

由于 vector 内保存的是 unique_ptr 持有的独立动态结点，vector 自身扩容不会移动结点的实际地址，堆中的指针仍然有效。n 种符号需要 n−1 轮合并，建树时间 O(nlog n)；输出所有码字的时间还取决于码字总长度。单符号输入时额外规定唯一符号的码字为 "0"，空字符集则产生空树。**此处单符号码字长度为 1 是编码接口约定**；若考试仅问单结点树的数学 WPL，应遵从题目指定的根到叶边数约定。

## 11.7 章节练习：题目条件、合并记录和答案缺一不可 {#v4-huffman-exercises}

<details class="question"><summary>练习 1｜两个字符的编码长度（基础，8 分）</summary>

**题目。** 只允许使用二进制前缀码，字母 A、B 的权值分别为 6、2，每个字母必须有一个非空码字。求最优二叉前缀码树的 WPL，并说明两个叶的深度分别是多少。

**提示。** 只有两个字符时根只需要连接两个叶，它们的码字可以为 0 和 1。

**解答。** 两个叶深度都为 1，所以 WPL=6×1+2×1=8。交换左右边对应的 0、1 不影响码长和 WPL。

</details>

<details class="question"><summary>练习 2｜四权值完整合并（作业同级，10 分）</summary>

**题目。** 给定四个权值 2、3、5、8，使用哈夫曼算法构造最优二叉树。请写每轮取出的两个最小权值、生成的新权值，以及最后的 WPL。合并后的内部结点应重新加入候选。

**提示。** 第一次 2+3 得到的新 5，会与原来就存在的权值 5 共同成为下一轮候选。

**解答。** 第一次 2+3=5；第二次 5+5=10；第三次 8+10=18。WPL=5+10+18=33。根权 18 只表示全部叶权之和，不能代替 WPL。

</details>

<details class="question"><summary>练习 3｜八权值作业题（作业同级，14 分）</summary>

**题目。** 权值按输入顺序给定为 15、3、14、2、6、9、16、17。请完整列出哈夫曼构造过程中产生的七个内部结点权值、最终根权及 WPL，并用原始权值总和检验根。

**提示。** 每轮需要重新在所有尚未合并的树（包括新树）中选最小两项，不能只从原输入队列中固定取邻近两项。

**解答。** 内部结点权依次为 5、11、20、29、33、49、82，根权 82，WPL=5+11+20+29+33+49+82=229。原叶权总和为 82，与根一致，说明没有漏权或重复权。

</details>

<details class="question"><summary>练习 4｜平均码长与 WPL（提高，10 分）</summary>

**题目。** 某棵前缀码树对应字符的总出现次数为 25，全部编码总长度 WPL=55 位。求平均每次出现一个字符所需的二进制位数，并解释为什么不能除以字符种类数。

**提示。** WPL 是全部字符出现次数加权后的总编码位数。

**解答。** 平均码长为 55/25=2.2 位/字符。若只除以字符种类数，会忽略某些字符反复出现造成的实际文件长度贡献。例如一个字符出现十次，它的码长就应当在 WPL 中被累计十次；题目真正要平均的是全部 25 次字符出现，而非不同字符的类别数量。

</details>

<details class="question"><summary>练习 5｜交换左右子树是否影响 WPL（提高，10 分）</summary>

**题目。** 已构造一棵合法的哈夫曼二叉树，规定左边记 0、右边记 1。现在把某个内部结点的左右子树整体交换，树中所有叶的权值、父子层级保持不变。问编码字符串是否可能变化？WPL 是否变化？说明原因。

**提示。** 码字是沿边得到的 0/1 序列；WPL 只取决于每个叶的权值与深度。

**解答。** 处于被交换两侧的字符码字可能发生变化，因为路径上对应的 0/1 方向改变。但叶到根的边数没有改变，所有权值也没改变，所以 WPL 完全不变。即使具体码字不是唯一的，最优总编码成本仍可唯一确定。

</details>

当你能够从“前缀码必须无歧义”自然走到“用树表示码字”，再从“权值乘深度”走到“每次合并两个最小树”，你才真正理解了哈夫曼构造，而不只是会用计算器相加。
