# 第 01 章　数据结构是什么，复杂度又怎样计算

> **来源**：《DSA 1-Intro》（96 页）。下文的纸笔示例和现代 C++ 表述为讲义补充。

## 01.1 一个任务为什么会有多种表示法 {#v4-structure}

假设要管理一个班的学生名单。你可能只想按顺序打印姓名，也可能要经常在名单中间插入转专业同学，或者按学号快速找某人。表面上都是“保存一些学生”，操作的要求却完全不同。

数据结构研究的重点，就是怎样组织数据以及它们之间的关系，令所需操作可以有效完成。学生名单的先后关系是一种**逻辑结构**；在内存中把名单放成连续数组，还是用一个个相连的结点，是**存储结构**。同一逻辑顺序可以有多种存储实现：数组能 O(1) 按下标访问，链表需要顺序找；链表若已持有插入位置的前驱指针，可以 O(1) 改链接，数组则可能需要移动后面的元素。

研究结构之前先说清操作：查询第 i 项、按关键码查找、插入、删除、排序、遍历。操作的频率也会影响选择。假如列表只建立一次而随后查询一百万次，与每秒钟大量增删的列表，很可能不应该使用同一种实现。

## 01.2 逻辑结构与物理实现不是一回事 {#v4-adt}

课程会遇到线性结构、树、图等。线性结构的典型关系是前后相邻；树中一个结点可能有多个孩子；图可以有环，两个点之间也未必存在唯一父子关系。

抽象数据类型（ADT, Abstract Data Type）描述一类对象及其允许的操作，并不强迫使用某种内存布局。例如栈只要求提供 push、pop、top、empty，并遵守后进先出；用数组栈还是链栈，是随后才决定的实现问题。这种分离有实际用处：表达式求值的代码可以只关心“压入运算符”“弹出运算符”，不必同时管理内存分配。

你可以用三句话核对一种结构：它存放哪类对象？对象之间存在什么关系？最重要的操作是什么、代价是什么？如果这三个问题没有回答，背完“定义”通常仍无法选择合适的数据结构。

## 01.3 数时间，先从具体循环开始 {#v4-counting}

同样一个算法在不同计算机上运行所需的秒数不同。为了比较算法，我们通常把输入规模记为 n，选择基本操作并计算该操作执行了多少次。基本操作可以是一次比较、一次加法或一次数组访问。真正关心的是 n 越来越大时，操作总数增长得有多快。

先看：

~~~cpp
long long count=0;
for(int i=0;i<n;++i)
    for(int j=0;j<i;++j)
        ++count;
~~~

对 n=4，外层 i 依次是 0、1、2、3；内层分别执行 0、1、2、3 次，最后 count=6。对任意 n，次数是 <code>0+1+⋯+(n−1)=n(n−1)/2</code>。展开得 <code>(n²−n)/2</code>，主导增长的是 n² 项，所以记为 Θ(n²)。

这一步比背“二重循环 O(n²)”可靠。若内层上界换成固定 n，次数确实为 n²；但若内层是 <code>j=j*2</code> 并从 1 开始，每轮只执行约 log₂n 次，整个算法便可能是 Θ(nlog n)。循环层数本身不能决定复杂度。

## 01.4 O、Ω、Θ 表示的是不同的陈述 {#v4-notation}

对足够大的 n，如果某函数运行次数 T(n) 不超过常数倍的 f(n)，我们写 T(n)=O(f(n))，表示**渐进上界**。若 T(n) 至少是某常数倍的 f(n)，写 Ω(f(n)) 表示**渐进下界**。两者同时成立，才写 Θ(f(n)) 表示**紧确增长阶**。

例如 T(n)=3n²+7n+20，最终被 n² 这一项控制，因此 Θ(n²)；说它是 O(n³) 虽然也正确，却不够精确。常用增长速度由低到高是 <code>1、log n、n、nlog n、n²、n³、2ⁿ</code>（适用于足够大的正 n）。对数底数的不同只相差一个常数倍，不影响 Θ(log n)。

不要混淆“算法最坏时间复杂度 O(n²)”与“算法对任何输入都会运行 n² 次”。最坏上界只说明最不利输入也不会超过该数量级的常数倍，具体输入可能更少。

## 01.5 最好、平均与最坏，需要先定义输入 {#v4-cases}

设顺序查找一个包含 n 个互异关键码的数组。如果要找的元素刚好在首位，只比较一次；若在最后一位，比较 n 次；若一定成功且每一位置等概率，平均比较次数为 <code>(1+2+⋯+n)/n=(n+1)/2</code>。

如果题目允许查找失败，那么“平均多少次”就必须同时交代成功和失败的概率，以及失败时是否要比较全部 n 项。没有概率模型的“平均复杂度”不能从一个例子随意得出。

更深入的分析还可能讨论均摊复杂度：有些操作偶尔很贵，但在一长串操作中平均到每次很便宜。第三章以后的队列扩容和并查集会用到这一思想；现在只需将“期望平均”和“均摊平均”区分开，不把两者当成同一个公式。

## 01.6 算空间：输入、额外数组、调用栈分别处理 {#v4-space}

空间复杂度通常强调算法执行过程额外需要的存储。选择排序在原数组上交换，不需要另开与 n 同长的辅助数组，因此辅助空间 O(1)；归并排序通常需要 O(n) 辅助数组。

递归调用也会占用空间。一个每次递归到 n−1 的函数，即使每层只有常数个局部变量，最多仍可能积累 n 层栈帧，因此需要 O(n) 栈空间。不要因为代码里没用 <code>new[]</code> 就认为其额外空间必定为 O(1)。

## 01.7 用递归树分析递归算法 {#v4-recursion-tree}

假设一个算法先把规模 n 的问题分成两个规模 n/2 的子问题，再用 n 次基本操作合并结果，则时间满足 <code>T(n)=2T(n/2)+Θ(n)</code>。先按 n 是 2 的幂手算：根层工作 n；下一层两个子问题各 n/2，合计 n；再下一层四个各 n/4，合计仍为 n。到规模 1 停止，层数大约为 log₂n，每层工作 Θ(n)，于是总工作 Θ(nlog n)。你由此得到了结论，也知道每一个 n 从何而来。

相反，<code>T(n)=T(n−1)+Θ(n)</code> 没有分叉，但总时间是 n+(n−1)+⋯+1=Θ(n²)。复杂度分析要把所有实际工作加总，不能只数递归调用表达式里出现几个函数名。

## 01.8 什么时候该把复杂度用来做选择 {#v4-tradeoffs}

给定 n=10 的列表，O(n²) 算法可能足够快；给定 n=10⁶ 时，同样的平方增长会成为大问题。复杂度并不替代具体运行环境或数据规模，但它提供了规模增长时的可靠趋势。

考试中涉及结构选择题时，至少回答“需要什么操作”“数据当前有无有序性”“是否提供前驱位置或随机访问”“最坏时间和空间分别是多少”。这比只写“链表快”“二分查找快”更有说服力。

## 01.9 课后练习 {#v4-complexity-exercises}

<details class="question"><summary>作业同级：两个长度 m、n 的有序单链表复用结点归并，算法每轮至少取出一项。求时间与辅助空间。</summary><p>所有 m+n 项至多各被取出一次，时间 Θ(m+n)；只维护两个输入游标和一个结果游标，辅助空间 Θ(1)。若创建全新结点，结果存储另需 O(m+n) 空间，必须注明是否要求原地。</p></details>

<details class="question"><summary>作业同级：求 T(n)=T(n−1)+n、T(1)=1 的精确值及阶。</summary><p>展开为 n+(n−1)+⋯+1=n(n+1)/2，因此 Θ(n²)。这同时展示了精确表达式和渐进结论。</p></details>

<details class="question"><summary>提高：一个程序先执行 n 次工作，再分别递归处理两个规模 n/4 的子问题。分析时间增长。</summary><p>每层总工作依次为 n、n/2、n/4、…，形成几何级数，总和受 2n 限制，故 T(n)=Θ(n)。边界是子问题不断缩小直到常数规模；分支为两个并不必然是 nlog n。</p></details>

**小结自测：**给任意代码，先列“规模 n、基本操作、每层或每轮次数、总和、辅助存储”五项。若离开公式仍能解释该算法为什么快或慢，就具备下一章选择存储结构的基础。
