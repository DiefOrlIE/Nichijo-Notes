# 第 01 章　数据结构与算法分析

<p class="chapter-epigraph">怎样判断一种存储方案值不值得用</p>

> **来源**：《DSA 1-Intro》；本讲义另外补充了手工追踪、推导过程和 C++ 实例。  
> **前提**：会数组、循环与简单函数。  
> **目标**：区分逻辑结构、存储结构和 ADT；从实际操作次数推出复杂度；同时分析时间与辅助空间；根据操作场景选择合适的结构。

课程名叫“数据结构”，但程序员在实践中很少会收到“请实现一个数据结构”的需求。更常见的任务是“保存一群学生，能够查成绩、录入新学生、按顺序打印记录”。这三个动作看上去都在处理学生，却对存储方式提出了不同的要求。我们首先要学会的，是从任务中找出真正频繁的操作，再判断什么样的表示法适合它。

## 01.1 逻辑结构与存储结构 {#v4-structure}

<p class="section-epigraph">同一份名单，为什么会有完全不同的组织办法</p>

设班级名单按照入学顺序排列为甲、乙、丙、丁。你希望保留这个顺序，能够根据序号读取第 i 人，也能在中间插入新同学。我们可以用数组保存：每个人占连续存储中的一项，知道首地址和下标就能快速找到第 i 项。但如果要在乙之前插入新同学，后面的乙、丙、丁都必须让出位置。

另一种办法是让每人对应一个结点，结点里额外记录“下一人在哪里”。从甲顺着指针走到乙，再从乙走到丙，能够恢复相同的名单顺序。现在插入新同学，只需要改变少量链接；代价是如果只给第 i 个位置，必须沿链依次走过去。

你会发现，同一个有序名单，**我们关心的前后关系并没有变**，但它在内存里的表示方式可以非常不同。前后关系属于数据的逻辑结构，连续数组、链式结点等属于存储结构。学习数据结构，要先知道这些结构如何保持哪些关系，再分析它们如何实现所要求的操作。

一个很有用的问题是：“题目主要强调的是哪种操作？”如果 99% 的请求都在按下标读记录，数组的随机访问特别有价值；如果题目已经给了需要插入位置的前驱结点，链表的改链接会更直接。千万别把“链表插入 O(1)”当成无条件口号——如果题目只给序号，从头找到前驱仍然可能花 O(n)。

## 01.2 抽象数据类型（ADT） {#v4-adt}

<p class="section-epigraph">从“允许什么操作”到抽象数据类型</p>

回想上一节，同一份名单可以在数组或链表里实现。若编写业务代码的人只想执行“读取第 i 项”“在 i 位置插入”“删除某项”，每次操作都直接操心数组搬移或指针改接，会让程序难以维护。于是我们把外部可见的行为先规定清楚，让底层表示法留给实现去选择。

这就是抽象数据类型（Abstract Data Type，ADT）的思想：规定数据对象是什么、支持哪些操作、操作满足什么约束。例如栈的外部规则是最后进入的元素最先弹出，可能提供 push、pop、top、empty；它完全可以由连续数组或链表实现。用户只依赖“后进先出”这个约定，通常无需知道内部的 top 是怎样记录的。

学习时请同时保留三个层次。**逻辑层**描述数据之间的关系，例如线性先后、树形父子；**接口层**规定允许怎样使用，如插入、删除、查找；**实现层**说明对象怎样放进内存、每种操作怎样执行。三层分开后，才能合理比较不同实现，而不会把一个类的函数列表当成整个数据结构。

逻辑上常见的结构有线性表、树和图：线性表的普通内部元素各有一个直接前驱和后继；树的结点可以拥有多个孩子，但除根以外每结点有唯一父结点；图允许更一般的连接，包括环。这些分类并不直接说明哪一个更快。快慢仍取决于问题、实现和操作。

## 01.3 基本操作与时间计数 {#v4-counting}

<p class="section-epigraph">从一段循环亲手数出时间复杂度</p>

假设两个算法都能完成任务，你在电脑上运行一次，程序甲花 0.1 秒、程序乙花 0.3 秒，就能认定甲永远更好吗？不能。不同机器、编译器和输入数据都会影响秒数，更重要的是，当输入规模扩大十倍、一百倍时，两种算法的增长趋势可能截然不同。

因此算法分析常把输入规模记为 n，再选定某个基本操作（一次比较、一次加法或一次赋值），计算这个操作执行的次数。我们先看一段确实能手算的代码：

~~~cpp
long long count = 0;
for (int i = 0; i < n; ++i)
    for (int j = 0; j < i; ++j)
        ++count;
~~~

假设 n=5：外层 i=0 时，内层没有任何工作；i=1 时执行一次；i=2 时两次，依次直到 i=4 时执行四次。所以 count 最后为 0+1+2+3+4=10。推广到一般 n，内层总次数为 <code>n(n−1)/2</code>，即 <code>(n²−n)/2</code>。当 n 非常大时，n² 是增长最快的项，因而我们说它的时间复杂度与 n² 同阶。

这与“看见两层循环就写 O(n²)”有本质区别。若内层写成 <code>for(int j=1;j<n;j*=2)</code>，它只访问 1、2、4、8、… 等指数增长的下标，约执行 log₂n 次；外层仍做 n 次，整体就是 Θ(nlog n)。正确分析需要回答：**每个外层取值对应多少内层工作？把这些次数加起来是多少？**

计数时也要确定基本操作。比如一次交换可能有三条赋值语句，常数差异不会影响渐进复杂度，但在题目要求“精确比较次数”时仍要按比较的定义逐次计数。写清“我数的是什么”，比套上一个公式更可靠。

## 01.4 渐进记号 O、Ω、Θ {#v4-notation}

<p class="section-epigraph">大 O、Ω、Θ：上界、下界和同阶到底分别说了什么</p>

我们已经得到一次实际循环的次数 <code>T(n)=n(n−1)/2</code>。如果只关心 n 变大时的增长速度，常数 1/2 和低阶项 −n 对最终数量级没有决定性影响，于是用渐进记号压缩描述。

若存在正常数 c 和阈值 n₀，使所有 n≥n₀ 时都有 <code>T(n)≤c·f(n)</code>，就写 <code>T(n)=O(f(n))</code>，表示渐进**上界**。类似地，若有常数 c 使 <code>T(n)≥c·f(n)</code>，就写 <code>Ω(f(n))</code>，表示渐进下界。若上、下界都由同一个 f(n) 控制，写 <code>Θ(f(n))</code>，表示紧确的增长阶。

对 <code>T(n)=3n²+7n+20</code>，可写 Θ(n²)。它也是 O(n³)，因为更宽松的三次方上界仍成立；但若考试问“最紧的渐进阶”，写 Θ(n²) 才揭示了主要增长量。对于非常大的输入，常见阶的增长由慢到快大致为 <code>1、log n、n、nlog n、n²、n³、2ⁿ</code>。这个排序是在忽略常数、考虑足够大 n 的意义上成立，实际数据规模小时常数开销仍可能影响速度。

还有一个细节：大 O 描述的是数学函数的上界，不自动表示“最坏情况”。我们经常把**最坏运行次数函数**写成 O(n²)，这是因为先选定了最坏情况作为分析对象。如果研究的是某类输入上的平均次数，同样可以对这个平均函数使用 O、Ω 或 Θ。分析对象与渐进符号，是两个应当分开的判断。

## 01.5 最好、最坏与平均复杂度 {#v4-cases}

<p class="section-epigraph">最坏、最好、平均：平均之前必须说清概率</p>

设数组为 [3,8,12,20,35]，从左到右寻找某个存在的值。查找第一个值只需比较一次，查找末项则要比较五次。这两个输入规模同为 n=5，但运行次数不同。所以我们会分别讨论最好、最坏与平均情况。

如果题目明确说“查找必定成功，并且每一位置等概率”，那么五个位置各有 1/5 的概率。成功的平均比较次数为 <code>(1+2+3+4+5)/5=3</code>。对于长度 n，公式推广为 <code>(n+1)/2</code>。这个平均值完全依赖概率假设：若最前面的记录被查得最频繁，平均比较次数就可能明显小于 3；若失败查找也占一定比例，就需要把失败情况下的代价及其概率一并计入。

以后你还会见到查找的平均查找长度 ASL。它本质上是同一思想：把“每种结果需要比较多少次”与“这种结果发生的概率”相乘再求和。若题目没有给概率模型，不能随意把若干手算次数平均就认定那是唯一答案。

“均摊复杂度”是另一件事：它考虑一串操作整体付出多少工作，再平均到每次操作。例如某个动态数组偶尔扩容很贵，但只要扩容次数有限，一长串尾部追加的均摊代价仍可 O(1)。均摊分析不依赖输入结果的概率，与期望平均不能混用。

## 01.6 辅助空间复杂度 {#v4-space}

<p class="section-epigraph">算法还会占内存：什么才属于辅助空间</p>

学习复杂度时容易只记运行时间，但程序还能消耗内存。一个算法若额外新建长度 n 的工作数组，它的辅助空间为 Θ(n)；若只保存常数个计数器和指针，即使原输入有一百万项，额外空间仍可能是 Θ(1)。

不过这里要明确**什么被计入**。一般分析辅助空间时，把调用者已经提供的原始输入及要求返回的结果空间单独说明。若题目问程序总占用，则还需要考虑输入本身和结果。比如“在原数组上逆置”只需要若干指针或下标，辅助空间 O(1)；如果重新申请一个长度 n 的数组按逆序填值，就需要 O(n) 的额外数组。

递归更容易被忽视。即使递归函数里没有任何显式 <code>new</code>，每一次调用仍须保存参数、返回位置和局部状态。若递归参数按 n、n−1、…、1 逐层下降，最大同时活动的调用有 Θ(n) 层，栈空间就可能是 Θ(n)。树遍历所需栈空间则与树高 h 有关，最坏 O(h)；同样 n 个结点的平衡树和链状树因此可能差异很大。

这提醒我们：时间是整个执行期间**累计发生**的工作，空间看的是某一时刻**同时存在**的额外存储。不能把累计函数调用次数直接写成栈空间。

## 01.7 递归树分析法 {#v4-recursion-tree}

<p class="section-epigraph">递归树：把时间成本按层堆起来</p>

先想象一个算法处理 n 项数据时，把任务平均分给左右两部分，每部分大小 n/2，最后还要花 n 次操作把结果合并。其运行时间可以写作 <code>T(n)=2T(n/2)+n</code>，当 n 足够小时直接完成。

若 n=8，整棵递归树根层做 8 次工作。下一层有两个规模 4 的问题，合计做 4+4=8 次；再下一层四个规模 2 的问题，合计仍是 8 次；最底层八个规模 1 的任务，也合计 8 次。因此每层的总工作近似都是 n，而不断对半缩小使层数约为 log₂n+1。把每层累加，得到 Θ(nlog n)。

再换成 <code>T(n)=T(n−1)+n</code>，每层只产生一个子任务，却有 n、n−1、n−2、…、1 等不同工作量，累加是 <code>n(n+1)/2=Θ(n²)</code>。你会发现“分支多少”“每层做多少工作”“总共有多少层”是三个必须同时回答的问题。任何一个被省略，都可能让递归复杂度分析出现错误。

递归树法还能让你看见重复工作。例如求 Fibonacci 数时，每个 F(n) 又分别计算 F(n−1) 和 F(n−2)，很多 F(k) 在不同分支里被反复求出。之后学习动态规划时，这种重复子问题会成为优化的关键线索。

## 01.8 数据结构选型 {#v4-tradeoffs}

<p class="section-epigraph">用操作要求选择结构：怎样避免空洞结论</p>

课程真正希望你掌握的，并非只会把代码归类成 O(n)、O(nlog n) 或 O(n²)。你还要能够根据任务做出取舍。例如“经常按序号访问第 i 个成员”有利于选择顺序数组；“已经拥有一个结点的前驱地址，需要在它后面插入新结点”适合链式结构；“总要获得当前最大值”可以考虑堆。

这时必须注意限定条件。说“链表插入 O(1)”需要补充“已知待插位置的前驱结点”；说“二分查找 O(log n)”需要说明“数据有序且能 O(1) 访问中间项”；说“堆能取最大值 O(1)”需要区分**查看堆顶**和**删除堆顶并恢复堆**，后者通常要 O(log n)。

当你面对一道新的结构选择题时，可以先写一份简短的判断过程：数据之间的逻辑关系是什么？最频繁的操作是什么？题面已经提供哪些位置或索引？有没有内存、排序、稳定性和实时更新的限制？最后再列出候选结构的时间及空间代价。按照这个顺序比较，你就从被动记忆定义转向主动解决问题。

## 01.9 本章综合练习 {#v4-complexity-exercises}

<p class="section-epigraph">章节练习：必须展示计数理由</p>

#### 练习 1｜循环次数（基础，8 分）

**题目。** 已知 n 为正整数，分析 <code>for(int i=1;i<n;i*=2) work();</code> 的渐进时间复杂度，假设 work() 每次只做常数工作。请先列出 n=17 时 i 的实际取值，再说明一般 n 的循环次数为什么与对数有关。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 第 k 次执行时 i 是 2 的某个幂；循环停止在 i≥n。

**解答。** n=17 时 i 依次为 1、2、4、8、16，共 5 次。一般从 1 不断翻倍，执行 k 次后即到 2ᵏ 量级；达到 n 所需次数约为 log₂n，因此时间 Θ(log n)。注意 i 初值必须大于零，否则 0 连续乘 2 永远仍是 0。

</details>



#### 练习 2｜精确次数到渐进阶（作业同级，10 分）

**题目。** 以下循环以 n≥0 为输入，每执行一次 <code>++count</code> 算一次基本操作。请先求 n=4 的精确执行次数，再求一般 n 的封闭表达式与 Θ 阶。

~~~cpp
int count = 0;
for (int i = 0; i < n; ++i)
    for (int j = 0; j <= i; ++j)
        ++count;
~~~

<details class="question"><summary>查看思路与解答</summary>

**提示。** 观察内循环是 <code>j<=i</code>，第 i 轮包括 j=0，一共 i+1 次。

**解答。** n=4 时外层 i=0、1、2、3，内层分别做 1、2、3、4 次，合计 10。一般为 <code>1+2+⋯+n=n(n+1)/2</code>，主导项 n²，因此 Θ(n²)。若误把 <= 看作 <，会错误地少计整整 n 次。

</details>



#### 练习 3｜多段程序的复杂度（作业同级，10 分）

**题目。** 某程序先对 n 项数组执行一次顺序扫描（每项常数工作），接着执行双层循环：外层 n 次，内层执行约 log₂n 次；最后还执行 1000 次固定操作。假设 n≥2。求整体 Θ 阶，说明为什么不能将三段的时间复杂度简单相乘。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 三段按顺序执行，应该把工作次数相加；只有内外嵌套才需要相乘。

**解答。** 三段时间分别 Θ(n)、Θ(nlog n)、Θ(1)，因此总代价是它们之和，主导项为 Θ(nlog n)。把三段相乘相当于误认为第二段对第一段的每一步都重新执行，但题目明确说它们是顺序连接。

</details>



#### 练习 4｜递归时间与栈空间（作业同级，12 分）

**题目。** 算法 <code>F(n)</code> 在 n>1 时先执行 n 次常数工作，再分别递归调用两次 <code>F(n/2)</code>，n 是 2 的幂；n=1 时只做常数工作。求时间复杂度，并说明若采用深度优先递归执行，最大额外调用栈空间是多少。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 先画每层结点数量和每个结点的规模，再另外数单条从根走向叶子的调用路径。

**解答。** 第一层工作 n，第二层两个 n/2 的工作总计 n，第三层四个 n/4 的工作仍是 n。共有 Θ(log n) 层，时间 Θ(nlog n)。同时活动的调用帧只沿一条递归路径，深度 Θ(log n)，每帧常数空间时额外栈空间 Θ(log n)。总调用数与最大同时活动数不能混为一谈。

</details>



#### 练习 5｜已知条件对结构选择的影响（提高，10 分）

**题目。** 某学生档案按加入顺序保存，使用过程中绝大多数操作是读取第 i 条记录，偶尔才在末尾追加一条记录，且已知最大档案数量不会超过内存容量。你会选择带随机访问的顺序表还是只有 next 指针的单链表？请至少比较两项操作及其时间复杂度，并解释哪些条件变化可能让你的选择改变。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 先计算读取第 i 项的代价；再考虑末尾追加是否需要搜索到尾部。

**解答。** 倾向选择顺序表：按下标读取 O(1)，尾部在容量允许时追加 O(1)。单链表按第 i 项读取需要沿 next 前进 O(i)；若维护尾指针，尾部追加可 O(1)，若没有尾指针还要遍历。若任务改为“已知前驱位置，频繁在中间插入或删除”，链表就可能更合适。结构选择必须结合实际操作分布，不能凭“链表灵活”一句话决定。

</details>
