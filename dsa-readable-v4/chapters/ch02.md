# 第 02 章　线性表：同一种顺序如何产生两种不同的算法

> **资料**：《DSA 2-LinearList》，并对照《Lesson 3 Practice》的有序链表原地归并题。  
> **先修**：指针与结点的基本语义、循环复杂度。  
> **目标**：理解顺序表与链表各自维护什么；能够追踪插入删除的链接；亲手完成有序合并、链表逆置和多项式相加。

在前一章，我们以学生名单为例发现：逻辑上同样的前后顺序，可以用连续数组或链接结点保存。这一章将不再满足于说它们“各有优缺点”，而是拿出一个具体操作，一步一步看内存里发生了什么、为什么必须这样做。等两种存储方式都理解以后，后面的栈和队列就只是对同一种线性关系增加操作限制。

## 02.1 一张表意味着什么，什么又叫插入第 i 项 {#v4-list-meaning}

设名单为 L=(甲,乙,丙,丁)，长度 n=4。它有明确的顺序：甲在乙之前，丙在丁之前。所谓线性表，就是这类元素按一条先后链排列的数据对象；空表也允许存在。对于中间的元素，它有一个直接前驱和一个直接后继；首项没有直接前驱，末项没有直接后继。

现在说“在第 3 项之前插入新同学戊”。如果采用 **1-based** 编号，原第 3 项是丙，目标结果为 (甲,乙,戊,丙,丁)。如果改用 C++ 的 **0-based** 下标，则这个插入位置是 2。表面上只差一个数字，但顺序表搬移范围、链表寻找前驱的位置都由它决定。因此任何计算题应先在纸上标出编号约定。

从逻辑层面看，插入以后原来丙、丁的相对顺序不应改变，只是它们的位置在结果表里顺延。物理实现可以搬移数组元素，也可以重新接线。接下来的两节就研究这两种方案如何维持这个基本要求。

## 02.2 顺序表：插入为什么必须从后往前搬 {#v4-seqlist}

顺序表将线性表的元素按逻辑顺序连续存储。若一项占 w 字节，首地址为 base，则 0-based 第 i 项位于 <code>base+i*w</code>。这解释了它的优势：只需算出偏移，不需要经过前面所有元素就能读取第 i 项，访问时间 O(1)。

但刚才的插入会遇到内存位置冲突。以长度 4、容量至少 5 的整数顺序表 [2,4,6,8] 为例，要在原下标 1 插入 3。原来的 4、6、8 都必须分别向右移动一格。如果先把 4 放到下标 2，它会覆盖尚未来得及移动的 6。因此搬移必须从末尾开始：

| 动作 | 数组有效区域变化 | 这样做的理由 |
|---|---|---|
| 初始 | [2,4,6,8,_] | 第 4 格尚有空间 |
| 将 8 右移 | [2,4,6,8,8] | 原末项先保留 |
| 将 6 右移 | [2,4,6,6,8] | 旧 6 的内容已复制 |
| 将 4 右移 | [2,4,4,6,8] | 下标 1 现在可写 |
| 写入 3 | [2,3,4,6,8] | 得到目标顺序 |

把“下标 1 之前的前缀”与“下标 1 开始需要右移的后缀”分开，就能直接求移动次数。原长度 n、插入位置 pos（0-based）时，后缀长度为 n−pos；因此从数组插入 O(1) 的定位优势，抵不过中间插入最坏需要移动 Θ(n) 项的事实。删除 pos 位置时，让它右边每项向左前进一步，共 n−pos−1 项，最坏也为 Θ(n)。

~~~cpp
#include <vector>
#include <stdexcept>

void insertAt(std::vector<int>& a, int pos, int value) {
    if (pos < 0 || pos > (int)a.size())
        throw std::out_of_range("insert position");
    a.insert(a.begin() + pos, value);
}
void eraseAt(std::vector<int>& a, int pos) {
    if (pos < 0 || pos >= (int)a.size())
        throw std::out_of_range("erase position");
    a.erase(a.begin() + pos);
}
~~~

这里使用 vector 帮我们管理容量、长度和元素移动，方便核对语义。课堂手写顺序表可能另设容量 <code>maxSize</code> 与当前长度 <code>length</code>，并手动执行数组赋值。在那种实现里，**capacity 是实际可用的槽数，length 是已经存入的有效项数**。length<m 时才可能继续插入；访问第 length 项依然越过了有效元素范围，即使底层数组还有对应内存。

## 02.3 单链表：只改两个链接，为什么还要花时间寻找位置 {#v4-linkedlist}

换一种表示法。把 2、4、6、8 分别存入四个独立结点，每个结点除了值还保存 next 指针。只有从首结点出发依次跟随 next，才知道逻辑上的“下一项”是谁。内存地址可以不连续，这让插入时无需将后面的 6、8 整体搬走。

假设已经拿到值为 2 的结点地址 p，要求在 p 后插入值为 3 的结点 q。我们需要保留原 p->next（值为 4 的结点地址），所以先让 <code>q->next=p->next</code>，然后再执行 <code>p->next=q</code>。这样连成 2→3→4→6→8。若先改 p->next，再把它复制给 q->next，q 很可能指向自己，旧后继便失去可达链接。

~~~cpp
struct Node { int value; Node* next; };

void insertAfter(Node* p, int x) {
    if (!p) return;
    Node* q = new Node{x, p->next};
    p->next = q;
}
bool eraseAfter(Node* p) {
    if (!p || !p->next) return false;
    Node* q = p->next;
    p->next = q->next; // 先跨过 q
    delete q;           // 再释放
    return true;
}
~~~

这段代码的局部修改只涉及有限个指针，因此**已知前驱地址**时插入、删除操作本身为 O(1)。但是如果题目只给“在第 i 项之前插入”，程序还必须从 head 起沿 next 找到 i−1 项，这会花 O(i) 时间。以后做复杂度分析要把“定位”和“修改”拆开，否则很容易写出不成立的 O(1) 结论。

## 02.4 不带头结点与带头结点：空表时为什么差别特别大 {#v4-list-variants}

在上面的链表里，head 可能直接指向第一个有效数据结点。这时删除第一项必须修改 head 本身：如果原链是 2→4→6，删除 2 之后，新的 head 应指向 4。若函数只接收一个普通 <code>Node* head</code> 参数而没有返回新地址，函数外的 head 可能仍指向被删除的旧结点。

另一种实现额外增加一个**头结点**，它不保存有效数据，只是长期位于链表最前面的哨兵。此时空表写作 <code>head→nullptr</code>；不管删除第一个还是其他数据结点，都可以理解为“删除某个已知前驱的后继结点”。引入哨兵的主要价值就是统一边界处理，不过也增加了一个额外结点，并且要记住 head 本身不参与表的长度和数据遍历。

链表还可以采用其他连接方式。循环链表的末尾 next 指回起点，遍历时不能再等待 nullptr；双向链表增加 prev 指针，允许从一个结点找到前驱，但删除时通常需要维护前后两个方向的链接。静态链表则把“下一结点在哪里”表示为数组下标而不是内存地址。它们依然表达线性顺序，只是为了不同操作便利作出了不同的存储取舍。

理解这些变体时，建议始终画同样一条三结点链，分别问“空表怎样表示”“首项怎样删除”“最后一项怎样判断”“修改一条链接会不会破坏另一条链接”。这样比机械背四种链表的定义更有效。

## 02.5 头插与尾插：相同输入为什么生成了不同顺序 {#v4-list-build}

构建链表时，输入数据往往按 1、2、3 的顺序到来。如果每次新建结点都接在**当前首项之前**，第一次结果为 1，第二次为 2→1，第三次为 3→2→1。这就是头插法，它把输入顺序逆过来了。

如果希望保留输入顺序，就维护一个尾指针 tail，让每个新结点接到 tail 的 next，然后更新 tail。结果便是 1→2→3。假设某个算法要求“输入升序、结果降序”，头插正好是有用的工具；但如果题目要求稳定地保留相等键的原始先后关系，随意头插又可能改变它们的顺序。

已构建好的链表若要整体逆置，也可以重复应用这个思路：从原链取出一个结点，把它接在结果链最前面。关键仍然是先保存原后继，再改变当前结点 next。前置章节已经用 prev、cur、next 三个工作指针完成过完整逆置，这里的“逐项头插”与它是同一种指针操作规律。

## 02.6 作业核心：两条升序链如何原地合成降序链 {#v4-list-merge}

现在把前面的操作组合起来。已知 A=1→4→7，B=2→4→5，两条链内部按非递减顺序排列，且结点互不共用。题目要求把**所有六个原结点**合并成一条非递增链，不能申请新的数据结点，也不能改变各结点保存的整数。

若先合成一条升序链，再逆置，当然可以得到正确结果。但有没有办法只经过一次选取就得到降序链？观察两个输入各自有序，所以当前最小的剩余元素，一定在两条链当前首项之中。于是每次取较小的那个结点，并把它**头插到结果链前端**。随着我们取出的值越来越大，结果链前端也越来越大，因此它始终保持非递增。

| 轮次 | A 当前首项 | B 当前首项 | 取出值 | 头插后的结果 |
|---|---:|---:|---:|---|
| 1 | 1 | 2 | 1 | 1 |
| 2 | 4 | 2 | 2 | 2→1 |
| 3 | 4 | 4 | 4（A） | 4→2→1 |
| 4 | 7 | 4 | 4（B） | 4→4→2→1 |
| 5 | 7 | 5 | 5 | 5→4→4→2→1 |
| 6 | 7 | 空 | 7 | 7→5→4→4→2→1 |

特别注意第三、四轮：两个 4 来自不同的原始结点，题目要求全部保留，不能因为值相等就擅自去重。又因为输入是升序，取出某个结点以后，当前输入游标必须先前进到原后继，再把取出结点的 next 改为指向结果链。

~~~cpp
struct Node { int value; Node* next; };

Node* mergeDescending(Node* a, Node* b) {
    Node* result = nullptr;
    while (a || b) {
        Node* q;
        if (!b || (a && a->value <= b->value)) {
            q = a;
            a = a->next;     // 保存 A 剩余部分
        } else {
            q = b;
            b = b->next;     // 保存 B 剩余部分
        }
        q->next = result;    // 头插当前最小结点
        result = q;
    }
    return result;
}
~~~

每轮至少从 A 或 B 取出一个结点，因此两个输入总长度 m+n 时恰好进行 m+n 轮，时间 Θ(m+n)。程序只维护 a、b、q、result 四个指针，辅助空间 Θ(1)。空链表也能处理：如果 A 为空，程序只会从 B 依次取结点头插，得到 B 的逆序；如果两者都空，则直接返回 nullptr。

**这里真正需要掌握的并非四个指针的名字，而是一个操作不变量**：每轮开始时，A 和 B 仍按原序保存尚未处理的结点；result 已经按非递增顺序保存处理完的结点。每轮取出两条输入剩余部分的最小值并头插，两个条件继续成立。直到 A、B 都为空时，所有原结点恰好在 result 中出现一次。

## 02.7 多项式相加：两指针合并为什么又能用一次 {#v4-poly}

再看一个与名单看上去不同的问题。多项式 <code>P(x)=3x⁵+2x²+4</code> 只含三个非零项；若把它存成从 0 到 5 的完整系数数组，其中很多位置都是 0。可以把每个非零项记作 (系数,指数)，按指数大小链接起来，例如 P=(3,5)→(2,2)→(4,0)。

令另一个多项式为 <code>Q(x)=−3x⁵+7x³−2x²</code>，它的非零项链为 (−3,5)→(7,3)→(−2,2)。现在要求 P+Q。两条链都按指数从大到小排列，我们可以像归并有序链表那样，分别查看当前两个指数：

1. 指数相等为 5，系数相加 3+(−3)=0，因此这个项在结果中消失；
2. Q 当前指数 3 大于 P 当前指数 2，先输出 7x³；
3. 两边指数都是 2，系数 2+(−2)=0，仍不输出；
4. Q 已空，留下 P 的常数项 4，输出 4。

最终 <code>P(x)+Q(x)=7x³+4</code>。与上一个问题相比，两指针比较的骨架完全相同，但**相等时的处理语义不同**：原地多链归并保留全部重复值，多项式相加则要合并相同指数的系数，并在系数为零时省略该项。

这恰好说明学习数据结构的价值：理解“两个有序序列各用一个游标向前处理”的一般模式，之后能够根据新题的语义决定输出规则，而不用为每道题重新发明整个算法。

## 02.8 章节练习：题干要先说清结点和编号 {#v4-list-exercises}



#### 练习 1｜顺序表插入的精确移动次数（基础，8 分）

**题目。** 一个长度为 9、容量至少为 10 的顺序表按 **1-based** 位置编号。现在要在原第 4 项之前插入一个新元素，保持原有九个元素的顺序。请说明原来哪些位置的元素必须移动、搬移方向和移动总次数；再给出一般公式。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 先处理原来第 9 项，避免覆盖尚未移动的元素；一直处理到原第 4 项。

**解答。** 原第 9、8、7、6、5、4 项分别向后一位移动，共 6 项。最后把新元素写入第 4 项位置。一般在长度 n 的表的第 i 项之前插入，需要移动原第 i 到第 n 项，共 n−i+1 项。若换成 0-based 下标 pos，则为 n−pos。

</details>



#### 练习 2｜头插两次的链表状态（基础，8 分）

**题目。** 不带哨兵头结点的单链表初始为 2→6→8，head 指向值为 2 的结点。先创建新结点值 1 并头插，再创建新结点值 3 并头插。请画出两次操作后整条链，并说明 head 在两次操作中分别指向谁。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 每次头插都让新结点 next 指向当前 head，再将 head 改为新结点。

**解答。** 第一次得到 1→2→6→8，head 指向 1；第二次得到 3→1→2→6→8，head 指向 3。最先输入的 1 现在位于新来的 3 之后，因此连续头插会逆转这部分输入的先后。

</details>



#### 练习 3｜删除带头结点链表的首个数据项（作业同级，10 分）

**题目。** 结点定义为 <code>struct Node{int value;Node* next;};</code>。变量 head 指向一个不保存有效数据的**哨兵头结点**；当 head->next==nullptr 时链表没有数据项。请编写删除第一个数据项的核心代码，要求在空表时直接返回，非空时正确跨接和释放结点。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 因为 head 是哨兵，真正要删的是 head->next。释放前必须先取得被删除结点的原后继。

**解答。**

~~~cpp
void eraseFirst(Node* head) {
    if (!head || !head->next) return;
    Node* q = head->next;
    head->next = q->next;
    delete q;
}
~~~

当链表只有一个数据结点时，q->next 为 nullptr，跨接后 head->next 变空，符合题意。若先 delete q 再读取 q->next，会访问已经释放的对象。

</details>



#### 练习 4｜两链原地逆序归并（作业同级，12 分）

**题目。** 两个无环、互不共享结点的单链表 A、B 分别保存 1→4→7 与 2→4→5，均按非递减顺序排列。必须复用全部六个数据结点，不允许申请额外数据结点，也不允许修改 value。请写每次头插后的结果链，并给出最终函数应维护的指针、不变量、时间和额外空间复杂度。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 比较两个当前首项、取较小者、先让原输入游标前进，再把取出的结点放到结果头部。

**解答。** 取出顺序是 1、2、4(A)、4(B)、5、7；结果链依次为 1，2→1，4→2→1，4→4→2→1，5→4→4→2→1，7→5→4→4→2→1。结果始终非递增，输入剩余部分始终非递减。维护 a、b、q、result 四个指针即可，时间 Θ(m+n)、辅助空间 Θ(1)。相等值来自不同结点，两者都必须保留。

</details>



#### 练习 5｜多项式相加与零项消除（提高，12 分）

**题目。** 按指数从大到小存储两个稀疏多项式：P(x)=3x⁵+2x²+4，Q(x)=−3x⁵+7x³−2x²。请写出合并过程中每次比较的指数、系数处理结果以及最终的非零项链。说明这种合并与“保留重复值的两个有序链表归并”有何不同。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 两指针遇相同指数时相加系数；如果和为 0，就不要为这项生成结果结点。遇不同指数时，先输出指数较大的一项。

**解答。** 首次 5 与 5 相等，系数 3+(−3)=0，丢弃该项；之后 Q 的指数 3 大于 P 的 2，输出 (7,3)；两边指数 2 再次相等，系数 2+(−2)=0，丢弃；最终 P 剩 (4,0)，结果链 (7,3)→(4,0)，即 7x³+4。普通多链归并中重复键可能需要保留两个结点，而多项式相加要求根据系数和进行数学合并。

</details>

学到这里，你应该能够解释：顺序表为何移动数据而链表改动指针；为什么改 next 以前要保存旧后继；为什么“相同的双游标比较流程”可以用于逆序归并和稀疏多项式相加，却有不同的相等分支。接下来，我们会进一步限制线性表只允许在一端操作，得到栈。
