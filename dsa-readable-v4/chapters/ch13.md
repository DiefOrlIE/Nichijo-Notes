# 第 13 章　二叉搜索树：怎样在链接中保存大小顺序

> **资料**：《DSA 6-Search Tree》BST 插入、查找和删除部分。  
> **前置**：二叉树、中序遍历、有序数组、指针回接。  
> **学习目标**：理解 BST 的全子树有序约束；逐步查找与插入；正确处理删除结点的三类情况；写出能维护根指针的递归 C++ 程序。

上一章我们通过二分查找体会到：只要数据有序，一次比较就可以排除大量不可能的元素。但在有序数组中插入一条新记录时，后面的元素可能都需要移动。现在想结合链表的局部改接能力与二分的大小排除能力。二叉搜索树（Binary Search Tree，BST）便是从这个愿望出发的结构。

## 13.1 为什么二叉树需要比“父子关系”更强的约束 {#v4-bst-motivation}

普通二叉树只规定每个结点最多拥有左右两个孩子，并不约束关键码。例如根 8、左孩子 20、右孩子 1 也是合法二叉树，但我们无法只根据“目标与根的大小”判断应该往哪边查找。

BST 增加了一个有序规则：**对任意结点，其整棵左子树所有关键码都小于它，整棵右子树所有关键码都大于它；左右子树自己也遵守相同规则。** 例如根 8、左子树根 4、右子树根 12，而 4 下有 2、6，12 下有 10、15，这才形成可以通过大小关系查找的结构。

注意这个要求涉及**整个子树**。如果根 8 左侧的某个更深结点保存 11，即使它小于自己的直接父结点，也违反根 8 的左子树必须整体小于 8 的约束。检查 BST 时，不能只比较每对直接父子。

本章先假设关键码互异。如果题目允许重复键，必须另外规定相等时放哪边、是否在结点里计数等策略，否则“插入相等项”没有唯一操作规则。

## 13.2 一次查找为什么只需沿一条根到叶的路径 {#v4-bst-search}

沿用刚才的例子，要找关键码 10。先比较根 8，10 更大，因此只需进入右子树；整个左子树都小于 8，肯定不含 10。进入 12 时，10 小于 12，于是转左；下一个结点恰好是 10，查找成功。

<pre class="diagram">         8
       /   \
      4     12
     / \   /  \
    2   6 10   15

找 10：比较 8 → 比较 12 → 比较 10 → 成功</pre>

如果要找 11，则仍沿 8→12→10 走；11 大于 10，因此转到 10 的右孩子，但那里为空。这个空指针已经能证明目标不存在：按照 BST 的规则，任何可能存放 11 的位置都必须沿前面这些大小判断走向这条空链接，而那里当前没有结点。

查找时保持的不变量是：**如果目标存在，它一定属于当前指针指向的子树**。每次比较会把不可能的另一侧整棵子树排除，因此只需沿一条路径工作。时间与树高 h 成正比，O(h)。

## 13.3 插入：为什么走到空位置就够了 {#v4-bst-insert}

从空树开始按顺序插入 5、2、8、1、3。首先 5 成为根；2<5，应当放到 5 的左边，那个位置为空，于是直接创建结点 2；8>5，放到右边；1<5 且 1<2，放到 2 的左孩子；3<5 但 3>2，放到 2 的右孩子。

<pre class="diagram">        5
       / \
      2   8
     / \
    1   3</pre>

插入并不需要搬动其他结点，原因是新值按比较路径走到一个空链接，挂在这个位置后，它仍落在每一个祖先要求的合法大小区间里。比如 3 在根 5 的左子树范围（小于 5），又在结点 2 的右子树范围（大于 2），所以整个 BST 约束保持成立。

~~~cpp
struct Node {
    int key;
    Node *left, *right;
};

Node* insert(Node* root, int x) {
    if (!root) return new Node{x,nullptr,nullptr};
    if (x < root->key)
        root->left = insert(root->left, x);
    else if (x > root->key)
        root->right = insert(root->right, x);
    return root;
}
~~~

请特别注意 <code>root->left=insert(root->left,x)</code>：递归操作后返回的子树根必须接回原父结点。首次往空树插入时，外部也必须写 <code>root=insert(root,x)</code>，因为整个树根会从 nullptr 变为新结点。如果忽略返回值，即使 new 成功，调用者仍可能不知道新根地址。

## 13.4 删除为什么需要分类讨论孩子数量 {#v4-bst-delete}

与插入相比，删除更难。删除某个结点时，除了让目标关键码消失，还要确保剩余数据仍保持 BST 的整个子树有序性。最自然的做法是按被删结点拥有的孩子数量分成三类。

**没有孩子的叶子。** 从父结点对应的 left 或 right 链断开，释放目标即可。因为没有任何后代需要重新接回，逻辑最简单。

**只有一个孩子。** 直接让唯一的子树接替被删结点的位置。例如根 5 的左孩子 2 只有右孩子 3，删除 2 后可让 3 成为 5 的左孩子。原来 3 属于 5 的左子树且大于 2，接替后仍小于 5，因此不会破坏 BST。

**有两个孩子。** 不能简单随意丢弃某一侧。需要找一个能够在大小顺序上接替当前结点的关键码，例如它的**中序后继**：到当前结点的右子树里，一直沿 left 走到最左结点。这个值是所有大于当前结点的键里最小的，因此可以替代被删结点的关键码；然后再去右子树中删除后继原来的结点。

为什么后继原结点容易删除？因为它已经是所在右子树最左的结点，不可能还有左孩子，否则会存在更小的结点与“最左”矛盾。它可能有右孩子，但这属于前面的“零个或一个孩子”情形。这样两孩子删除最终就化成了简单删除。

## 13.5 亲手删除一个拥有两个孩子的结点 {#v4-bst-delete-trace}

仍使用插入得到的树：

<pre class="diagram">        5
       / \
      2   8
     / \
    1   3</pre>

现在删除结点 2。它拥有左孩子 1 和右孩子 3，因此进入双孩子情形。先进入 2 的右子树，在其中寻找最小关键码；这里只有结点 3，它就是中序后继。将原结点 2 的 key 替换成 3；随后删除右子树里原先保存 3 的叶子。这一步完成后，根 5 的左孩子保存 3，3 的左孩子仍是 1，右孩子为空。

<pre class="diagram">删除前：             删除后：
    5                    5
   / \                  / \
  2   8                3   8
 / \                  /
1   3                1</pre>

可以用中序遍历反向检查：删除前是 1、2、3、5、8；删除后是 1、3、5、8，恰好只少了 2 且仍严格升序。若程序只把 2 的 key 改为 3，却忘了删除右子树原来的 3，那么树里会出现两个相同关键码，违反本章互异的约定。

还有一种对称策略是使用中序前驱：进入左子树沿 right 找最右结点。它也能保持 BST 有序性，但可能得到不同的具体树形。因此手工题若指定“用后继”，必须按后继给出过程。

## 13.6 完整删除代码：为何每层都要返回新的子树根 {#v4-bst-code}

~~~cpp
Node* minNode(Node* p) {
    while (p && p->left)
        p=p->left;
    return p;
}

Node* erase(Node* root, int x) {
    if (!root) return nullptr;
    if (x < root->key) {
        root->left=erase(root->left,x);
    } else if (x > root->key) {
        root->right=erase(root->right,x);
    } else {
        if (!root->left) {
            Node* next=root->right;
            delete root;
            return next;
        }
        if (!root->right) {
            Node* next=root->left;
            delete root;
            return next;
        }
        Node* successor=minNode(root->right);
        root->key=successor->key;
        root->right=erase(root->right,successor->key);
    }
    return root;
}
~~~

若目标不存在，递归走到 nullptr 后返回，不改变原结构。若被删结点最多有一个孩子，函数直接返回接替它的那个子树根，供上层改写 left 或 right。若有两个孩子，替换键以后还要递归删除后继原结点，并将右子树的新根接回。

为什么不能删除完以后始终返回旧 root？因为当被删的恰好是某个子树的根，子树根可能变成它的孩子；如果它还是整棵树的根，外部 root 也必须改变。调用处应写 <code>root=erase(root,x)</code>。这项回接规则后面学习 AVL 旋转时同样重要。

## 13.7 BST 为什么仍然可能慢到线性时间 {#v4-bst-balance-need}

BST 的查找沿根到叶路径前进，所以时间取决于树高。但 BST 的大小有序规则**没有限制树必须长得均衡**。如果按 1、2、3、4、5 依次插入空树，新值每次都比当前结点大，便一路成为右孩子：

<pre class="diagram">1
 \
  2
   \
    3
     \
      4
       \
        5</pre>

查找 5 要比较所有五个结点。推广到 n 项，最坏树高 Θ(n)，查找、插入和删除都可能退化为 Θ(n)。如果插入顺序能形成近似平衡的树，树高才接近 Θ(log n)。

所以普通 BST 实现了“按大小方向查找、局部改链接插删”，却尚未获得稳定的最坏 O(log n) 保证。下一章将添加高度平衡约束，通过旋转防止树无限伸成长链。

## 13.8 章节练习：用中序遍历给自己验算 {#v4-bst-exercises}

<details class="question"><summary>练习 1｜识别 BST 的全子树约束（基础，8 分）</summary>

**题目。** 某二叉树根为 8，左孩子 4、右孩子 12；4 的右孩子为 10，其余孩子为空。假设全部关键码互异。判断它是否为合法 BST，并解释仅比较每个结点与直接孩子是否充分。

**提示。** 10 虽然大于它的父亲 4，却位于根 8 的整棵左子树中。

**解答。** 该树不合法，因为根 8 的整个左子树所有键都应小于 8，但左子树里的 10 大于 8。只检查局部父子会遗漏祖先规定的大小边界。

</details>

<details class="question"><summary>练习 2｜依次插入与画树（作业同级，10 分）</summary>

**题目。** 从空 BST 按顺序插入互异关键码 5、2、8、1、3。每次遇小值走左、遇大值走右，直到空孩子位置才插入。请画最终树，并写前序与中序序列。

**提示。** 先让 5 成根，之后每个新值沿实际比较路径下降。

**解答。** 根 5，左右孩子 2、8；2 的左右孩子为 1、3。前序为 5、2、1、3、8，中序为 1、2、3、5、8。中序严格升序是合法性的有力检查。

</details>

<details class="question"><summary>练习 3｜删除双孩子结点（作业同级，12 分）</summary>

**题目。** 在上一题得到的 BST 中删除关键码 2，规定使用中序后继替换，且不允许保留重复键。请给出查找后继的路径、替换动作、被实际释放的原结点，以及最终树形。

**提示。** 2 的右子树只有结点 3，右子树最小值就是 3。

**解答。** 后继 3 位于原结点 2 的右孩子处；将 2 的 key 改为 3，再释放原右孩子结点 3，令新键 3 的右指针为空。最终根 5，左孩子 3、其左孩子 1，右孩子 8。中序为 1、3、5、8，只删去了原关键码 2。

</details>

<details class="question"><summary>练习 4｜查找性能与退化（作业同级，10 分）</summary>

**题目。** 从空 BST 依次插入 1、2、3、4，然后查找关键码 4。假设每访问一个结点比较一次关键码。写出访问次序、比较次数，并分析对 n 个升序插入的键最坏时间阶。

**提示。** 每个新键都比所有已出现的祖先大，所以树不断向右伸长。

**解答。** 查找访问 1→2→3→4，共四次比较。一般 n 项时最深结点需要比较 n 次，最坏 Θ(n)。BST 的有序性本身无法保证平衡高度。

</details>

<details class="question"><summary>练习 5｜中序后继为什么没有左孩子（提高，10 分）</summary>

**题目。** 对一个拥有两个孩子的 BST 结点 x，教材选择“到右子树一路向左走到底”找到中序后继 s。请从 BST 的有序性出发，解释为何 s 不可能还有左孩子、为何它可以有右孩子，以及这如何降低删除的难度。

**提示。** 若 s 有左孩子，会存在一个比 s 更小、却仍在 x 的右子树中的关键码。

**解答。** s 已是 x 右子树中的最小键，如果 s 有左孩子，则该孩子键更小，与 s 最小矛盾，因此没有左孩子。s 可以拥有右孩子，且右孩子仍大于 s；删除 s 时只需用其右孩子接替它，属于“最多一个孩子”的简单情况。所以两孩子删除先找后继后便能转化为简单删除。

</details>

本章的主线是：大小顺序让查找只需沿一条分支；空链接使插入局部化；删除时要用恰当的前驱或后继保持有序；但树高尚未受限制，因此我们还需要下一章的平衡机制。
