# 第 13 章　二叉搜索树 BST：动态查找如何维持大小顺序

> 来源：《DSA 6-Search Tree》二叉搜索树部分。  
> 前置：树的中序遍历、递归、顺序查找。

## 13.1 有序数组很会查找，但为什么插入麻烦 {#v4-bst-motivation}

有序数组二分查找非常快，但如果频繁插入位于中间的新关键码，仍得移动许多元素。我们能否保留“比较关键码后能排除一部分对象”的优点，同时不用把全部记录搬到新位置？

二叉搜索树（Binary Search Tree，BST）给每个结点一个关键码，要求：所有左子树关键码严格小于根，所有右子树关键码严格大于根；左右子树自己也分别满足同一规则。若允许重复值，必须另定规则（例如统一放右侧或计数），本章先假设关键码互异。

## 13.2 查找一个关键码，为什么只需沿一条路径走 {#v4-bst-search}

设根为 8，左子树根 4，右子树根 12；4 左孩子 2、右孩子 6；12 左孩子 10、右孩子 15。要找 10，先比根 8，目标更大，就直接转右而无需查看左子树；再比 12，目标更小，转左；下一次比 10，成功。只访问了根→12→10 的三结点路径。

这个过程的循环不变量是：如果目标确实存在于整棵树里，它必定位于当前指针指向的子树中。每次比较后，大小关系保证被丢弃的方向没有目标。

## 13.3 插入时为什么只需修改一条空链接 {#v4-bst-insert}

按次序 5、2、8、1、3 插入空树：5 是根；2<5，放左；8>5，放右；1<5 且 1<2，放在 2 左边；3<5 但 3>2，放在 2 右边。得到：

<pre class="diagram">       5
      / \
     2   8
    / \
   1   3</pre>

新结点只需沿比较路径走到某个空链接并在那里接入，不需要移动原来的其他结点。下面使用返回子树根的递归写法，便于后面 AVL 旋转时复用同一接口：

~~~cpp
struct Node{int key;Node* left;Node* right;};
Node* insert(Node* root,int x){
    if(!root)return new Node{x,nullptr,nullptr};
    if(x<root->key)root->left=insert(root->left,x);
    else if(x>root->key)root->right=insert(root->right,x);
    return root; // 相等时本实现不重复插入
}
~~~

函数调用者必须写 <code>root=insert(root,x)</code>，因为原空树插入首项时根指针会从 null 变为新结点；返回值是新树根而非某个“查找成功标志”。

## 13.4 删除为什么分成零个、一个、两个孩子 {#v4-bst-delete}

删除 BST 中的结点，目标并不是单纯释放内存，而是让余下所有关键码仍满足大小顺序。

**无孩子的叶结点：**可以直接从其父亲链接断开。**只有一个孩子：**让这个唯一孩子接替被删结点的位置，因为孩子子树中的关键码本来就在这一方向的合法范围内。

**两个孩子：**若随意让某个孩子接替根，可能让部分结点落到不该在的位置。一个标准方案是找**中序后继**：在被删结点右子树里，从右子树根一路向左走到最小关键码，将这个值拿来替代被删关键码，再去其原位置删除这个后继结点。

为何后继最多只有一个孩子？因为它已经是右子树最左的结点，不可能还有左孩子，否则存在更小的候选。它可以有右孩子，所以原位置删除时只需处理“零个或一个孩子”的简单情形。

## 13.5 完整模拟删除一个有两个孩子的结点 {#v4-bst-delete-trace}

沿用前面的 BST：根 5，左子树根 2（左右孩子 1、3），右孩子 8。删键 2 时，它有左右孩子 1 与 3。右子树只有结点 3，所以 3 就是后继。先用 3 替换结点 2 中的关键码，再删原位置的 3 叶。新树根仍为 5，左孩子变成键 3、其左孩子为 1，右孩子仍 8。

如果题目规定使用**中序前驱**而非后继，也可以从左子树最右边选择关键码替代，所得具体树形可能不同。手工题要照给定策略画，不可只说“结果是合法 BST”而跳过指定过程。

## 13.6 完整的 BST 删除 C++17 代码 {#v4-bst-code}

~~~cpp
Node* minNode(Node* p){
    while(p&&p->left)p=p->left;
    return p;
}
Node* erase(Node* root,int key){
    if(!root)return nullptr;
    if(key<root->key)root->left=erase(root->left,key);
    else if(key>root->key)root->right=erase(root->right,key);
    else{
        if(!root->left){
            Node* next=root->right;
            delete root;
            return next;
        }
        if(!root->right){
            Node* next=root->left;
            delete root;
            return next;
        }
        Node* successor=minNode(root->right);
        root->key=successor->key;
        root->right=erase(root->right,successor->key);
    }
    return root;
}
~~~

这段代码**没有使用 AVL 高度平衡规则**，只维护 BST 有序性。注意它在删叶子和只有一个孩子时返回了可能改变的子树根，所以父调用必须把返回结果重新接回 left 或 right。

## 13.7 为什么 BST 的最坏时间仍可能是 O(n) {#v4-bst-balance-need}

如果按 1、2、3、4、5 的顺序插入，所有新结点都走到最右侧空链接，树变成 1→2→3→4→5 的单边链。查找 5 要比较 5 次，n 项时最坏 Θ(n)。若插入顺序较平衡，树高可能为 Θ(log n)，查找就更快。

这说明 BST 解决了动态插入时无须移动数组的问题，却没有自动保证树的高度。下一章的 AVL 在大小顺序之外增加高度限制，才给查找操作提供稳定的最坏性能。
