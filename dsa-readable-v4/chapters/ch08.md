# 第 08 章　树与二叉树：从层次关系一步步恢复结构

> **来源**：《DSA 5-Tree》二叉树、遍历、性质及重建部分，以及《4 String & BinTree Practice》相关习题。  
> **先修**：递归、栈、队列与数组下标。  
> **学习目标**：解释树的基本关系；推导叶子数公式；给出遍历轨迹；由前序与中序重建二叉树；正确处理数组中的缺失结点；理解显式栈与递归的关系。

我们已经学过线性表、栈和队列，它们都有很明确的一条先后顺序。但现实中有些关系会不断分叉：课程目录有章节和小节，文件夹里还有子文件夹。一个元素可能拥有多个直接下属，若继续用一条普通链表来表示，就必须额外编码大量分支信息。树提供了专门表达这类层次关系的模型。

## 08.1 从一张文件夹目录认识根、父亲与子树 {#v4-tree-idea}

想象一门课叫“数据结构”，下面分“线性表”“树”“查找”三章；“树”下面又分“二叉树”和“堆”。最上面的课程是根；章节是课程的孩子，课程是这些章节的父亲。没有继续划分下一级的项目是叶子。

树的关键性质是：对于非空树，存在一个根，每个其他结点恰有一个父亲。因此从根沿父子边到某个结点只有一条路径，这也意味着树没有从孩子绕回祖先的环。删去根后，剩下的是若干互不相交的树，也就是根的各棵子树。

结点的**度**是直接孩子数量。没有孩子的结点度为 0，称为叶子；树的度是全树结点度数的最大值。深度通常从根算起，若根深度为 0，则孩子深度为 1；高度可以按到最深叶的边数定义，也有教材按结点层数计。两种约定会相差 1，做题时应先看题面。

这些名词的价值是让我们能够说清结构。例如“一个结点有两个孩子”只说明局部度为 2；“树的高度为 4”则描述从根到最深位置的长度。之后的时间复杂度与树高高度相关，所以高度约定一定要清楚。

## 08.2 二叉树和普通树的差异不止是“最多两个孩子” {#v4-binary-shape}

二叉树的每个结点有固定的**左孩子位置和右孩子位置**。即使某结点只有一个孩子，我们也必须知道它是左孩子还是右孩子。例如 A 的唯一孩子 B 放左边，和 B 放右边，是不同的两棵二叉树。对于普通无序树，孩子通常作为一个集合或序列组织，具体排序要看模型定义；二叉树则天然区分左右。

<pre class="diagram">只有左孩子：       只有右孩子：
      A                 A
     /                   \
    B                     B</pre>

**满二叉树**的所有层都填满；**完全二叉树**允许最后一层不满，但必须按照从左到右依次填充。这种特殊形状使得完全二叉树可以紧凑存进一个普通数组，因为它在层序编号中没有中间空洞。后面学习堆时，这一点非常重要。

树的“形状”和结点的“值”也要分开。两个结点值相同的结构可能有不同形状；同一种形状也可以填入不同数据。重建题问唯一性时，必须确认题目给的遍历信息能否分辨这些可能。

## 08.3 树的计数性质：为什么叶子总比度为 2 的结点多一个 {#v4-tree-count}

课堂上常出现一个结论：非空二叉树中，度为 0 的结点数比度为 2 的结点数多 1，即 <code>n₀=n₂+1</code>。如果只背公式，很容易把它错误用到一般三叉树。其实这个关系可以从一个非常简单的观察推导出来。

一棵有 n 个结点的非空树，有 n−1 条父子边。为什么？根没有父亲，而其他每一个结点都恰有一条来自父亲的边，因此共 n−1 条。现在换个方向，从每个结点数出“它向下连了多少条边”。在二叉树里，度为 0、1、2 的结点分别贡献 0、1、2 条边。如果对应数量为 n₀、n₁、n₂，则总边数为 <code>n₁+2n₂</code>。

另一方面，总结点数 <code>n=n₀+n₁+n₂</code>，所以同一批边也等于 <code>n₀+n₁+n₂−1</code>。令两者相等：

<code>n₀+n₁+n₂−1=n₁+2n₂</code>，移项得到 <code>n₀=n₂+1</code>。

这个式子与 n₁ 无关，所以无论有多少只有一个孩子的结点，只要树非空，叶子数始终比双孩子结点数多 1。对一般树，若 nₖ 表示度为 k 的结点数，使用同样的边数两次计数可得 <code>n₀=1+Σ(k−1)nₖ</code>（对所有 k≥1 求和）。公式是结构关系的结果，而非需要凭空记忆的事实。

## 08.4 遍历：同一棵树为什么能产生三种不同次序 {#v4-tree-traversal}

如果要把一棵树的所有结点访问一次，关键是确定什么时候处理根。下面设根 A 有左右孩子 B、C；B 有孩子 D、E；C 只有右孩子 F：

<pre class="diagram">       A
      / \
     B   C
    / \   \
   D   E   F</pre>

前序（根→左→右）先输出 A，再完整访问 B 子树，最后 C 子树，得到 <code>A B D E C F</code>。中序（左→根→右）先完成左子树，再输出 A，最后右子树，得到 <code>D B E A C F</code>。后序（左→右→根）先完成两棵子树，最后输出 A，得到 <code>D E B F C A</code>。

为什么这些名字里都包含“序”？它们只改变**访问当前根的时间**。递归调用对子树的顺序仍是左子树优先，然后右子树。你可以用一个统一框架记忆：

~~~cpp
#include <iostream>
struct Node {
    char value;
    Node* left;
    Node* right;
};
void preorder(Node* p) {
    if (!p) return;
    std::cout << p->value << ' '; // 根
    preorder(p->left);             // 左
    preorder(p->right);            // 右
}
void inorder(Node* p) {
    if (!p) return;
    inorder(p->left);
    std::cout << p->value << ' ';
    inorder(p->right);
}
void postorder(Node* p) {
    if (!p) return;
    postorder(p->left);
    postorder(p->right);
    std::cout << p->value << ' ';
}
~~~

另有层序遍历，按 A、B、C、D、E、F 的先后逐层进行。它适合使用队列：访问 A 时把 B、C 入队，访问 B 时把 D、E 排到 C 后面，保证较浅层先完成。

时间上，每种遍历都会访问 n 个结点，故 Θ(n)；递归调用栈取决于树高 h，空间 O(h)。退化单链可能有 h=Θ(n)，近似平衡的树则只有 h=Θ(log n)。

## 08.5 两份遍历序列怎样一步步确定树形 {#v4-tree-rebuild}

假设有两份序列：前序 <code>A B D E C F</code>，中序 <code>D B E A C F</code>，且每个结点值互异。我们现在完全没看到图，能否画回原树？

第一步只看前序：根一定是 A，因为前序最先访问根。第二步看中序：中序在输出根 A 之前，完整输出其左子树；在 A 之后，完整输出右子树。于是中序可拆为 <code>[D B E] A [C F]</code>，左子树有三个结点，右子树有两个。

第三步回到前序。去掉根 A 后，前序一定先连续列出左子树的全部三个结点，再列出右子树的两个。所以它自然拆成 <code>A [B D E] [C F]</code>。左子树的根是 B；在左子树中序 <code>D B E</code> 里，D 在 B 左边、E 在 B 右边，因此 B 的左右孩子分别为 D、E。右子树前序首项 C 是根，而右子树中序为 <code>C F</code>，C 左边没有任何结点，所以 F 只能位于 C 的右侧。

由此得到上一节的图。**真正决定重建步骤的是“前序给根、中序确定左右子树大小”**。对每棵子树重复这个动作，直到范围为空。

为什么只给前序和后序往往不够？只有两个结点 A、B，前序 AB、后序 BA，可以来自 A 的唯一左孩子 B，也可以来自唯一右孩子 B。两种树遍历结果相同，无法唯一确定。若存在重复结点值，前序+中序也未必能够直接唯一重建，因为中序中“哪一个同名结点是根”可能不唯一。题目应当明确关键码互异或额外提供区分信息。

### 用区间代替切片：完整构造代码

为了将纸笔的“划分左右子树”转成程序，不需要反复复制子数组。只保存当前中序区间 [L,R]、前序的下一未使用位置 pos 即可。每次从 pre[pos] 取根，定位根在中序区间的位置 k，再递归生成左区间和右区间：

~~~cpp
#include <vector>
#include <unordered_map>
#include <stdexcept>

struct BuildNode {
    char value;
    BuildNode *left, *right;
};

BuildNode* buildRec(const std::vector<char>& pre, int& pos,
                    int L, int R,
                    const std::unordered_map<char,int>& where) {
    if (L > R) return nullptr;
    if (pos >= (int)pre.size()) throw std::invalid_argument("bad traversals");
    char value = pre[pos++];
    auto it = where.find(value);
    if (it == where.end() || it->second < L || it->second > R)
        throw std::invalid_argument("inconsistent traversals");
    int k = it->second;
    BuildNode* root = new BuildNode{value, nullptr, nullptr};
    root->left  = buildRec(pre, pos, L, k-1, where);
    root->right = buildRec(pre, pos, k+1, R, where);
    return root;
}

BuildNode* rebuild(const std::vector<char>& pre,
                   const std::vector<char>& in) {
    if (pre.size() != in.size())
        throw std::invalid_argument("length mismatch");
    std::unordered_map<char,int> where;
    for (int i=0;i<(int)in.size();++i)
        if (!where.emplace(in[i],i).second)
            throw std::invalid_argument("duplicate keys");
    int pos=0;
    BuildNode* root=buildRec(pre,pos,0,(int)in.size()-1,where);
    if (pos!=(int)pre.size()) throw std::invalid_argument("extra preorder keys");
    return root;
}
~~~

这是教学版本，假设输入合法时构建成功；异常发生在中途时的已分配结点回收还需要额外的所有权管理。核心时间分析是：前序每个结点只消费一次，用映射平均 O(1) 定位它在中序的位置，因此正常输入下平均时间 O(n)，映射额外空间 O(n) 加递归栈 O(h)。

## 08.6 数组里的 @ 为什么不能直接删掉 {#v4-tree-array}

对完全二叉树按层自左向右编号，如果根下标为 0，下标 i 的左右孩子位置是 2i+1、2i+2，非根的父结点位置是 <code>(i−1)/2</code> 的整数部分。这些公式来自层序编号，在普通二叉树里也能通过**保留缺失位置**来表示形状。

例如数组 <code>[A,B,C,@,D,E,F]</code>。A 在 0，下标 1 和 2 是 B、C；B 的左孩子位置 3 是 @，说明那里没有结点，B 的右孩子位置 4 是 D；C 的左右孩子位置 5、6 为 E、F。因此中序为 <code>B D A E C F</code>。

如果把 @ 从数组中直接删去，D 就会前移到下标 3，被错误解释为 B 的左孩子。更长的作业数组 <code>[A,B,C,D,E,F,G,@,@,H,@,I,J,K,L]</code> 同理必须保留所有占位，才能把 H 放在 E 的左侧，把 I、J 放在 F 的左右两侧。按完整位置图做中序，结果为 <code>D B H E A I F J C K G L</code>。

这类题的实际操作顺序应该是：**先标下标、按 2i+1/2i+2 画边、确认 @ 表示缺失、最后再遍历**。直接盯着数组字符猜序列，很难保证正确。

## 08.7 显式栈与递归遍历到底如何对应 {#v4-tree-stack}

递归中序遍历会沿左孩子不断深入，直到无法再向左；随后访问当前根，再去处理右子树。系统调用栈正是在保存那些“左子树还没处理完、当前结点还没输出”的祖先。如果我们使用自己创建的栈，也可以完成同样的过程。

~~~cpp
#include <stack>
void inorderIter(Node* root) {
    std::stack<Node*> st;
    Node* cur = root;
    while (cur || !st.empty()) {
        while (cur) {
            st.push(cur);      // 暂存尚未输出的祖先
            cur = cur->left;   // 先进入左子树
        }
        cur = st.top();
        st.pop();
        std::cout << cur->value << ' ';
        cur = cur->right;
    }
}
~~~

这里的栈保存的结点不是“都已遍历完成”，恰恰是“左侧尚未彻底处理完，自身还未输出”的祖先。左边走到底时弹出一个祖先、输出它，再去右子树，完整遵守中序。

如果题目要求非递归地把整棵二叉树做**镜像**，我们也可以先把根压栈，每弹出一个结点就交换其 left 和 right，再将仍需处理的孩子压栈。每结点访问一次，时间 Θ(n)，辅助栈空间最坏 O(h)（对二叉树深度优先、恰当压栈顺序而言）。返回值应始终是保存的原树根地址 root，而不是循环中不断改变的临时变量 cur。

## 08.8 章节练习：重建前先说明数据约定 {#v4-tree-exercises}



#### 练习 1｜边数证明与叶数（基础，8 分）

**题目。** 一棵非空二叉树共有 7 个度为 2 的结点，其余结点的度可能为 0 或 1。求叶结点个数，并从父子边计数推导所用公式，不能只引用结论。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 所有结点贡献的孩子边数为 n₁+2n₂；同一棵树的边数也等于总结点数减一。

**解答。** 令 n₀、n₁、n₂ 为对应度数结点数量，有 n₁+2n₂=n₀+n₁+n₂−1，解得 n₀=n₂+1=8。无论 n₁ 是多少，叶子个数都恰为 8。

</details>



#### 练习 2｜数组二叉树的完整中序（作业同级，12 分）

**题目。** 将字符数组 <code>[A,B,C,@,D,E,F]</code> 按 0-based 完全二叉树位置规则解释，其中 @ 表示该位置没有结点，不能删除或左移其他元素。请画出二叉树，并写出前序、中序、后序。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 对下标 1 的 B，其左孩子位置 3 为 @，右孩子位置 4 为 D；下标 2 的 C 有左右孩子 E、F。

**解答。** 树根 A，左 B、右 C；B 仅有右孩子 D，C 左 E、右 F。前序 A B D C E F；中序 B D A E C F；后序 D B E F C A。你可以按各子树分别输出，最后检查根在三种遍历中的位置。

</details>



#### 练习 3｜前序与中序重建（作业同级，12 分）

**题目。** 一棵二叉树所有结点标签互不相同，已知前序序列为 <code>A B D E C F</code>，中序序列为 <code>D B E A C F</code>。请给出每一次左右子树区间划分、画出最终结构，并写出后序与层序。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 前序首项确定 A；中序以 A 分成 [D B E] 与 [C F]，前序剩余的前 3 项属于左子树。

**解答。** A 为根，左子树前序 [B D E]、中序 [D B E]，所以 B 为左子树根，左右孩子 D、E；右子树前序 [C F]、中序 [C F]，所以 C 为根且只有右孩子 F。最终后序 D E B F C A；层序 A B C D E F。把结果树再次遍历，可以恢复题目给出的前序和中序。

</details>



#### 练习 4｜一般树的度数关系（作业同级，10 分）

**题目。** 一棵非空一般树中，度为 1 的结点有 4 个、度为 2 的有 3 个、度为 3 的有 2 个，其余结点都是叶子。求叶子个数、总结点数，并用父子边数验证结果。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 一般树允许度为 3，不能直接套二叉树的 n₀=n₂+1。使用 n₀=1+Σ(k−1)nₖ。

**解答。** n₀=1+(2−1)×3+(3−1)×2=8；总结点数 8+4+3+2=17。所有父子边总数应为 16，从每个结点孩子数求得 1×4+2×3+3×2=16，恰好验证一致。

</details>



#### 练习 5｜非递归镜像中的返回指针（提高，12 分）

**题目。** 定义 <code>Node{char value;Node* left;Node* right;}</code>。要求在不递归的条件下，逐个交换二叉树每个结点的左右孩子，返回仍然指向原树根的地址。请说明需要维护什么栈状态、为什么空树安全，以及为何不能直接返回循环结束时的临时结点 p。

<details class="question"><summary>查看思路与解答</summary>

**思路。** 栈存放尚未处理的结点。每次弹出 p、交换它的两个孩子，再压入仍存在的孩子；root 一直单独保存。

**解答。** 初始化 root 为空则直接返回 nullptr；否则压入 root。循环直到栈空，每轮弹出 p、<code>std::swap(p->left,p->right)</code>，并把其非空孩子压栈。最终返回 root。p 的值随着遍历改变，循环结束时它只是最后处理的某个结点，不一定是根。每个结点访问一次，时间 Θ(n)，栈在这类 DFS 方式下额外空间受树高和分支数量影响，二叉树最坏 O(h)。

</details>

本章知识最终收束到两条主线：树用父子关系表达层次，遍历和重建用不同次序透露结构信息；所有递归与非递归过程都必须知道哪些子树已处理、哪些待处理。只有能从一张图独立推回遍历、再从遍历画回图，才算真正掌握了二叉树。
