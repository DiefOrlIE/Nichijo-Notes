# 第 14 章　AVL 平衡树：旋转究竟为什么能恢复高度

> 来源：《DSA 6-Search Tree》AVL 插入、旋转及删除部分。  
> 前置：BST 插删、树高、递归返回子树根。  
> **约定**：本章使用 <code>bf = 右子树高度 − 左子树高度</code>。许多教材定义相反，题目应明确符号。

## 14.1 普通 BST 不够快，问题出在哪里 {#v4-avl-motivation}

连续插入递增键 10、20、30，普通 BST 会形成单边向右的链，高度增长到 3。虽然满足“左小右大”，每次查找仍可能沿整条链比较。AVL（Adelson-Velsky and Landis tree）在 BST 规则之外增加约束：每个结点左右子树高度之差的绝对值不超过 1。

我们用空子树高度 0、叶结点高度 1。设结点 p 的左高为 HL、右高 HR，定义 bf=HR−HL。bf=0 表示左右同高；bf=+1 表示右边多一层；bf=−1 表示左边多一层；bf=+2 或 −2 表示失衡，需要局部调整。

要注意 bf 是哪个方向的差。若使用相反的教材约定，旋转的几何方向不变，但公式里正负号会颠倒。

## 14.2 旋转之前先画三结点链 {#v4-avl-rotations}

先插入 10、20、30，根 10 的右子树连续加高，是**右右 RR 情况**。我们希望让中间键 20 上升为新根，10 成为其左孩子，30 成为右孩子。执行一次**左旋**即可：

<pre class="diagram">旋转前：   10             旋转后：    20
              \                      /  \
              20                    10  30
                \
                30</pre>

为什么旋转不破坏 BST？因为原来 10<20<30，旋转后仍满足左边小、右边大。对于实际包含子树的情形，旋转还要把中间子树接到合适位置：若 p 右孩子 q，左旋时 q 的左子树 B 变成 p 的右子树，而 q 变成局部新根，p 变成 q 的左孩子。

左左 LL 的情况对称，用右旋。对于“先向左走，再向右走”的 LR，单次右旋不够；先对左孩子做左旋，再对失衡祖先做右旋。RL 则先对右孩子做右旋，再对祖先左旋。

## 14.3 四种插入形态用同一套方向判断 {#v4-avl-four-cases}

把三个关键码的插入顺序分别试一遍：

| 输入次序 | 首次失衡的根 | 从失衡根到新项的两步方向 | 修复 |
|---|---|---|---|
| 30,20,10 | 30 | 左→左（LL） | 右旋 30 |
| 10,20,30 | 10 | 右→右（RR） | 左旋 10 |
| 30,10,20 | 30 | 左→右（LR） | 左旋 10，再右旋 30 |
| 10,30,20 | 10 | 右→左（RL） | 右旋 30，再左旋 10 |

四种情况最后都得到根 20、左孩子 10、右孩子 30。手工题最容易错的是 LR、RL：只记“失衡根左边太高就右旋”，忽略了孩子方向，可能产生仍失衡的结果。

## 14.4 插入后为什么只要从新结点向上检查 {#v4-avl-insert}

新关键码按 BST 规则走到一个空位置插入，只有从插入点到根的祖先路径可能高度变化；与这条路径无关的子树完全没变。递归回溯时更新当前结点高度，若绝对差超过 1，就观察较高孩子是左重还是右重，选择相应的单旋/双旋。

完整代码不仅要执行旋转，还要**把旋转后新的局部根返回给上一层**。若旋转发生在整棵树根，也必须更新外部 root 指针。局部指针关系正确而忘记回接新的根，整个结构仍可能断开。

## 14.5 AVL 删除和插入为什么不完全对称 {#v4-avl-delete-motivation}

插入让某条根到叶路径变长，首次失衡旋转后通常已恢复那一带的原高度，因此不一定继续影响祖先。删除使某条路径变短，旋转后某棵子树的高度可能仍减少，变化就会继续沿父指针传上去，**可能要在多个祖先处重新平衡**。

因此理解 AVL 删除的第一步不是立即记更多旋转组合，而是拿纸笔在每一个祖先写出“删除前左/右高度”“删除后左/右高度”“经过旋转后的新高度”。课堂使用 shorter 标记的实现尤其需要区分“子树高度是否真的少一层”。


### 从“某一边矮了一层”推导删除时何时停止

以本章 bf=右高−左高 为约定。设一次删除使结点 p 的**左子树高度减少 1**。只从 p 旧 bf 与新 bf 的变化便能判断是否继续沿祖先回溯：

| 删除前 p 的 bf | 删除后 bf | p 的总体高度 | 下一步 |
|---:|---:|---|---|
| −1（原来左高 1） | 0 | 整体降低 1 | 继续检查父结点 |
| 0（原来等高） | +1 | 整体高度不变 | 可以停止传播 |
| +1（原来右高 1） | +2 | 暂时失衡 | 必须旋转、再看旋转后高度 |

为什么第一行高度减少？因为旧最大高度来自左子树，左子树变矮后，左右变得一样高，最大高度也跟着下降。为什么第二行可以停止？因为原来的右子树高度仍然保持最大值，整体高度没有变化。第三行里右子树比新的左子树高两层，已经违反 AVL 条件。

右子树变短时做完全对称的分析。需要旋转时，还要查看较高孩子的 bf：若与失衡方向同向，可单旋；若反向，需双旋；若较高孩子 bf=0，则是删除中可以出现的特殊单旋情形，旋转后的高度变化与平常并不完全相同。

### 再检查代码里的两个容易漏掉的回接

~~~cpp
root = avlInsert(root, x);   // 整棵树的根可能因旋转改变
root = avlDelete(root, x);   // 删除后也可能换根
~~~

在结点 p 内部，<code>p->left=avlDelete(p->left,x)</code> 与 <code>p->right=avlDelete(p->right,x)</code> 是相同道理：某棵子树的根在删除/旋转后可能改变，上层必须接住新的子树根。仅更新高度数值，却忘记把“指向子树根的那条父链接”改正确，树结构仍然错误。

## 14.6 具体删除示例：失衡孩子 bf=0 的特殊情况 {#v4-avl-delete-zero}

考虑下面一棵 AVL：根 2，左孩子 1；右子树根 4，左右孩子分别 3、5。删除叶子 1 后，根 2 左高由 1 变 0，右高仍为 2，故 bf(2)=+2；但右孩子 4 的 bf=0。

<pre class="diagram">删除前：       删除 1 后：      在 2 左旋后：
    2               2                4
   / \               \              / \
  1   4               4            2   5
     / \             / \            \
    3   5           3   5            3</pre>

注意这个分支：旋转后新子树高度和删除前一样，所以此次高度缩短没有继续向更高祖先传播。若用 shorter 布尔量维护删除传播，就必须有特别处理。若采用递归回溯逐层重新计算高度，则可以在每一层独立检查是否需要旋转，更不容易漏分支。

## 14.7 一份可以编译的完整 AVL 插删实现 {#v4-avl-code}

下面采用结点自身记录高度的实现，空树高度 0、叶高 1。插入和删除都借助同一函数 rebalance，每次变化后更新高度；双旋时会先平衡较高的孩子。逻辑方向与本章 bf=右高−左高 保持一致：

~~~cpp
#include <algorithm>
struct AvlNode{
    int key,height;
    AvlNode *left,*right;
};
int height(AvlNode* p){return p?p->height:0;}
void update(AvlNode* p){
    p->height=1+std::max(height(p->left),height(p->right));
}
int balance(AvlNode* p){return height(p->right)-height(p->left);}
AvlNode* rotateLeft(AvlNode* p){
    AvlNode* q=p->right;
    p->right=q->left;
    q->left=p;
    update(p);update(q);
    return q;
}
AvlNode* rotateRight(AvlNode* p){
    AvlNode* q=p->left;
    p->left=q->right;
    q->right=p;
    update(p);update(q);
    return q;
}
AvlNode* rebalance(AvlNode* p){
    update(p);
    if(balance(p)==2){
        if(balance(p->right)<0)
            p->right=rotateRight(p->right);
        return rotateLeft(p);
    }
    if(balance(p)==-2){
        if(balance(p->left)>0)
            p->left=rotateLeft(p->left);
        return rotateRight(p);
    }
    return p;
}
AvlNode* avlInsert(AvlNode* p,int key){
    if(!p)return new AvlNode{key,1,nullptr,nullptr};
    if(key<p->key)p->left=avlInsert(p->left,key);
    else if(key>p->key)p->right=avlInsert(p->right,key);
    else return p;
    return rebalance(p);
}
AvlNode* avlDelete(AvlNode* p,int key){
    if(!p)return nullptr;
    if(key<p->key)p->left=avlDelete(p->left,key);
    else if(key>p->key)p->right=avlDelete(p->right,key);
    else{
        if(!p->left || !p->right){
            AvlNode* child=p->left?p->left:p->right;
            delete p;
            return child;
        }
        AvlNode* s=p->right;
        while(s->left)s=s->left;
        p->key=s->key;
        p->right=avlDelete(p->right,s->key);
    }
    return rebalance(p);
}
~~~

需要用 <code>root=avlInsert(root,x)</code>、<code>root=avlDelete(root,x)</code> 接住返回的树根。平衡因子如果是 +2 且右孩子 bf=0，满足上面的单左旋条件；孩子 bf<0 才走 RL 双旋。左侧对称。

## 14.8 如何说明 AVL 的查找性能 {#v4-avl-complexity}

高度始终平衡的 AVL 树不可能像普通 BST 那样变成 n 长单边链。最少结点数满足类似 <code>N(h)=1+N(h−1)+N(h−2)</code> 的增长关系，因此高度 h=O(log n)。沿一条根到叶路径查找、插入和删除需要 O(log n) 时间；旋转本身只改常数条链接，为 O(1)。删除可能在多个祖先旋转，但祖先数也受 O(log n) 约束。

这是一个性质明确的最坏上界，不等于“任何树都必须恰好达到 log₂n 层”，也不表示每次操作都发生旋转。
