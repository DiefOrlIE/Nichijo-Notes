# 第 14 章　AVL 平衡树：当删除和插入改变高度时怎么办

> **来源**：《DSA 6-Search Tree》AVL 部分，覆盖插入、四类旋转及删除。  
> **已学**：BST 的中序有序性、递归返回子树根、树高。  
> **本章约定**：空树高度 0，叶子高度 1，平衡因子 **bf=右子树高度−左子树高度**。部分教材定义相反，考试须以题目为准。  
> **目标**：自己识别 LL、RR、LR、RL；解释旋转如何保序；在删除后沿祖先路径判断高度是否继续变化；读懂完整 C++ 实现。

上一章我们终于做到：在一棵树里根据大小关系查找，并且插删时只改局部链接。但我们留下了一个重大缺口。按 1、2、3、4 的顺序插入时，BST 会退化成一条向右的链，查询最深结点仍要经过所有祖先。我们希望树既保持“左小右大”，又不会因为某些输入顺序长得过高。AVL 树就在 BST 有序性之外，主动维护左右子树的高度差。

## 14.1 为什么要管高度，平衡因子究竟如何计算 {#v4-avl-motivation}

设某个结点左子树高度为 3、右子树高度为 1。它的一侧明显更深。如果树里有很多这样的结点一直朝同一边倾斜，根到叶的路径会变得很长。AVL 要求对**每一个结点**都成立：左右子树高度差的绝对值最多为 1。

本章定义 <code>bf(p)=height(p->right)−height(p->left)</code>。因此 bf=0 表示左右同高，bf=+1 表示右侧高一层，bf=−1 表示左侧高一层；bf=+2 或 −2 就代表该结点失衡。千万不要只检查根：一棵树的根可能左右高度接近，但某棵子树内部仍然严重失衡。

高度按“空树为 0、叶子为 1”的约定计算。譬如单结点 A 的左右都为空，高度 1、bf=0；若 A 有一个右孩子 B，则 A 左高 0、右高 1，bf=+1，仍合法；若继续在 B 的右边插 C，根 A 的右子树高 2、左高 0，bf=+2，才出现需要修复的情况。

为什么限制高度能改善查找？因为 AVL 无法形成 n 项长链：如果一个结点某侧很深，另一侧不能相差超过一层。满足这个条件的树高随结点数按 O(log n) 增长，沿根到叶查找的最坏时间就保持 O(log n)。

## 14.2 旋转前先看三项的相对大小 {#v4-avl-rotations}

从空树依次插入 10、20、30，普通 BST 会形成 10→20→30 的连续右链。根 10 的 bf=+2，右侧太高。我们想让中间键 20 升为局部根，较小的 10 放左侧，较大的 30 放右侧，这样树高便从三层降为两层。

这种局部改变称为**左旋**。右边较高的孩子 q 上升为新根，原结点 p 成为 q 的左孩子；如果 q 原本还有左子树 B，那么 B 必须成为 p 的右子树，才能继续保持 <code>p<B<q</code> 的整体大小次序。

<pre class="diagram">左旋前：          左旋后：
     p               q
    / \             / \
   A   q           p   C
      / \         / \
     B   C       A   B</pre>

这里的 A、B、C 代表三棵可能为空的子树，并不是单独三个值。左旋的关键顺序是先让 <code>p->right=q->left</code>，再让 <code>q->left=p</code>，最后重新计算 p、q 的高度。若只修改 p 和 q 的关系而丢掉 B，虽然局部画图似乎成功，却会损失整棵子树。

右旋完全对称：左侧较高的孩子上升，原结点下降到其右侧。旋转改变局部父子关系，却不会改变中序序列，因此能够恢复高度而保持 BST 有序性。

## 14.3 为什么有时候需要连续两次旋转 {#v4-avl-four-cases}

现在分别插入三组关键码：

- 30、20、10：新值沿“左、左”路径进入，使 30 左重，这是 LL 型，对 30 **右旋**；
- 10、20、30：新值沿“右、右”路径进入，使 10 右重，这是 RR 型，对 10 **左旋**；
- 30、10、20：新值在左孩子 10 的右侧，形成“左、右”路径，这是 LR 型，先对 10 **左旋**，再对 30 **右旋**；
- 10、30、20：新值在右孩子 30 的左侧，形成“右、左”路径，这是 RL 型，先对 30 **右旋**，再对 10 **左旋**。

为什么 LR 不能直接对根右旋？以 30、10、20 为例，若只把 10 提到根，20 仍在 30 的左侧，根 10 的右子树可能继续比左子树深很多。正确做法先把“折角”中的 20 提到左子树顶部，再做一次右旋，使中间键 20 取代原失衡根。四种输入最后都会得到根 20、左 10、右 30。

判断类型时不要只看 bf 的正负。它告诉你**哪一侧太高**，但还要检查较高孩子自身往哪侧倾斜。正因如此，LR、RL 的判断涉及两层关系。

| 新结点进入路径 | 类型 | 恢复方法 |
|---|---|---|
| 左→左 | LL | 对失衡根右旋 |
| 右→右 | RR | 对失衡根左旋 |
| 左→右 | LR | 先对左孩子左旋，再对根右旋 |
| 右→左 | RL | 先对右孩子右旋，再对根左旋 |

## 14.4 插入为何只需沿新结点的祖先检查 {#v4-avl-insert}

在 AVL 树中插入一个新键，第一步仍完全按照 BST 的大小比较规则走到空孩子位置。新增结点只可能增加**它所在的那条根到叶路径**的高度；所有与这条路径无关的子树都没有改变，原来的平衡状态仍成立。

所以可以用递归插入，在函数返回过程中沿祖先逐层更新高度，再计算平衡因子。若当前结点 bf 在 −1 到 +1 之间，保持原结构；若 bf=+2 或 −2，就根据较高孩子的方向执行单旋或双旋。最关键的一点是：每次旋转都有一个新的**局部子树根**，上一层调用必须接住这个返回值。

例如插入 30、10、20 时，最后一次插入使子树根 30 改为 20。若函数只在内部交换了几个 next 指针，却让外部仍把根指向 30，调用者就拿不到完整的新树。写调用代码时应使用 <code>root=avlInsert(root,x)</code>，左右递归分支内部同样要执行 <code>p->left=...</code> 或 <code>p->right=...</code> 接回子树。

## 14.5 删除以后为什么可能需要检查多个祖先 {#v4-avl-delete-motivation}

AVL 删除的第一部分仍是普通 BST 删除：找到要删除的键，按零个、一个或两个孩子分类；两个孩子时可使用中序后继替换，再删除后继原结点。真正新增的难点是：删去结点以后，某个子树的**高度可能降低一层**。

插入使某条路径变长，首次失衡旋转后常常能恢复到插入前的子树高度；删除则不同。某层旋转虽然恢复了它自己的 AVL 条件，整棵子树高度仍可能比删除前低一层，于是上一层的高度关系也会变化，可能继续失衡。因此不能简单规定“找到一个失衡点、旋一次后就必定停止”。

我们先不记旋转分支，而用一个表说明删除后高度到底何时变化。假设删除发生在 p 的**左子树**，使左高减少 1；本章 bf=右高−左高：

| 删除前 bf | 删除后 bf | 当前结点整体高度的变化 | 下一步 |
|---:|---:|---|---|
| −1 | 0 | 原较高的左侧变矮，整体高度减少 1 | 继续向上检查 |
| 0 | +1 | 右侧保持原来的最大高度，整体高度不变 | 可以停止高度传播 |
| +1 | +2 | 右侧比新左侧高两层，局部失衡 | 必须旋转，判断旋后高度 |

这里每个结论都来自“最大高度由哪一侧决定”。当 bf 从 0 变成 +1，较高侧始终还是原右子树，所以整体高度没有下降；当 bf 从 −1 变成 0，原较高左侧被削短，整体高度才下降。若删除发生在右侧，则符号和方向对称。

理解这张表以后，再看 AVL 删除中的 <code>shorter</code> 标记或递归更新高度，你就知道它们究竟在追踪什么：**当前子树比删除之前是否矮了一层**。

## 14.6 右孩子平衡因子为 0：删除才有的特殊单旋 {#v4-avl-delete-zero}

考虑下图。原来根为 2，左孩子为 1，右子树根为 4，而 4 的左右孩子分别是 3、5。这棵树完全平衡。

<pre class="diagram">删除前：         删除 1 后：        对 2 左旋后：
     2                2                  4
    / \                \                / \
   1   4                4              2   5
      / \              / \              \
     3   5            3   5              3</pre>

删除 1 后，根 2 的左高变成 0，右高仍为 2，所以 bf(2)=+2，失衡。此时它的右孩子 4 的左右子树高度相同，bf(4)=0。按删除规则，我们对 2 做一次左旋，便得到新根 4，左子树根 2、其右孩子 3，右孩子 5。

为什么这个例子特殊？旋转后整棵局部子树的高度仍是 3，与删除前一样，因此高度变短的信息不需要继续向更高祖先传播。若在代码里只写“右孩子 bf>0 才单左旋，其他情况双旋”，就会错误地把 bf=0 分入 RL 分支。正确的右重分支是：右孩子 bf<0 才先右旋孩子，bf≥0（含 0）可以直接左旋。

这一点往往是 AVL 删除比插入更难的来源：删除可能使失衡祖先的较高孩子恰好左右同高，需要专门考虑旋转后的高度。

## 14.7 把旋转、插入与删除写成同一套实现 {#v4-avl-code}

下面的实现把每个结点的高度直接存下来，因此不需要额外通过布尔标记把 shorter 一层一层传递。每次从递归返回时更新高度、判断当前 bf，并在必要时旋转。请阅读时重点看每个函数**返回的指针是谁**。

~~~cpp
#include <algorithm>

struct AvlNode {
    int key, height;
    AvlNode *left, *right;
};

int height(AvlNode* p) {
    return p ? p->height : 0;
}
void update(AvlNode* p) {
    p->height = 1 + std::max(height(p->left),height(p->right));
}
int balance(AvlNode* p) {
    return height(p->right) - height(p->left);
}
AvlNode* rotateLeft(AvlNode* p) {
    AvlNode* q = p->right;
    p->right = q->left;  // B 子树回接到 p 右侧
    q->left = p;
    update(p);
    update(q);
    return q;            // q 成为新局部根
}
AvlNode* rotateRight(AvlNode* p) {
    AvlNode* q = p->left;
    p->left = q->right;
    q->right = p;
    update(p);
    update(q);
    return q;
}
AvlNode* rebalance(AvlNode* p) {
    update(p);
    if (balance(p) == 2) {
        if (balance(p->right) < 0)
            p->right = rotateRight(p->right);
        return rotateLeft(p);
    }
    if (balance(p) == -2) {
        if (balance(p->left) > 0)
            p->left = rotateLeft(p->left);
        return rotateRight(p);
    }
    return p;
}
AvlNode* avlInsert(AvlNode* p,int key) {
    if (!p) return new AvlNode{key,1,nullptr,nullptr};
    if (key < p->key)
        p->left=avlInsert(p->left,key);
    else if (key > p->key)
        p->right=avlInsert(p->right,key);
    else
        return p;  // 本实现不插入重复键
    return rebalance(p);
}
AvlNode* avlDelete(AvlNode* p,int key) {
    if (!p) return nullptr;
    if (key < p->key) {
        p->left=avlDelete(p->left,key);
    } else if (key > p->key) {
        p->right=avlDelete(p->right,key);
    } else {
        if (!p->left || !p->right) {
            AvlNode* child=p->left ? p->left : p->right;
            delete p;
            return child;
        }
        AvlNode* next=p->right;
        while (next->left) next=next->left;
        p->key=next->key;
        p->right=avlDelete(p->right,next->key);
    }
    return rebalance(p);
}
~~~

代码中的 <code>rotateLeft</code> 与 <code>rotateRight</code> 总是先修改链接，再更新高度，因为更新高度必须读取旋转后的孩子关系。<code>rebalance</code> 在当前局部根失衡时返回新的根；<code>avlInsert</code> 与 <code>avlDelete</code> 都要把它返回给上层。调用者再将返回值赋给整个 root。

若删除目标不存在，递归到空结点后不发生变化；若目标有零个或一个孩子，删除结点后返回相应孩子；如果两个孩子，复制后继关键码并继续从右子树删除后继，最终沿递归返回路径逐层重新平衡。全过程保留 BST 的中序有序性和 AVL 的高度限制。

## 14.8 平衡为什么能保证 O(log n) 高度 {#v4-avl-complexity}

普通 BST 允许一直单边增长，最坏高度 Θ(n)。AVL 要求每结点的左右子树高度差不超过 1，这使得要获得一棵高度很高的 AVL，至少需要相当多的结点。

设 N(h) 为高度为 h 的 AVL 至少需要多少结点。要让高度达到 h，一侧至少高度 h−1，另一侧为了仍满足平衡至少高度 h−2，再加根，所以有类似 <code>N(h)=1+N(h−1)+N(h−2)</code> 的递推。它随着 h 以指数速度增长，反过来说明若只有 n 个结点，h 最多 O(log n)。

BST 查找、插入的定位阶段沿根到叶路径，故在 AVL 上为 O(log n)。删除后可能沿多个祖先检查甚至旋转，但祖先数量最多 O(log n)；每次局部旋转只修改常数条链接，所以插入、删除的最坏时间仍为 O(log n)。

这里的 O(log n) 是最坏渐进上界，并不意味着每一次操作都恰好走 log₂n 层，也不意味着每次插入删除都一定旋转。

**提示。** 先算 1−3，再检查绝对值是否超过 1。

**解答。** bf=−2，左侧高两层，当前结点失衡。要决定单右旋还是 LR 双旋，还必须查看左孩子自己的左右高度关系。仅凭当前结点左重，不足以判定唯一旋转。

</details>



<h4 class="exercise-title">练习 2｜三结点 LR 插入（作业同级，12 分）</h4>

**题目。** 从空 AVL 依次插入互异关键码 30、10、20。采用 bf=右高−左高，写出插入 20 后的失衡根、路径方向、需要的两次旋转及最终树形。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 20 位于根 30 的左孩子 10 的右侧，路径为左→右。

**解答。** 首次失衡的是结点 30，属于 LR 型。先对左孩子 10 左旋，使 20 位于左子树顶部；再对结点 30 右旋。最终根为 20，左孩子 10、右孩子 30，所有结点 bf 均为 0，满足 BST 中序 10、20、30。

</details>



<h4 class="exercise-title">练习 3｜RL 删除分支（作业同级，12 分）</h4>

**题目。** 在一次 AVL 删除后，某祖先 p 的平衡因子变成 +2，其右孩子 q 的平衡因子是 −1。已知所有高度按本章约定计算。请判断旋转类型、执行顺序以及每次旋转返回的局部根应如何连接父结点。

<details class="question"><summary>查看思路与解答</summary>

**提示。** p 右侧太高，而右孩子又向左倾斜，因此先修复右孩子的折角。

**解答。** 类型为 RL，先对 q 右旋，再对 p 左旋。第一步返回的新右子树根要赋给 <code>p->right</code>；第二步左旋返回新的局部根，上层必须用它替换原来指向 p 的链接。旋转后重新计算高度并继续检查祖先。

</details>



<h4 class="exercise-title">练习 4｜删除时孩子 bf=0（作业同级，14 分）</h4>

**题目。** 初始 AVL 的根为 2，左孩子 1，右孩子 4；4 的左右孩子分别为 3、5，其他孩子均为空。删除关键码 1 后，计算结点 2 和 4 的平衡因子、给出旋转类型及最终树形；解释为什么这是删除中的特殊情况。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 删除 1 后，根 2 左高变 0、右高仍 2；右孩子 4 左右同高。

**解答。** bf(2)=+2，bf(4)=0。对根 2 单左旋，得到新根 4、左孩子 2（其右孩子 3）、右孩子 5。旋转后的局部子树高度为 3，与删除前一样，因此不继续向父亲传播高度减少信息（如果它还有父亲）。不能因为 q 的 bf=0 就误判为 RL 双旋。

</details>



<h4 class="exercise-title">练习 5｜删除高度传播的三种状态（提高，12 分）</h4>

**题目。** AVL 中结点 p 的左子树因删除一个结点而高度下降 1，右子树高度不变。分别讨论删除前 p 的 bf 为 −1、0、+1 时，删除后的 bf、当前子树整体高度是否下降，以及是否应继续向父结点传播高度变化。采用 bf=右高−左高。

<details class="question"><summary>查看思路与解答</summary>

**提示。** 判断删除前哪一侧决定整个子树的最大高度。

**解答。** 旧 bf=−1：原左侧高，下降后两侧等高，bf→0，整体高度下降 1，应继续检查父结点。旧 bf=0：两侧原等高，左侧下降后右侧高 1，bf→+1，整体最大高度仍由右侧维持，不需要继续传播。旧 bf=+1：原右侧高 1，左侧再下降会得 bf→+2，必须旋转；旋转后的高度是否下降需根据较高孩子的 bf 再判断，不能预先一概而论。

</details>

本章最终应该留下四个可独立回答的问题：BST 的大小约束靠什么保持？AVL 的高度约束额外限制了什么？一次旋转为什么不破坏中序顺序？删除时为什么某层恢复平衡以后仍可能影响更高祖先？能够解释这四件事，比单纯背下 LL、RR、LR、RL 四个名称更可靠。
