先完成正文算例，再用本章对照原作业。这里保留旧稿中有效的结果表作为复查材料，不能跳过前面的首次教学。涉及有符号回绕的项目采用32位机器模型。


## 题 34：原式与完整推理对照

先按题设把算术视为 32 位补码回绕、右移视为算术右移。下表保持教材中 x>y 的方向，以及第 8 项右侧 y−x 的次序。涉及有符号溢出、负数左移的项，在标准 C11/C17 中还须标明语言边界。

| 题项与表达式 | 判断与推理 |
|---|---|
| 1 · (x*x)≥0 | 假；x=46341，数学平方2147488281，低32位解读为−2147479015。 |
| 2 · (x−1<0) \|\| x>0 | 假；x=INT_MIN，x−1回绕为INT_MAX，两个条件均假。 |
| 3 · x<0 \|\| −x≤0 | 真；负x由左项保证，非负x的负数≤0。 |
| 4 · x>0 \|\| −x≥0 | 假；x=INT_MIN，机器取负仍为INT_MIN。 |
| 5 · x&0xF !=15 \|\| (x<<28)<0 | 按原印刷优先级假；!=优先于&，取x=0。若第一项补为(x&0xF)!=15，则机器模型下真：低四位非全1时左项真，全1时左移后最高位为1。 |
| 6 · (x>y)==(−x<−y) | 假；x=INT_MIN、y=0，左假右真。若取负可表示，负号会反转严格不等号。 |
| 7 · ~x+~y == ~(x+y) | 假；~x≡−x−1，两边差1；x=y=0时−2≠−1。 |
| 8 · (int)(ux−uy)==(y−x) | 假；x=1、y=0时1≠−1。左边对应x−y，顺序与右边相反。 |
| 9 · ((x>>2)<<2)≤x | 真；清低两位得4·floor(x/4)，不大于x；负数也向下取整。 |
| 10 · x*4+y*8 == (x<<2)+(y<<3) | 真；两边是相同的模2³²乘加运算。 |
| 11 · x/4+y/8 == (x>>2)+(y>>3) | 假；x=−1、y=0，除法向零得0，算术右移得−1。 |
| 12 · x*y == ux*uy | 真；位串乘积低32位相同，比较时左边转换为unsigned。 |
| 13 · x+y == ux+uy | 真；低32位相同，比较时左边转换为unsigned。 |
| 14 · x*~y+ux*uy == −x | 真；统一到模2³²，~y+y≡−1，提取x得−x。 |

## 题 10：x86-64/Linux 的对应转换

题设 x 在 RAX/EAX/AX/AL，ptr 在 RDX。始终通过 (%rdx) 使用完整指针，写入字节数按目标类型决定。

| src_type | dst_type | 一组可行指令 |
|---|---|---|
| char | long | movsbq %al,%rcx
movq %rcx,(%rdx) |
| int | char | movb %al,(%rdx) |
| int | unsigned long | movslq %eax,%rcx
movq %rcx,(%rdx) |
| short | int | movswl %ax,%ecx
movl %ecx,(%rdx) |
| unsigned char | unsigned | movzbl %al,%ecx
movl %ecx,(%rdx) |
| char | unsigned long | movsbq %al,%rcx
movq %rcx,(%rdx) |
| unsigned long | int | movl %eax,(%rdx) |

特别检查 int→unsigned long：负 int 按模 2⁶⁴ 转换，故使用 movslq 。如果源类型改为 unsigned int，则 movl %eax,%ecx 自动清 RCX 高 32 位，实现零扩展。最后一项只写低 32 位；超范围 unsigned long 转 int 在 C11/C17 中为实现定义，本题按 x86/GCC 的低位截断约定处理。可移植代码若需要带符号 char，应明确写 signed char。

## 题 4：汇编合法性逐条排查

依次检查：名称存在→数据宽度一致→目的操作数可写→显式内存操作数数量→寻址格式→立即数字段能否容纳。普通 mov/add/or 等双操作数指令不能同时显式访问两个内存操作数。下表针对普通整数指令，串指令另有隐式内存规则。

| 原指令 | 问题与修正方向 |
|---|---|
| movl 0xFF,(%eax) | 0xFF 没有 $，表示绝对内存地址，形成内存→内存。若意图为常量，写 $0xFF。 |
| movb %ax,12(%ebp) | AX 为 16 位，与 b 后缀不一致；改 AL 或改用 w，取决于需求。 |
| addl %ecx,$0xF0 | 立即数不能作为目的操作数。 |
| orw $0xFFFF0,(%ebx) | 20 位立即数超出 16 位字段；GNU as 会警告并截成 FFF0，应明确预期值/宽度。 |
| addb $0xF8,(%dl) | DL 为 8 位数据寄存器，不能用于地址；按模式使用 EDX 或 RDX。 |
| movl %bx,%eax | BX 为 16 位；扩大值使用 movswl 或 movzwl，源有符号性决定选择。 |
| andl %esi,%esx | ESX 不存在；核对寄存器名称。 |
| movq 8(%ebp,,4),%rax | 给了比例因子却没有变址寄存器；改 8(%ebp) 或补上合法索引。64 位模式中 q 数据配 32 位地址寄存器本身可通过地址大小前缀实现。 |
| leaq 20(%rdi,%rsi),%eax | q 的目的应为 RAX；若只需低 32 位地址结果，写 leal …,%eax。省略比例因子表示 1。 |

这里区分语法错误与汇编器警告：题目要求找“不正确”写法，包含容易被截断而改变意图的常量。GNU as 实测超宽 orw 会产生警告并继续汇编；不能据此宣称所有汇编器都必然拒绝它。地址宽度与数据宽度分别检查。

## 题 7：独立执行、局部写入与标志

每条指令都从同一组初始数据开始，逐行重置；本题不把上一行结果带进下一行。 先算有效地址，再按后缀取 1/2/4 字节，做定宽运算，最后记录实际写入位置与已定义标志。初始标志未给出时，保持 CF 应写“原 CF”，未定义标志写“未定义”。

初始 EAX=08049300  EBX=00000100  ECX=00000010  EDX=00000080
内存 08049300: FFFFFFF0   08049400: 80000008
     08049384: 807FFF00   08049380: 908F12A8

| 指令 | 地址／运算与写入结果 | CF / OF / SF / ZF |
|---|---|---|
| addl (%eax),%edx | 80+FFFFFFF0→EDX=00000070 | 1 / 0 / 0 / 0 |
| subl (%eax,%ebx),%ecx | 地址08049400；10−80000008→ECX=80000008 | 1 / 1 / 1 / 0 |
| orw 4(%eax,%ecx,8),%bx | 地址08049384；低16位FF00，BX=0100；EBX=0000FF00 | 0 / 0 / 1 / 0 |
| testb $0x80,%dl | 80 AND 80=80，寄存器与内存均保持原值 | 0 / 0 / 1 / 0 |
| imull $32,(%eax,%edx),%ecx | 地址08049380；908F12A8×32，ECX=11E25500 | 1 / 1 / 未定义 / 未定义 |
| mulw %bx | AX=9300，BX=0100；DX:AX=0093:0000；EAX=08040000，EDX=00000093 | 1 / 1 / 未定义 / 未定义 |
| decw %cx | CX=0010→000F；ECX=0000000F | 原 CF / 0 / 0 / 0 |

第三行只读 16 位：内存的完整 32 位值是 807FFF00，小端起始两字节为 00 FF，所以读取 FF00。写 BX 保留 EBX 高 16 位。第六行为隐式 AX×BX→DX:AX，地址值 EAX 的低 16 位恰好也是 AX；必须按寄存器视图取数。IMUL 的 CF/OF 检查完整有符号乘积是否超出目标宽度，MUL 则检查高半是否为 0。

## 浮点判断的来源约束

这里dx、dy、dz来自32位int的精确double转换。不能另取超出int来源的巨大数作为初始反例。两项或三项和都在53位精度范围内，因此加法结合律在这道受限题中成立；乘法无此保证。

| 表达式（dx=(double)x 等） | 判断与理由 |
|---|---|
| dx*dx ≥ 0 | 真；有限范围，不会平方上溢 |
| (double)(float)x == dx | 假；x=2²⁴+1 |
| dx+dy == (double)(x+y) | 机器回绕模型下假；INT_MAX+1。标准 C 中右侧先溢出，表达式无定义 |
| (dx+dy)+dz == dx+(dy+dz) | 真；最多三个 32 位整数的和，精确可表示 |
| dx*dy*dz == dz*dy*dx | 假；乘积可能超出 53 位有效精度 |
| dx/dx == dy/dy | 假；x=0、y=1，左侧 0/0 为 NaN，比较为假 |


乘法的有效反例取x=1818339828、y=1765447924、z=1657142324。每次运算按binary64最近取偶舍入时，(dx×dy)×dz与(dz×dy)×dx之差为2⁴⁰。前一个中间乘积已经舍入，扩宽或交换后面的乘法无法恢复其误差。核验脚本分别重算两种顺序。

## 交换与别名：先看每条赋值的新状态

教材题13的三步为`*y=*x ^ *y; *x=*x ^ *y; *y=*x ^ *y;`。取不同对象x=5、y=3，第一步y=5 XOR 3=6，第二步x=5 XOR 6=3，第三步y=3 XOR 6=5，完成交换。每行都用刚更新的状态。若两个指针指同一个对象，第一步把它与自身异或，立即清零，之后无法恢复。因此题14对奇数长度数组执行到左右索引相等时，会将中间对象清零；用left<right停止便避开自身交换。

## 移位除法题的印刷前提

教材题21所给`if(y<0) y+3;`只计算表达式，没有把值存回y。若意图实现负数向零除4，应修为`y+=3`。例如−1：原句后仍−1，算术右移两位仍−1；修正后得到2，右移为0，与−1/4一致。题设另一路(x<<4)−x对应15x。答题先注明修正前提，再写M=15、N=4。

## 自行核对新题

1. 两个指针分别指向值9与12，执行同样三句交换，每句后的值是什么？
2. 从地址100起字节为58 FE FF FF，按32位补码读成多少？
3. 用上述类型转换表的步骤，将unsigned short的65535写到int目标；再将signed short的−1写到unsigned int目标。

解答一：第一句(9,5)，第二句(12,5)，第三句(12,9)。核对异或9 XOR 12=5。

解答二：按小端重组FFFFFE58，无符号4294966872，减2³²得−424。十六进制写出的高位字节顺序与内存表相反。

解答三：第一种源AX=FFFF、零扩展得到0000FFFF，再写四字节。第二种同样源位串FFFF，但符号扩展得到FFFFFFFF，再写四字节，unsigned读为4294967295。位串相同而源类型不同，决定了不同扩展。
