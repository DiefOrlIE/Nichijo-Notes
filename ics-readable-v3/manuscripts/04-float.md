# 浮点表示、运算与字符编码

先修：二进制权重、补码、类型与宽度。本章任务是把13.625编码为单精度浮点数，再从编码恢复原值，并解释为何某些实数运算规律会失效。

## 小数位也有位置价值

十进制小数点右边的第一位值十分之一；二进制对应二分之一，后续依次四分之一、八分之一。因此`0.101₂=1/2+0/4+1/8=0.625`。十进制13可拆成8+4+1，即1101。合起来13.625=`1101.101₂`。

要反向把一个小数变成二进制，可以反复乘2，依次记录整数部分，再对剩余小数继续。0.625乘2得1.25，记录1，余0.25；乘2得0.5，记录0；再乘2得1，记录1，余0，停止。整数部分则可以不断除2记余数，逆序读取。用按权展开检查结果。

把小数点固定在某一位置叫定点。例如八位补码整数编码再统一除128，C0先读为−64，最后值为−0.5。范围也整体缩放为−1到127/128。若既要极小数又要极大数，一个固定位置会浪费许多格子。

科学计数法允许另存小数点位置。13.625可以写成`1.101101₂×2³`：小数点左移三格，同时乘8补回原值。把非零二进制数整理成1.xxx乘2的整数次幂，称为规格化。

## 实际拆装一次binary32

IEEE是Institute of Electrical and Electronics Engineers，电气与电子工程师协会；IEEE 754规定了本课浮点格式及运算规则。binary32通常对应float，32位分成符号1位、阶码8位、尾数字段23位。符号s决定正负；存储阶码E用于恢复指数；尾数字段F记录小数部分，其整数值除2²³便是小数f。

普通规格化值采用`(−1)^s × (1+f) × 2^(E−127)`。偏置127使负指数也能用无符号阶码字段记录。开头的1已由规格化保证，因此不用另外存储，叫隐含的首位1。

现在编码13.625。它为正，s=0。指数为3，故E=3+127=130，八位写为10000010。小数部分为101101，后面补0直到23位。三个字段连起来为`0 10000010 10110100000000000000000`。从左按四位分组，得到`0x415A0000`。

解码检查：取符号0，指数130−127=3；小数101101对应1/2+1/8+1/16+1/64=0.703125。有效数1.703125乘8=13.625。用解码反查字段，可以发现指数多加一或小数点移动错误。

## 特殊阶码为什么要单独分支

八位阶码全0时不再套用刚才的隐含1。此时值为`(−1)^s × f × 2^(1−127)`，称非规格化数。指数固定为−126，尾数首位为0，能在接近0时逐渐变小。最小正非规格化值由F=1得到2⁻¹⁴⁹。F也为0时是正零或负零。

阶码全1，即255时，F=0表示正负无穷；F非0表示NaN，英文Not a Number，非数。它可表示无效运算结果。NaN与自身相等的比较也为假。解码时先查阶码属于0、1至254、255的哪一类，再选公式。

binary64通常对应double：符号1位、阶码11位、尾数52位，偏置1023，普通数共有53位有效二进制精度。binary32普通数有24位有效精度。指数范围决定能表示多大，尾数精度决定附近两个可表示数相隔多远，两者不可混为一谈。

### 教材第二章题2(4)、2(5)：范围、精度与规格化（转述）

题目：总位数和基数确定后，哪些字段控制浮点范围与精度？为什么规格化，需要哪两种调整？

提示：分别观察一个数的小数点移动能力与相邻可表示数的间隔。

解答：阶码位数主要控制指数范围，有效数位数主要控制精度。在固定总位数内增加阶码会挤占有效数，扩大范围可能牺牲精度。规格化让非零有效数按统一形式充分利用位数。有效数绝对值过小时左移小数点、指数减小，称左规；加法产生多余高位时右移小数点、指数增大，称右规。必须同步修改指数，保持真值。

### 教材第二章题9(6)、10(5)、10(6)：双向浮点转换（原题数据）

题目：写double b=10.5的机器数；解读float位串C4480000及double位串C024800000000000。

提示：先查符号与阶码类别。double的分数52位，偏置1023，不能使用float的23位和127。

解答：10.5=1010.1₂=1.0101₂×2³。double符号0、阶码1026=0x402，分数对应.0101，合成4025000000000000。C4480000为负、float阶码136，实际指数9，分数.1001₂，有效数1.5625，值−1.5625×512=−800。C024800000000000为负、double阶码1026，分数.01001₂，有效数1.28125，值−1.28125×8=−10.25。最后用绝对值重新规格化检查尾数。

## 舍入怎样破坏结合律

在2²⁴附近，binary32相邻可表示整数间隔为2。整数16777217夹在16777216与16777218之间，无法精确记录。默认“最近、平局取偶”舍入会选前者，因为前者的保留最低有效位为偶数位值0。

因此，在每步均按binary32舍入的模型中，令a=16777216、b=1、c=−16777216。先算a+b会舍回a，再加c得0；先算b+c可精确得到−16777215，再加a得到1。相同数学表达式因括号改变中间舍入，结果不同。

浮点加法可理解为先对齐指数、有效数相加、重新规格化、最后舍入。13.625+0.125时，后者写为0.000001×2³，与前者同指数相加，得到1.101110×2³=13.75。位数有限时，对阶过程可能丢弃低位。浮点乘法则有效数相乘、指数相加，再规格化和舍入。

32位int全部能被binary64精确表示，因为53位精度足够；binary32只能保证连续整数区间−2²⁴到2²⁴内精确。把float扩成double可以保存已有的float值，无法找回此前丢掉的信息。浮点转整数会丢小数部分、向零截断；越过目标整数范围时不能假定得到某个固定值。

## 字符同样需要约定

位串也能代表文字。ASCII是American Standard Code for Information Interchange，美国信息交换标准代码，使用七位编码常见拉丁字符，例如'A'的代码为65，即41H。Unicode给字符分配码点，UTF-8是Unicode Transformation Format—8-bit，八位Unicode转换格式，把码点编码成可变长度字节序列。字符数、字节数与屏幕字形数可能不同；strlen计算终止零之前的字节数。文本编码决定字节如何解释，字形由字体提供。

### 教材第二章题11(1)：ASCII字节串（原题数据）

题目：字节68 65 6C 6C 6F 2C 77 6F 72 6C 64 0A 00按ASCII解释为哪段字符串？

提示：先逐字节查字符，最后区分换行与结束零。它们都会占字节，但终止零不属于strlen长度。

解答：前五字节为hello，2C为逗号，随后五字节为world，0A是换行，00为字符串终止符。因此内容为hello,world后跟换行，strlen为12，包含终止零的存储共13字节。这里原题逗号后没有空格，不能凭习惯添上。

### 教材第二章题2(6)：输入码、内码与字形（转述）

题目：为什么处理汉字会涉及不同编码？举例区分输入、内部表示和显示信息。

解答：拼音等输入码帮助人输入字符，内码约定字符在系统中的表示，字模码描述显示时的点阵等字形信息。用户输入的拼音写法与系统处理的字符标识是不同层次；机内最终都需要编码为位串。一个16×16单色点阵需32字节，不代表该汉字在文本中也占32字节。

## 练习

题一：编码普通binary32的−0.75。

提示：先把0.75写成二进制，再规格化；负号只影响符号字段。

解答：0.75=0.11₂=1.1₂×2⁻¹。s=1，E=126，F的第一位1、其余0。编码BF400000。反查(−1)×1.5×1/2=−0.75。

题二：某binary32字段E=0、F=1，可以用隐含首位1吗？

解答：先识别为非规格化数，首位0，值为2⁻²³×2⁻¹²⁶=2⁻¹⁴⁹。误用普通公式会失去逐渐下溢的意义。

题三：把一个很大的float数先转double，再减去原float值，能恢复原来被舍掉的1吗？

解答：不能。转换只保留当前已存的值，丢掉的信息没有另存。应从运算开始就选择足够精度；即使double也有自身有限精度，不能把扩宽等同于无限精确。

## 更仔细地完成一次浮点相减

计算0.5+(−0.4375)。先分别写0.5=1.000₂×2⁻¹，0.4375=1.110₂×2⁻²。两数指数不同，若直接把两个有效数相减会错。把第二数改写成0.111₂×2⁻¹后，有效数相减1.000−0.111=0.001，指数暂时仍−1。最后0.001×2⁻¹=1.000×2⁻⁴=0.0625。小数点向右移三格，需要把指数再减3，保持数值。

实际有效位有限，右移对阶时要记录被移出的信息。额外保留最靠近结果的一些位，再用粘滞位记录更低位是否出现过1，可帮助区分“小于半个间隔、恰好一半、大于一半”。默认最近取偶时，恰好一半检查保留结果最低位：若为1则进位使其成为偶数，若为0则保持。其余舍入方向包括向零、向正无穷和向负无穷。对负数，“向正无穷”表示更接近零的方向，不能按“加绝对值”理解。

例如某简化格式只保留四位有效数，1.011100…在1.011和1.100正中，选择1.100，其保留末位0。1.010100…在1.010和1.011正中，选择1.010。先找到上下相邻可表示值，再判断中点，比背“看到5就进”更可靠。

在默认IEEE浮点异常处理模型下，有限非零数除正零通常产生带符号无穷并设置相应异常状态，零除零产生NaN；这与整数除零的处理不同。不能把某种语言运行时抛异常或某次配置的表现推广到全部硬件模式。

## 存储单位与中文编码补充

一字节八位。容量若按二进制计算，1 KiB=1024字节，1 MiB=1024 KiB；十进制1 kB=1000字节。课件写KB时沿用传统1024口径，跨资料比较应先确认单位。每秒八百万bit的数据量若忽略协议开销，对应每秒一百万byte，bit和byte差八倍。

早期汉字标准常以区号、位号定位字符。例如GB 2312使用94×94的区位组织，区位数、标准交换编码和某些环境中的机内编码有各自变换约定。按常见教学规则，区位的两个十进制数分别加0x20得到标准字节，再分别加0x80得到对应高位字节。例如区位16、01，先把16转0x10，再加0x20得30H；01加20H得21H，因此标准码为30 21，常见机内码为B0 A1。不要对十进制书写的“16”直接当十六进制16运算。

一个汉字的16×16点阵若每点一位，需要256位，即32字节；这描述字形图像的占用，与该汉字文本编码占几字节不同。现代Unicode与UTF-8也不能套用“所有汉字固定两字节”的旧环境说法。


## 浮点判断的来源约束

这里dx、dy、dz来自32位int的精确double转换。不能另取超出int来源的巨大数作为初始反例。两项或三项和都在53位精度范围内，因此加法结合律在这道受限题中成立；乘法无此保证。

| 表达式（dx=(double)x 等） | 判断与理由 |
|---|---|
| dx*dx ≥ 0 | 真；有限范围，不会平方上溢 |
| (double)(float)x == dx | 假；x=2²⁴+1 |
| dx+dy == (double)(x+y) | 机器回绕模型下假；INT_MAX+1。标准 C 中右侧先溢出，表达式无定义 |
| (dx+dy)+dz == dx+(dy+dz) | 真；最多三个 32 位整数的和，精确可表示 |
| dx*dy*dz == dz*dy*dx | 假；乘积可能超出 53 位有效精度 |
| dx/dx == dy/dy | 假；x=0、y=1，左侧 0/0 为 NaN，比较为假 |


乘法的有效反例取x=1818339828、y=1765447924、z=1657142324。每次运算按binary64最近取偶舍入时，(dx×dy)×dz与(dz×dy)×dx之差为2⁴⁰。前一个中间乘积已经舍入，扩宽或交换后面的乘法无法恢复其误差。核验脚本分别重算两种顺序。
