第二章 · 数据的表示与处理

01 · 一串位怎样变成一个数

教材 2.1；第二章 PPT 1–7、15–16
学完应能：区分位串、真值、进制和编码，熟练在二进制与十六进制间转换。
速通 · 核心规则

计算机保存的是 0 和 1。真值是我们理解的数，机器数是保存它的位串。解释一个位串，需要知道位数、编码和小数点的位置。11111111 当作 8 位无符号整数为 255，当作 8 位补码整数为 −1。

二进制每位的权重是 2 的幂；十六进制的一位正好对应四个二进制位。十六进制用来缩短书写，并不改变存储内容。

0x2D = 0010 1101₂ = 32 + 8 + 4 + 1 = 45
101.101₂ = 4 + 1 + 1/2 + 1/8 = 5.625
了解 · 原理与直觉

为什么二进制更适合硬件

电路很容易区分两种稳定状态。把这些状态规定为 0 和 1 后，就能用逻辑门处理信息。n 位一共有 2ⁿ 种组合，具体含义由编码规则分配。

整数和小数怎么转换

整数不断除以 2，把余数倒过来读；小数不断乘以 2，把每次得到的整数部分顺着读。二进制转十六进制时，以小数点为界向两侧每四位分组，整数侧左补零，小数侧右补零。

13 ÷ 2：余数依次 1、0、1、1 → 1101₂
0.625 × 2 = 1.25 → 1
0.25  × 2 = 0.5  → 0
0.5   × 2 = 1.0  → 1
13.625 = 1101.101₂ = D.A₁₆

定点整数与定点小数

约定最高位为符号，余下 n−1 位是小数时，原码小数最大正值为 1−2⁻⁽ⁿ⁻¹⁾，最小负值为其相反数；补码小数范围为 [−1,1−2⁻⁽ⁿ⁻¹⁾]。位串不变，只是每位的权重随小数点移动。

例如 8 位补码 0xC0 当整数为 −64，当 1 位整数位加 7 位小数的定点格式时为 −64/128=−0.5。给机器数求真值时必须看题目的小数点约定。

掌握 · 推演与练习

例题：28.125 的三种表示

28=16+8+4，所以整数部分为 11100；0.125=2⁻³，所以小数部分为 .001。得 11100.001₂。按三位分组得到 34.1₈，按四位分组得到 1C.2₁₆。

进制转换保持数值；改变编码解释可能改变数值。题目给“机器数”时，先问它按什么类型解释。

展开答案与推理

深入 · 边界与联系

定点、浮点与 BCD

定点编码约定小数点位置，例如一个无符号 8 位定点小数可规定值为整数编码除以 256。浮点编码另存指数，使数值可在更大范围内移动。BCD 则把每个十进制数字单独编码：十进制 59 的 BCD 是 0101 1001，普通二进制是 0011 1011。

一个最简分数只有在分母为 2 的幂时，才有有限二进制小数。因此 1/8 精确，1/10 循环。这会直接影响后面的浮点数。

02 · 位数、字节、地址与大小端

教材 2.5；第二章 PPT 44–54
学完应能：能画出整数的内存字节布局，并理解类型宽度依赖平台。
速通 · 核心规则

本讲主线采用 IA-32/Linux：字节 8 位、short 16 位、int/long/指针 32 位。float 为 32 位，double 为 64 位。内存按字节编址，连续四字节的 int 占用四个地址，它的地址是其中最小的地址。

小端：低有效字节放低地址；大端：高有效字节放低地址。x86 采用小端。

地址100101102103
0x12345678，小端78563412
0x12345678，大端12345678
了解 · 原理与直觉

把内存想成带门牌号的一排小格子，每格一字节。取一个 int 时，从起始地址读四格，再按机器规定拼起来。字节顺序只调整字节之间的排列，每个字节中的位不用倒置。

x86 的 word 固定指 16 位，double word 指 32 位，quad word 指 64 位；“机器字长”常指寄存器与主要数据通路的基本宽度，两者概念要分清。

类型IA-32/Linuxx86-64/Linux（LP64）
char / short / int1 / 2 / 4 B1 / 2 / 4 B
long / 指针4 / 4 B8 / 8 B
float / double4 / 8 B4 / 8 B
掌握 · 推演与练习

例题：−65535 的存储

32 位补码机器数为 2³²−65535=0xFFFF0001。若地址为 100，小端布局从 100 到 103 为 01、00、FF、FF。调试器显示的内存字节序与我们通常从高位向低位写整数的顺序不同。

uint32_t x = 0x12345678u;
const unsigned char *p = (const unsigned char *)&x;
// 在 x86 上：p[0]=0x78，p[1]=0x56，p[2]=0x34，p[3]=0x12

展开答案与推理

int 的机器数是 0x0000FFFE，值为 65534；首字节是 254。读取宽度会影响结果。

深入 · 边界与联系

课件中的平台约定与常见误区

课件容量单位采用传统二进制口径：1 KB=1024 B。严格区分时可写 1 KiB=1024 B，1 kB=1000 B；带宽通常按十进制，1 Mb/s=10⁶ bit/s。换成字节每秒要再除以 8。

课件用 char 检测大小端的例子还混入了符号扩展：0xFF 读成 signed char 后提升为 int 是 −1，与 int 常量 255 比较会为假。用 unsigned char 观察对象表示更直接。C 的 sizeof(char) 始终为 1，课程进一步约定一字节为 8 位。

03 · 补码：把减法接到加法器上

教材 2.1.4、2.2.1；第二章 PPT 8–16
学完应能：能求补码、解补码，并解释范围不对称和模运算。
速通 · 核心规则

n 位无符号整数范围：0 到 2ⁿ−1。n 位补码整数范围：−2ⁿ⁻¹ 到 2ⁿ⁻¹−1。相同位串若最高位为 1，补码值等于无符号值减去 2ⁿ。

U = Σ bᵢ2ⁱ；T = −bₙ₋₁2ⁿ⁻¹ + Σᵢ₌₀ⁿ⁻² bᵢ2ⁱ

求负数补码：先写绝对值的 n 位二进制，再按位取反加 1。例如 8 位 −5：00000101 → 11111010 → 11111011。

了解 · 原理与直觉

时钟为什么能解释补码

时钟从 10 点退 4 格，与顺拨 8 格到达同一点，因为 −4 和 8 在模 12 下同余。n 位加法器只保留低 n 位，天然是模 2ⁿ 系统。它能用“加上 2ⁿ−b”实现“减去 b”。

8 位 −5 编码为 251。3+251=254，解读为补码就是 −2。硬件仍只做普通二进制加法，结果的有符号含义由编码赋予。

00000011    3
+ 11111011   -5（位串的无符号值为 251）
-----------
  11111110   -2（254 - 256）
掌握 · 推演与练习

解码例题：0xC5

8 位无符号值为 12×16+5=197，补码值为 197−256=−59。也可以取反加一：C5 → 3A → 3B=59，原值为 −59。

8 位最小值 0x80=−128，最大值 0x7F=127。0 只有一种编码；负数比正数多一个。对最小值取负，正的 128 无法用 8 位补码表示，保留低位又回到 0x80。

停一下，自己试试

展开答案与推理

分别为 −14、−128、114。−123 的补码为 256−123=133=0x85。

位串解读实验台

深入 · 边界与联系

其他编码用于什么

原码用符号位加绝对值，8 位整数原码范围为 −127 到 127，有 +0 和 −0；反码对负数把绝对值各位取反，也有两个零。补码解决了零的重复和加减电路统一的问题。

移码把真值整体加偏置 K，E=e+K，用于浮点阶码。若 K=2ⁿ⁻¹，移码与补码最高位互反；IEEE 754 的偏置为 2ᵏ⁻¹−1，因此不能把“最高位互反”规则直接套到 IEEE 指数字段。

两个符号位的变形补码可通过结果符号 01、10 识别溢出，00、11 表示未溢出。符号位扩充仍须复制原符号。

04 · C 类型转换：先确定表达式的类型

教材 2.2.2、2.6.3；第二章 PPT 17–22、51、60
学完应能：能判断混合类型比较，区分重解释、扩展与截断。
速通 · 核心规则

同位宽有符号与无符号转换，在课程的补码机器模型下保留位串，重新解释数值。扩宽时，无符号数补 0，有符号数复制符号位；缩窄时保留低位。

-1 < 0U 为假：int 的 −1 转为同宽 unsigned int 后变为 2³²−1。-1 < 0 为真。

了解 · 原理与直觉

转换分两步判断

  1. 先做整数提升：在本平台，char、short、unsigned char、unsigned short 的全部值都能装进 int，因此通常提升成 int。
  2. 再做通常算术转换：相同等级的 int 与 unsigned int 混用，int 转 unsigned int。不同等级还要看较高等级的带符号类型能否容纳无符号类型的全部值。

所以 unsigned short 并不会在每次比较中把另一边变成 unsigned。类型等级与能否表示全部值都要考虑。

unsigned short b = 1;
int c = -1;
b > c;              // b 提升为 int，结果真
unsigned int a = 1;
a > c;              // c 转 unsigned int，结果假
掌握 · 推演与练习

例题：先扩展，还是先重解释

signed char 的 −1 位串为 FF。直接转 unsigned int 时，语言规则得到 2³²−1；先转 unsigned char 得 255，再转 unsigned int 得 255。中间类型会改变最终数值。

操作16 位结果值
8 位 signed −5 符号扩展FFFB−5
8 位 unsigned 251 零扩展00FB251
16 位 0x1234 截断至 8 位3452（无符号）
停一下，自己试试

unsigned short us=65535; int i=-1; us>i 与 (unsigned int)us>i 各是什么？

展开答案与推理

第一项真：us 提升成 int，65535>−1。第二项假：i 转成 unsigned int 的 4294967295。

深入 · 边界与联系

常量与标准边界

十进制整数字面量与十六进制整数字面量候选类型不同，C90 与 C99 规则也有差异。-2147483648 先确定正字面量 2147483648 的类型，再施加一元负号。写 INT_MIN 或 (-2147483647-1) 能避免把旧课件中的常量现象当作所有编译器的固定行为。

机器指令保留低位，与 C 语言保证的语义需要分开判断：无符号转换按模定义；超范围转有符号类型，在本讲采用的 C11/C17 下为实现定义。有符号溢出、越界和非法移位也不能直接推断为某个必然输出。

printf 的格式要匹配参数类型：%d 对 int，%u 对 unsigned int，%zu 对 size_t，%p 对转成 void* 的指针。

05 · 按位运算、逻辑运算与掩码

教材 2.6.1；第二章 PPT 39、57–58
学完应能：能构造掩码，并解释 XOR 交换及别名问题。
速通 · 核心规则

& | ^ ~ 每一位独立计算；&& || ! 把整个操作数按真假判断，结果为 0 或 1。0 为假，非零为真。逻辑与、或还会短路。

目标32 位无符号表达式
保留最低字节x & 0xFFu
把最低字节置 1x | 0xFFu
最低字节清 0，其余不变x & ~0xFFu
最低字节清 0，其余取反~x & ~0xFFu
了解 · 原理与直觉

掩码为什么有效

AND 中，遇 0 就清零，遇 1 就保留；OR 中，遇 1 就置一，遇 0 就保留；XOR 中，遇 1 就翻转，遇 0 就保留。

x = 0x12345678u
x & 0xFFu       → 0x00000078
x | 0xFFu       → 0x123456FF
x ^ 0xFFu       → 0x12345687
~x & ~0xFFu     → 0xEDCBA900
0x55 & 0x0F = 0x05；0x55 && 0x0F = 1
掌握 · 推演与练习

教材题 13、14、16 的解题方法

XOR 交换的三步是：a←a⊕b；b←(a⊕b)⊕b=a；a←(a⊕b)⊕a=b。成立的前提是两个指针指向不同单元。

若 x、y 指向同一单元，第一句 *x ^= *y 就把该单元清零。奇数长度数组若循环条件为 left≤right，最后会交换中间元素自身，导致中间值变 0。改成 left<right，或采用临时变量交换。

32 位最高字节掩码为 0xFF000000u。一般 n 位无符号对象可在满足 n≥8 且移位数合法时，用最高 8 位为 1 的同宽掩码。题目中的宽度不可省略。

停一下，自己试试

x=0xA5：x&0x0F、x^0xFF、!x 的结果？同一变量自己 XOR 交换会怎样？

展开答案与推理

分别为 0x05、0x5A、0。自己交换会被清零。

深入 · 边界与联系

位运算容易藏在哪些地方

x & 0xF != 15 在 C 中解析为 x & (0xF != 15)，因此结果为 0。应写 (x & 0xFu) != 15u。读教材题 34 时要检查括号，不能凭“意图”替代实际语法。

~x 的位宽受整数提升影响：对 unsigned char 取反，表达式通常为 int。若只需翻转低 8 位，先取反再与 0xFFu 相与，或显式转换到 unsigned char。

06 · 移位、乘 2 的幂与带符号除法

教材 2.6.2、2.6.6；第二章 PPT 59、88、93–95
学完应能：分清逻辑右移、算术右移与向零舍入。
速通 · 核心规则

逻辑右移高位补 0；算术右移高位补原符号。左移低位补 0，高位移出。n 位无符号左移相当于乘 2ᵏ 后模 2ⁿ；无符号右移相当于除 2ᵏ 取下整。

本讲 x86 补码模型采用算术右移处理有符号负数：-7 >> 1 得 −4；C 整数除法 -7/2 得 −3，向零截断。

了解 · 原理与直觉

为什么负数右移需要“补偿”

算术右移近似地板函数，负的非整数结果会向更小方向取整。向零除法希望向更大方向取整。先加 2ᵏ−1，再算术右移 k 位，可把负数推到正确区间。

-14 / 4 = -3
-14：11110010₂
算术右移 2 → 11111100₂ = -4
先加 3：-11 = 11110101₂
再右移 2 → 11111101₂ = -3

// 32 位补码、算术右移的课程模型：
int div32(int x) {
    int bias = (x >> 31) & 31;
    return (x + bias) >> 5;

了解 · 原理与直觉

浮点加法的五步

先对阶：指数小的一方右移有效数；再相加；将结果规格化；舍入；最后处理范围。小数右移时可能丢掉有效位，因此每次运算都可能发生误差。

0.5 + (-0.4375)
= 1.000₂ × 2⁻¹ + (-1.110₂ × 2⁻²)
= (1.000₂ - 0.111₂) × 2⁻¹
= 0.001₂ × 2⁻¹
= 1.000₂ × 2⁻⁴ = 0.0625

在 [2²⁴,2²⁵) 上 float 的间距为 2。2²⁴+1 处于 2²⁴ 与 2²⁴+2 正中，舍入到 2²⁴；2²⁴+3 舍入到 2²⁴+4。

为什么 int 来源能保证加法

三个 int 的和的绝对值至多约 3×2³¹，远小于 2⁵³。每个中间整数也在精确范围内，所以任一次序都等于数学整数和。乘法却不同，三项乘积能达到约 2⁹³，必须舍入。

这些结论采用每个运算按声明精度计算、默认舍入、不启用允许重新结合的 fast-math。旧 x87 暂存的扩展精度，或不同编译优化，可能改变观察到的中间舍入。评题时先写清模型。

24 · 栈帧：ESP 在动，EBP 给参照

教材 4.1.1；第三章 PPT 65–73、88–98
学完应能：能按指令追踪 call、函数序言、leave、ret。
速通 · 核心规则

一次函数调用通常需要保存返回位置、入口参数和局部状态。典型 IA-32 栈帧序言为 pushl %ebp；movl %esp,%ebp；subl $N,%esp。

建立帧后：0(%ebp) 保存旧 EBP；4(%ebp) 为返回地址；8(%ebp)、12(%ebp) 为前两个普通 4 字节参数；局部变量通常用负偏移。该布局依赖上述序言和调用约定。

了解 · 原理与直觉

两个指针各司什么职

ESP 指向当前栈顶，push、pop、预留空间都会改变它。EBP 建立后可稳定作为本次调用的坐标原点。正偏移跨过旧 EBP 和返回地址找到参数；负偏移定位预留的局部空间。

call 保存下一条指令的地址后转到函数；ret 取出这个地址恢复控制流。call 不自动保存全部寄存器，也不自动创建完整局部变量区。

掌握 · 推演与练习

用真实地址走完整个过程

调用前 ESP=0x1000；执行 call 后，返回地址在 0x0FFC。设调用者 EBP=0x2000，被调用者 push %ebp 后 ESP=0x0FF8，M₄[0x0FF8]=0x2000；mov %esp,%ebp 后 EBP=0x0FF8；sub $16,%esp 后 ESP=0x0FE8。

相对当前 EBP绝对地址内容
+120x1004第 2 参数
+80x1000第 1 参数
+40x0FFC返回地址
00x0FF8旧 EBP=0x2000
−40x0FF4示例局部变量槽

leave 等价于 mov %ebp,%esp；pop %ebp。随后 ret 再弹返回地址，ESP 回到 0x1000；栈参数通常由调用者清理。

25 · 函数调用、参数和寄存器保存

速通 · 核心规则

课内 i386 System V 常见整数参数通过栈传递，普通参数从右到左准备；int 返回值在 EAX。EAX/ECX/EDX 属调用者保存；EBX/ESI/EDI/EBP 属被调用者保存。

按值与按地址

它展示“限制内部成员对齐”和“提高整体对象对齐”是两个维度。检查偏移用 offsetof，大小用 sizeof，对齐用 _Alignof（C）或 alignof（C++），比用空指针构造成员地址更清楚。

29 · 越界、缓冲区溢出与防范

教材 4.4；第三章 PPT 80–81、151–163
学完应能：理解越界如何覆盖调用状态，并能修正长度检查。
速通 · 核心规则

CPU 普通 load/store 通常只检查地址访问权限，不知道某地址是否仍属于 C 数组。越界可能改写邻近数据、保存寄存器或返回地址，也可能立即异常；C 语义中属于未定义行为。

缓冲区溢出是写入长度超过缓冲区容量。字符串还要为结尾的零字节留位置。

了解 · 原理与直觉

把破坏理解成地址覆盖

若示例缓冲区起点 B、容量 16，合法写地址为 B 到 B+15。复制 17 字节会写到 B+16，可能触及相邻槽。它覆盖哪个对象取决于本次实际编译布局，不能只靠源码声明次序猜。

课件中 a[i] 写入破坏 double d 的例子，意在展示相同位写入对相邻不同类型对象的影响。具体值依栈布局而定，代码没有标准保证的输出。

掌握 · 推演与练习

修正一个固定数组复制

#include <string.h>
int copy_text(char *dst, size_t cap, const char *src) {
    size_t n = strlen(src);
    if (cap == 0 || n >= cap) return 0;
    memcpy(dst, src, n + 1);
    return 1;
}

前提：src 是有效零结尾字符串、dst 确有 cap 字节可写、源目的不重叠。n≥cap 时拒绝，避免“只检查 n>cap”漏掉结尾字符。重叠复制须按实际需求考虑 memmove。

30 · x86-64：把 IA-32 知识迁移过去

教材 3.2、4.1.6；第三章 PPT 164–174、180
学完应能：能比较寄存器视图、数据模型和 Linux 参数约定。
速通 · 核心规则

x86-64 兼容并扩展 IA-32：通用寄存器扩至 64 位、增加 R8–R15。Linux System V 的前六个普通整数/指针参数通常依次放 RDI、RSI、RDX、RCX、R8、R9；后续参数走栈；整数返回值放 RAX。

了解 · 原理与直觉

写低 32 位会发生什么

在 64 位模式，写 EAX 会把 RAX 高 32 位清 0；写 AX/AL 不会。把负的 int 扩为 long 需要符号扩展，例如 movslq %eax,%rax。

RAX=0xFFFFFFFFFFFFFFFF
movl $1,%eax      → RAX=0x0000000000000001
movw $1,%ax       → 若从初值开始，RAX=0xFFFFFFFFFFFF0001
movl $-1,%eax     → RAX=0x00000000FFFFFFFF
movslq %eax,%rax  → RAX=0xFFFFFFFFFFFFFFFF
掌握 · 推演与练习

一个不需要典型栈帧的函数

// Linux x86-64：long add(long a,long b) { return a+b; }
add:
    leaq (%rdi,%rsi),%rax
    ret

参数已在寄存器，无需先从栈取；没有局部对象或额外调用，也可省略建立 RBP 帧。call/ret 仍用栈保存/恢复返回地址；常规 pushq/popq 改变 RSP 8 字节。

展开答案与推理

深入 · 边界与联系

平台差异需要同时记住

System V AMD64 的被调用者保存通用寄存器为 RBX、RBP、R12–R15；栈指针当然须恢复。常规调用要求 call 前 RSP 按 16 字节对齐，入口因压入 8 字节返回地址，RSP+8 为 16 字节对齐。
