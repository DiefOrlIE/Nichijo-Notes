# 讲义重写计划：先解决行文断裂

用户反馈：读者无法知道某句话为什么出现在当前位置，段落没头没尾，缺少衔接。2026-10-15 修订。

## 重新定位问题

前置知识只是其中一个问题。现稿还把许多各自正确的结论拼成段落，没有给出让它们依次出现的理由。

最小二乘节第一段从矩阵符号跳到正负误差抵消，再转到大误差惩罚、可求导性和精确拟合是否存在。这是五个不同的话题，尚未形成一个能跟随的问题。第二段在一个常数算出后顺带报告残差之和为零，却没解释为何此时需要看这个和；第三段立即跳到列空间与正交，没有连接前一例子的具体对象。范数等价节从长度比较跳到序列收敛，同样没有说明为什么关心收敛。

网页运行检查与数学正确性检查仍然需要，但都不能替代行文检查。后续报告须分开说明哪些属于程序验证，哪些属于教学文本判断。

## 重写步骤与交付物

1. **标出原稿的断点。** 以连续阅读顺序逐段检查：这段接着回答哪一个疑问，主题是否突然改变，指代是否明确，句子是否只给结论。输出具体原句、缺失的连接和处理方式，删除不承担解释任务的顺带结论。
2. **先写不含公式的解释路线。** 每节先用完整日常语言写清楚：遇到什么问题、试过的办法哪里不够、下一步为什么合理、结果怎样回答最初的问题。读完这条路线仍不知道目的，就先修路线，暂不加公式。
3. **重写最小二乘作为语言样本。** 从几次测量需要一个代表值开始，保持同一组数据和同一变量。比较候选值，遇到误差相消后解释平方计分，再计算最低分。矩阵写法只在读者已经看懂逐项计算后出现，逐项对照。几何解释另起一个有明确目的的小节；同一节不随意换数据。
4. **重建每段的内部推理。** 先交代为什么要算，再写具体计算，解释结果意味着什么，最后仅在确有必要时指出下一步尚未解决的问题。不能靠反复添加“因此”“接下来”掩盖中间缺失的理由；句式不强制统一。
5. **按五讲顺序重写，允许重新拆节。** 每节只承担有限的教学任务。定义、公式和例子服务于正在解决的问题。历史、用途、反例和数值算法说明按作用放置，避免把新话题塞入段尾。前置知识在真正需要处补齐。
6. **做连续阅读审稿。** 暂时遮去公式、图和小标题，只看文字是否形成连贯解释；恢复公式后查每个符号及每一步理由；再逐对审查相邻段落，能否说清上一段的结果为什么引出下一段。所有解释推到初学者可以回答“为什么在这里写这句”为止，不以字数验收。
7. **重写英文并核对图像。** 中文解释路线稳定后写同等细节的英文。图像使用正文数据；图前说明要观察什么，图后说明观察解决了哪个疑问。最后做数学与页面检查。
8. **独立文字审稿。** 使用已接通的 DeepSeek API 检查原稿、重写稿及修订稿，要求给出短原句、读者疑问和缺失连接。记录实际模型与审稿结果。逐条核对意见，保留采纳与未采纳的理由，不用模型评分代替读者反馈。

## 本轮界面要求

- 阅读层标题只保留速通、了解、掌握、深入，删去重复后缀和当前层新增徽标；保留深度切换功能。
- 47 个核对原课件展开框宽度改为正文的 50%。
- 目录可收起和展开，入口保持可见；收起后正文使用可用宽度。
- 增加日间/夜间切换，正文、公式底色、术语窗、图像底色一起适配。
- 目录和主题偏好保存在当前浏览器。
- 当前阅读层参照 Nichijo Notes 的 ICS 讲义：蓝色左边线、由左向右淡出的浅蓝底色；夜间采用相应深色底与浅蓝边线，不恢复重复说明。

## 完成判断

一节的教学验收需逐项写明：对象为何出现、符号如何对应具体例子、每一步操作的理由、结果回应的问题、段落间的连接，以及可以独立完成的类似任务。不得把网页正常显示、资料覆盖数量、字数和“已读过”当成自学可读性的证据。

本轮先按上述顺序完成反思、计划、界面调整和最小二乘试写，并交给 DeepSeek 复审。其余章节尚待逐节重写；不将界面更新或一个试写章节称为全量教学文本已修复。
