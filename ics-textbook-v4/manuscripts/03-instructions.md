# 3.1 程序转换、寄存器与寻址——把一行C落实到具体位置

第二章说明了数怎样变成位串，却还没有回答谁在什么时候读取它。现在考虑一个最小任务：取出变量x的值，加3，再把结果写到另一个位置。C语言让我们用变量名表达任务，处理器执行时则需要知道取数位置、数据宽度、操作种类和写回位置。本节先把这些对象落实，随后再读更长的汇编程序。

## 从文本走到可以执行的字节

C源文件是字符组成的文本，处理器不能把其中的`x+3`直接当成机器指令执行。常见构建先进行预处理，展开头文件、宏和条件编译；编译器再分析C语义并选择机器操作，汇编器把汇编指令编码为字节，链接器把多个目标模块与库组合起来。加载时，操作系统为程序建立执行所需的内存映射，才开始实际运行。第四章会把最后两步完整展开，本节只使用它们提供的接口。

以常见GNU工具链为例，`cc -E demo.c -o demo.i`查看预处理结果，`cc -S demo.c -o demo.s`生成汇编，`cc -c demo.c -o demo.o`生成可重定位目标文件，`cc demo.o -o demo`再链接。命令中的-E、-S、-c分别选择停止阶段。对缺少main的函数文件，生成.o可以成功，直接链接成普通可执行文件通常还缺程序入口所需的定义。编译成功与程序能够完整启动，是不同检查。

汇编文本让人能够阅读指令，机器码才是处理器实际识别的字节编码。同一源表达式可能因平台、优化程度、周围代码而得到不同指令序列。阅读时应证明“这组指令实现了什么”，无需期待每行C总有唯一的固定翻译。高级语言保证的行为也会约束优化；第二章讲过的有符号溢出等未定义行为，不能靠一份偶然生成的指令给C程序补保证。

## 先给执行状态画清边界

处理器内部有少量可以快速读写的存储位置，称为寄存器。它们用名字标识，内存则用数值地址定位。本章基础例子采用IA-32，即32位x86模型；EAX、ECX、EDX、EBX、ESP、EBP、ESI、EDI是32位通用寄存器。EIP记录控制流的指令位置，标志寄存器保存前章用到的ZF、SF、CF、OF等条件。现在只需把这些名字视为可保存位串的位置，等用到栈时再解释ESP和EBP的专门角色。

EAX的低16位可以用AX访问，AX的低8位为AL，高8位为AH。假设EAX原来是12345678H，写AL为AAH后变成123456AAH；只覆盖低8位，其余位保留。再写AX为0001H，则EAX变成12340001H。写窄寄存器并不会自动清空整个32位寄存器。到x86-64模型时，RAX扩为64位，写EAX会把RAX高32位清零，写AX或AL仍只改对应低位。架构规则不同，必须先声明使用哪个模型。

内存地址和寄存器内容都可写成数值，但角色由指令决定。设EAX=1000，内存地址1000起四字节为05、00、00、00。把EAX当操作数，读到的是1000；把EAX当地址去访问内存，才读到5。这是初学汇编最重要的一次区分。后文写`M32[1000]`表示从地址1000起读32位，M8则读8位；方括号里的数是位置，M给出该位置保存的内容。

## 逐个拆开AT&T操作数

课程使用的AT&T汇编一般把源写在前、目的写在后，寄存器前加`%`，立即数前加`$`。立即数就是指令中直接给出的常量。`movl $3,%eax`把常量3写入EAX；`movl %eax,%edx`复制EAX到EDX；`movl (%eax),%edx`把EAX当地址，读取那里四字节再写EDX。mov的l表示long，即这里的32位；b和w分别表示8位与16位，x86-64常用q表示64位。后缀来自汇编操作宽度，不能用本机C的long大小猜所有平台的指令宽度。

把一个真实的小状态走完。开始EAX=1000，EDX=7，M32[1004]=5。执行`movl 4(%eax),%ecx`时，先算地址1000+4=1004，再取出5，故ECX=5。执行`addl $3,%ecx`后ECX=8。执行`movl %ecx,8(%eax)`把8按小端写到1008至1011，字节为08、00、00、00。最后EAX仍1000，EDX仍7，源地址1004的5也没有变化。每条指令只改它明示或体系结构规定的状态，不能因为“用到了EAX”就认定EAX变化。

一般内存寻址可写成`D(B,I,S)`，有效地址是位移D加基址寄存器B的值，再加变址寄存器I的值乘比例S。S只能取编码允许的1、2、4、8；缺省部分按对应规则省略。设EBX=1000、ECX=3，`8(%ebx,%ecx,4)`对应1000+3乘4+8=1020。若那里保存99，mov读取的才是99。乘4先帮助选择四字节元素的位置，不意味着把元素的值再乘4。

`leal 8(%ebx,%ecx,4),%eax`也计算1020，但直接把1020写入EAX，完全不读取M32[1020]。lea称加载有效地址；可以用于指针运算，也可借地址计算结构完成某些整数运算。它不因括号出现就访问内存，也不更新算术标志。判读时先看指令，再决定括号表达式扮演什么角色。

## 指针是可保存的地址值

C中的`int *p`声明p用来保存指向int对象的地址；`&x`取得x的地址，`*p`访问p指向的对象。先设x在地址1004，x值5，p保存1004。表达式p给出1004，表达式*p给出5；执行`*p=8`改的是地址1004起的对象，p保存的地址仍为1004。指针变量自己也有存放位置，但解引用时使用的是它保存的地址。

下面的函数把这个操作与算术结合。它本身是一份完整可编译的函数定义，调用它时必须传入指向有效int对象的指针。

```c
void increase(int *p) {
    int x = *p;
    x = x + 3;
    *p = x;
}
```

如果本节先约定p已在EAX中，核心效果可由下面三条指令完成。参数到底怎样到达EAX，要等3.3学习调用约定后再补全过程。

```asm
movl (%eax), %edx
addl $3, %edx
movl %edx, (%eax)
```

当p=1004、M32[1004]=5，第一步EDX=5，第二步8，第三步M32[1004]=8。输入地址无效时，读或写可能出错；在C中，空指针解引用和越界解引用都没有有效行为保证。这个函数需要常量次数的操作，时间和额外空间均为O(1)。它的目的很小，却建立了读懂数组、结构体和栈访问所需的完整位置观念。

## 指令的地址也需要计算

数据有地址，机器指令的编码也占据连续字节。x86指令长度可变，下一条顺序指令在“本条起点加本条长度”。假设某条五字节call从十六进制1000开始，下一条在1005。若目标在1020，需要保存的相对位移为1020−1005=1B，编码可为E8 1B 00 00 00。E8辨认这种调用，后四字节按小端给出有符号位移。call还会保存返回地址，3.3会逐项演示。

若一条二字节条件跳转从1000开始，编码74 08，其中08是相对位移，则跳转目标是1002+8=100A。它以指令末尾为参照。反过来，若五字节相对调用从1020调用1000，位移为1000−1025=−25H，即−37十进制；32位补码为FFFFFFDB，四字节DB FF FF FF。检查时把有符号位移加回下一条地址，必须回到目标。

ISA是Instruction Set Architecture，指令集体系结构，规定指令可观察的行为、寄存器和编码等接口。同一ISA可以有不同内部实现，不能从一条汇编指令便推断实际需要几个时钟周期。现在我们先掌握这个接口层：一条指令从哪里取什么，怎样改状态，控制流往哪里走。

## 练习：每次都说清“位置还是内容”

### 练习一：三种源操作数

题目：EAX=2000，M32[2000]=17，分别执行`movl $2000,%edx`、`movl %eax,%edx`、`movl (%eax),%edx`，结果是什么？

提示：将源分别读成常量、寄存器值和内存内容。

解答：前两条都写2000，第三条写17。前两条在这组初值中碰巧相同，换EAX初值就会分开；第三条发生一次数据内存读取。核对时给每个数标角色，不能只记三个最终数字。

### 练习二：有效地址与lea（教材第三章寻址题同类改编）

题目：EBX=4000，ECX=5，M32[4024]=70。`movl 4(%ebx,%ecx,4),%eax`与对应的leal各得什么？

提示：先独立算地址，再看指令是否取内存内容。

解答：地址4000+20+4=4024。mov得到70，lea得到4024。改变4024处内存值只能改变mov结果。可用这一变式复查二者是否真的区分开。

### 练习三：反向相对跳转

题目：五字节call在3000H，目标2FF0H，位移的十六进制补码及小端字段是什么？

提示：后继地址3005H，差值为−15H。

解答：位移−21十进制，32位补码FFFFFFEB，字段EB FF FF FF。核对3005H−15H=2FF0H。不要用call起点3000H直接减目标。

能稳定区分地址、内容、宽度之后，下一节才有条件研究同一组指令怎样落实C的类型转换与算术。
