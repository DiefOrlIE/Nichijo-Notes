# 3.2 指令运算与类型转换——同一个位串怎样参与不同计算

上一节完成了取数、计算、写回的骨架。现在把输入换成一个字节F2H。如果它是unsigned char，数值为242；如果是signed char，数值为−14。两种输入存储完全一样，但扩展到32位后参与运算时应给出不同结果。机器指令如何保留C表达式指定的含义，就是本节的问题。

## 扩展指令负责保留哪一种数值

设EAX=1000，M8[1000]=F2。执行`movzbl (%eax),%edx`读取一个字节，将其零扩展为32位，EDX得到000000F2，即242。执行`movsbl (%eax),%edx`则把符号位1补到高24位，得到FFFFFFF2，按补码解释为−14。指令名称里的z表示零扩展，s表示符号扩展，b到l指出从字节扩到双字。原字节并未改变，区别只在读入更宽目的时怎样填高位。

若随后对EDX加3，两个路径分别得到245与−11。C表达式中的整数提升先发生，再参与运算，因此读取signed char并作int运算，通常需要符号扩展；unsigned char提升到能够容纳它的int，通常需要零扩展。这里int32能够容纳0至255。不能只因为最终加法都是addl，就忽略之前扩展已决定了输入数值。

变窄则没有额外“缩小数值”的指令魔法。若把32位1234F2H的低字节写到一个char对象，保存的就是F2H。按unsigned char读是242，按signed char读通常为−14，具体超范围有符号转换还须遵循语言与实现约定。数组下标、指针差等运算也有各自类型规则，先从C确定数值语义，再解释编译器选用的指令。

## 从寄存器中的x转换后写回指针目标

教材第三章题5要求的不只是“扩展一个寄存器”，还包括写到ptr指向的对象。现在设x在AL、ptr在EDX，目标类型int。当源为signed char时，先用`movsbl %al,%ecx`让ECX成为完整int，再用`movl %ecx,(%edx)`写四字节；当源为unsigned char时，第一条改为movzbl。ECX是临时位置，不能误用EDX承接转换结果，否则会在写回前丢失目的地址。

若x原在EAX，目标改为short，则只需`movw %ax,(%edx)`，写低16位；目标是char则用movb写AL。若x在AX、源为short、目标int，使用movswl；源为unsigned short时用movzwl。这些选择可由两个问题推出：是否扩大，扩大时要保留有符号值还是无符号值。缩窄只保留低位，写入宽度由目的对象确定。到x86-64目标long为64位时，可根据源符号性选择相应扩展，且写32位子寄存器会自动清高半；不能把有符号负int仅写EAX后便假定RAX已经是负long。

指令还受编码限制。普通mov不能同时把两个数据内存操作数作为源和目的，`movl (%eax),(%edx)`要拆成先读寄存器、再写内存。宽度也必须匹配，`movl %al,(%edx)`拿8位寄存器配32位传送不合法；`movb %al,(%edx)`才写一个字节。立即数不能当目的，因此`movl %eax,$3`没有“把结果存进常数3”的含义。有效地址比例只能1、2、4、8，写3无法编码。遇到汇编报错时，沿操作数角色、宽度、寻址限制逐项检查，比记错误例子更可迁移。

## add、sub与逻辑指令怎样为后续判断留下证据

`addl %ecx,%eax`把EAX旧值与ECX相加，结果写回EAX；`subl %ecx,%eax`计算EAX减ECX。`cmpl %ecx,%eax`也按EAX减ECX计算标志，却不把差写回EAX。这个“保留输入、只记条件”的用途，正好适合if和循环。`testl %eax,%eax`按位与同一个值，不改EAX，用零标志判断它是否为零；逻辑与、或、异或一般把CF和OF清零，并按结果更新ZF、SF等。

先让AL=7FH，加1后得到80H。位串加法本身给出唯一结果，CF=0，因为没有第九位进位；OF=1，因为两个非负补码相加却得到负号位；SF=1、ZF=0。若随后判断“有符号大于零”，不能只看SF。比较使用的条件必须把溢出纳入，3.4将通过两条实际分支路径解释SF与OF怎样组合。现在保留这个问题，不急着把所有跳转助记符当作孤立表格背下来。

`incl`和`decl`可加减1，但不更新CF；lea也不改标志。两段代码即使数值结果相同，若后面要用旧标志作条件，也未必可互换。乘除指令的标志规定又不同：imul通常可用CF、OF判断乘积是否适合目的宽度，其他若干标志未定义；除法之后也不能依赖ZF等旧式推测。阅读汇编时，先找分支实际使用哪次有定义的标志，再讨论条件。

## 乘除为何会涉及额外寄存器

两个32位数相乘，完整结果可能需要64位。一操作数形式的无符号`mull %ecx`把EAX与ECX相乘，低32位放EAX，高32位放EDX；有符号一操作数imul给出有符号完整积。常见双操作数`imull %ecx,%eax`只把乘积低32位写回EAX，若需要判断截断是否损失有符号结果，可检查CF、OF。

例如无符号EAX=FFFFFFFFH、ECX=2，完整积为1FFFFFFFEH，所以EDX=1，EAX=FFFFFFFEH。只读EAX会把真实积误看成4294967294。若按有符号−1乘2，完整积是FFFFFFFFFFFFFFFEH，高半全1才是正确符号延伸。位串输入和乘法解释共同决定高半结果。

除法把双宽被除数放在EDX:EAX，商回EAX、余数回EDX。这里冒号意为把两个寄存器拼成64位。若要算有符号int −7除3，先把EAX置−7，再用`cltd`把EAX符号扩展到EDX:EAX：EDX变FFFFFFFFH，拼接后仍是−7。随后对保存3的ECX执行idivl，商为−2、余数为−1，符合`−7=(−2)×3+(−1)`。若错误把EDX清零，拼出的64位数成为4294967289，已经换了被除数。

无符号除法常在32位被除数的高半为0时先清EDX；这项准备来自无符号数值的需要。除数为0或商放不进目的宽度时会产生除法异常。前章的INT_MIN除−1正是有符号商溢出的边界。这里每次先写被除数、除数和预期商范围，比只背“除法前清零”可靠得多。

## 移位优化必须继承原表达式的舍入规则

乘以8常可用左移3位实现低位结果，或由lea组合计算。除以4则要先检查正负与舍入。算术右移负数通常向负无穷取整，C有符号除法向零截断。−9右移2位通常得−3，但−9/4得−2。要让移位模拟除法，可对负数先加3：−9+3=−6，再算术右移2位得到−2；非负数不加。

为什么偏置是3？除数4会把余数分到0、1、2、3。向负无穷取整把非整除的负商多减了1，先加最大余数3即可把相应区间推回朝零的边界；对整除的−8，先加3为−5，向下除4仍是−2，不改变整除商。推广到2的k次幂，偏置取`2^k−1`。代码生成还须确保中间计算与边界安全，不能把这个数学说明无条件替换成任意有符号左移表达式。

## 用一个完整程序观察表示和数值

下面程序只采用已解释的地址、整数宽度和字节复制。stdint.h提供uint32_t这类精确宽度无符号类型，string.h声明memcpy，负责从源地址复制指定字节数到目的地址。复制不会把13.625做数学类型转换；它把同一组字节放到另一个对象中观察。此例明确要求float为IEEE binary32、uint32_t存在，且二者同为四字节。

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>
#include <inttypes.h>
int main(void) {
    float x = 13.625f;
    uint32_t bits = 0;
    if (sizeof x != sizeof bits) return 1;
    memcpy(&bits, &x, sizeof bits);
    printf("%08" PRIX32 " %d\n", bits, (int)x);
    return 0;
}
```

PRIX32选择与uint32_t匹配的十六进制输出格式，前面的08要求至少八位、不足补零。预期输出`415A0000 13`：左边印证第二章的手算编码，右边印证数值转换的截断。这个程序既能检查推导，也提醒我们“按另一种方式读字节”必须用语言允许的访问方式。

## 练习：沿数据路径追踪

### 练习一：一字节输入的两种含义

题目：内存字节80H分别用movsbl和movzbl读入32位寄存器，再加1，各得什么？

提示：先完成扩展，再执行32位加法。

解答：符号扩展为FFFFFF80，即−128，加1得FFFFFF81，即−127；零扩展为00000080，即128，加1得129。原内存都仍是80。核对时把最终数重新截成低字节，会发现二者低字节同为81，高位却表达了不同数值。

### 练习二：除法的高半

题目：EAX保存−10，欲除以3，cltd后EDX为何值？商余各是什么？若直接清EDX，为什么不能沿用答案？

提示：被除数是拼接后的64位数。

解答：EDX全1，完整被除数−10；商−3，余−1，检查−3乘3再减1得−10。清EDX把被除数改成4294967286，已不再是原题。错误发生在除法之前。

### 练习三：优化是否保留语义

题目：某人把`x/8`一律改成算术右移3位。给出反例，并对该反例使用正确偏置复算。

提示：选择不能被8整除的负数。

解答：x=−9时，C商−1，算术右移得−2。负数先加7为−2，再算术右移3位得−1。用−16再检查，先加7为−9，右移仍得−2，整除输入保持正确。完整实现还要限定机器移位语义与位宽。

### 练习四：转换后写到对象（教材第三章题5同类改编）

题目：x为signed char，AL=F2H，EDX指向有效int对象。写出转换并存储的两条指令；若改成unsigned char，应改哪里？

提示：保留EDX中的目的地址，用另一个寄存器完成扩大。

解答：先movsbl %al,%ecx，再movl %ecx,(%edx)，保存−14的FFFFFFF2；无符号源改用movzbl，保存242的000000F2。按四字节小端读回对象可核对。不能用movb替代第二条，否则只修改int低字节。

### 练习五：诊断非法指令（教材第三章题4同类改编）

题目：逐项解释movl (%eax),(%edx)、movl %al,%ecx、leal (%eax,%ecx,3),%edx为什么不合法，并给出前两项的可行修正。

提示：分别检查两个内存操作数、寄存器宽度和比例编码。

解答：第一项普通mov不能内存到内存，应先movl (%eax),%ecx，再movl %ecx,(%edx)；第二项8位与32位不匹配，若要保留有符号值可用movsbl %al,%ecx，保留无符号值用movzbl；第三项比例3不允许，可先用合法比例计算其他等价序列，不能直接写3。修正前应先明确想要的数值语义，汇编器接受不等于实现原意。

本节研究的是单条或短序列运算。程序还必须把控制交给函数，并在函数结束后准确回到原处；下一节将从这一需求建立栈与调用约定。
