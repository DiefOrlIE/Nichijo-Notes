4.1.1 IA-32的过程调用约定（教材 4.1.1；PPT 第3章）

先让调用者提出需求

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

考虑下面的程序：

#include <stdio.h>
int add(int a, int b) {
    int result = a + b;
    return result;
}
int main(void) {
    int answer = add(3, 5);
    printf("%d\n", answer);
    return 0;
}

在C这一层，我们已经知道answer应当得到8。但处理器不会因为看到函数名便自动理解“算完回来”。它实际执行的是存放在不同地址的指令。main中的一条指令必须让执行位置转到add入口，add中的某条指令又必须让它回到main中尚未完成的位置。

我们先只解决“去哪里、回哪里”。把main的一段执行位置想成三个连续任务：准备3和5，执行add，接收结果。进入add前，main还没有完成接收结果，所以必须有某处记住“回来后接着做哪一步”。这个位置就是返回地址。它指向调用指令后面的指令，和被调用函数的入口地址分别承担去程与回程的作用。

还剩两个问题。add必须取得3和5，它的局部变量result也需要临时存放；同时，main之前保存的工作数据不能因为add使用了同一组处理器内部存储位置而无故丢失。函数调用约定统一规定这些交接办法，英文ABI是Application Binary Interface，即应用程序二进制接口。它比“函数名相同”要求更多：参数放哪、返回值放哪、谁保护哪些值，都必须让两边一致。

给处理器安排几个能看见的位置

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

处理器内部有少量可直接读写的存储位置，称为寄存器。我们先只使用三个32位寄存器：EAX存放计算结果；ESP记录当前栈顶地址；EBP作为一次调用中的稳定位置参照。E来自Extended，表示扩展；AX历史上称Accumulator，累加器；SP是Stack Pointer，栈指针；BP是Base Pointer，基址指针。名称说明沿革，当前任务仍由具体指令决定。

寄存器中存放的只是一个位串。例如ESP中保存1000，表示程序把地址1000解释为当前栈顶；内存地址1000处存的内容则是另一件事。为避免混淆，下面说“ESP=1000”时指寄存器的数值，说“地址1000处的四字节”时指沿该数值找到的内存内容。

内存按字节编址，所以一个四字节整数从地址996开始，会占996、997、998、999四格。我们的表为了便于看调用过程，用“996：5”缩写为“从996开始的四字节对象值为5”。它没有让每个地址突然变成四字节。IA-32采用小端序；5的四字节实际为05、00、00、00。

为什么需要一块能后进先出的工作区

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

进入函数后还可能继续调用另一个函数。假设main调用add，而add又调用helper。helper完成后，应先回add，等add完成后再回main。后发生的调用先返回，因此保存返回位置的工作区天然适合后进先出。

这种按后进先出管理的内存区域称为栈。栈顶是下一个弹出操作要读取的位置。在本文的32位约定中，压入一个四字节值分两步：先令ESP减4，腾出四字节位置，再把值写到新ESP所指的地址。弹出分两步：先从ESP读取四字节，再令ESP加4。这个先后顺序必须说清，否则第一次压栈会错四字节。

现在给出第一轮操作。假设原ESP=1000，压入值5后，ESP变996，地址996起保存5；再压入值3，ESP变992，地址992起保存3，原来996处的5仍在。若弹出一次，先取得3，ESP回996；再弹出才取得5。减小的是地址，压入的数据仍可以是任意可表示值。

对应指令pushl $5中，push意为压入，l指定32位操作数，$表明5是常数。popl %eax把栈顶四字节复制到EAX并前移栈顶，%表明eax是寄存器名。弹出没有要求把旧内存内容抹成零；它改变的是这块内存是否仍属于当前有效栈内容。

从第一条准备指令走到add入口

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

我们采用常见cdecl中的一种未优化教学序列：调用者从右到左压参数，add返回int时把结果放EAX，参数由调用者清理。cdecl是C declaration的习惯缩写，指一类C调用约定；完整ABI和编译器选项仍会规定更多细节。真实编译器可以加入对齐空间或省略帧指针，本文先用固定序列观察原理。

main准备add(3,5)，所以先压第二个参数5，再压第一个参数3。我们人为指定call位于地址2000，它长5字节，因此main接收返回结果的下一条指令位于2005。假设进入这段序列前ESP=1000、EBP=1200。

pushl $5
pushl $3
call add
addl $8, %esp

前两条执行后，我们已经得到ESP=992，并在992、996起分别存放3、5。执行call时，处理器还需要把2005保存起来，因此它再压入四字节返回地址：ESP变988，988处保存2005；随后指令指针转到add入口。EIP是Extended Instruction Pointer，扩展指令指针，负责在IA-32中记录控制流位置；去执行add由它改变完成。

注意call没有为我们自动压入3与5。那两条push由调用者代码执行。call额外保存的是返回地址。如果把参数准备指令删除，call仍然能跳入add，但add将无法按预期位置取得正确参数。

此时add刚开始执行，还没有任何序言指令。由低地址到高地址，目前可确认的栈内容是：988处2005，992处3，996处5。EBP仍是main留下的1200。我们暂时只知道ESP，尚未规定add自己的稳定参照点。

为局部工作选择一个稳定参照

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

add可能要为result腾空间，也可能还要压入别的值。若所有参数都用“当前ESP再加多少”定位，每次ESP移动后偏移都需要跟着改。保留一个不随这些临时动作变化的参照，会让寻址更直接。

add先保存调用者的EBP，再令EBP等于此刻ESP：

pushl %ebp
movl %esp, %ebp
subl $4, %esp

第一条把旧EBP值1200压到984，ESP变984。第二条把984复制到EBP，ESP仍984。movl按“源、目的”顺序写，movl %esp,%ebp不会把ESP改成1200。第三条从ESP减4，ESP到980，为局部result预留四字节。预留空间尚未初始化，不能在赋值前把其中内容当成已知的0。

三条都执行后，EBP保持984。于是参数位置可以由刚才的实际摆放推出：第一个参数3从992开始，992−984=8；第二个参数5从996开始，996−984=12。返回地址在988，即EBP+4；旧EBP在984，即EBP+0；局部result在980，即EBP−4。这里的8和12来自已经走过的四次压栈与建立参照，读者无需凭空背一张偏移表。

表中一个地址占一行，只是在整理四字节对象的起点。实际字节仍连续存在。至此，一次调用所需的参数、返回位置、旧参照和局部空间都已经在具体位置上形成。通常将本次调用占用和管理的相关栈区域称为栈帧；不同资料对参数区归属的画法可能略有差异，我们以真实地址和指令为准。

真正执行加法，而不把地址当成数值

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

add的函数体可以按如下序列执行：

movl 8(%ebp), %eax
addl 12(%ebp), %eax
movl %eax, -4(%ebp)
movl -4(%ebp), %eax

第一条的括号要求访问内存。先取EBP=984，加位移8得992，再读992起的四字节，得到3，复制到EAX。执行后EAX=3；EBP、ESP以及内存中的参数都保持刚才状态。指令读到了参数值3，绝不能把EAX写成参数地址992。

第二条先算984+12=996，再读值5；把EAX旧值3加5，得到8写回EAX。它同时会按32位加法更新条件标志，但这里没有依赖它们的条件分支。996处的5没有因此被改成8，目的操作数EAX才是写入位置。

第三条用984−4=980计算目的地址，把EAX中的8写入局部result。第四条再从980取回8到EAX，准备按约定返回结果。这次取回看起来多余，是为了把C中的局部变量存取演示清楚；优化编译器通常会省去这对无必要的内存读写。理解一种教学序列后，还需要通过数据流识别等价实现，而不能要求编译器输出与讲义逐字相同。

现在可以独立核对：从2000跳转前参数为3、5，函数体读到的也为3、5；980处最终保存8；EAX最终也为8。地址计算和数据计算均能在表中找到依据。

返回需要两次恢复，随后才能ret

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

add已经算完，但ESP仍980，栈顶是局部result。此刻直接ret会把980处的8误当成返回地址。因此返回前必须先把栈顶移回真正的返回地址位置。

movl %ebp, %esp
popl %ebp
ret

第一条复制EBP=984到ESP，跳过局部result区域。它没有复制984处的内存值1200；复制的是寄存器本身的数984。第二条从ESP=984读四字节，恰好得到保存的旧EBP值1200，写回EBP；ESP再加4变988。最后ret从988读到2005，令EIP转到2005，ESP再加4变992。EAX没有被这些操作覆盖，仍为8。

两条序言恢复常可用leave表达。这里先把动作拆开，是为了让读者能判断leave到底恢复什么，以及为什么在它之后ret才会读到正确字节。

main回到2005后执行addl $8,%esp，让ESP从992回1000。加8来自两个四字节参数，总共八字节。main随后可以把EAX中的8赋给answer。这个清理只让参数区退出当前栈范围，不会撤销函数返回值。

从一轮调用理解寄存器保护

纸书 122–124 页 · PPT 第3章 64–79、88–103 页 · 需掌握

假设main在进入add前还把另一个待用值9保存在ECX。add也需要一个临时寄存器，如果它把ECX改成100，main返回后便不能继续假装ECX仍为9。所有函数若各自猜测对方会改什么，组合程序就会失败，因此ABI还规定寄存器保护责任。

在这里采用的常见IA-32约定中，EAX、ECX、EDX可由被调用函数改写，调用者若要让其值跨调用存活，就必须自行保存或换用其他合适位置。这叫调用者保存。EBX、ESI、EDI、EBP若由被调用函数使用，则被调用函数须在返回前恢复原值，这叫被调用者保存。前面的push EBP与pop EBP正是一个实际例子。

保护的是调用前后可观察的约定值，函数内部中途仍可以改变这些寄存器。判断一段汇编是否正确时，应当把“进入函数时的值”和“离开函数时的值”对应起来，不能只看到中途被修改便判错。返回结果放EAX也是契约的一部分，所以调用者不能要求EAX恢复成调用前的旧数。

4.1.2 变量的作用域和生存期（教材 4.1.2；PPT 第3章）

变量的作用域与生存期——名字可见与对象存在分别检查

纸书 125–126 页 · PPT 第3章 82、86–87、91 页 · 需掌握

同一个函数可多次调用，每次都需要区分“能否写出变量名”与“原对象是否仍存在”。变量名可被源代码访问的范围叫作用域，对象从建立到结束存在的时间叫生存期。函数里的普通局部变量只在相应块内可见，每次进入调用会建立本次所需对象；退出后其生存期结束。另一个函数即使有同名局部变量，也有自己的对象，不能因名字一样便共享值。

把局部变量声明成static后，它的名字仍只在声明所在范围可见，但对象会跨调用保留。设一个函数内有static int count，初始为0，每次调用先加1再返回，连续两次便返回1和2；普通局部int count=0会在每次调用重新初始化，两次都返回1。由此可见，局部作用域不能直接推出栈存储或短生存期。全局对象与静态对象通常在可写数据区域，普通自动对象可能在栈或寄存器，具体位置由实现与优化确定。

返回一个自动局部对象的地址，不会延长它的生存期。即使返回后原栈字节暂未改动，调用者再解引用也没有有效对象保证。判断地址有效性时，应先确认对象还活着，再检查地址与访问范围。

4.1.3 按值传递参数和按地址传递参数（教材 4.1.3；PPT 第3章）

按地址传参，多了一次沿地址访问

纸书 127–131 页 · PPT 第3章 74–79、93–103 页 · 需掌握

已经知道参数放在栈中的什么位置，就能解释指针参数。考虑void set_to_nine(int *p){*p=9;}。main有一个int变量x，假设x位于地址3000，当前值7。main将地址3000作为参数值传入。在set_to_nine的栈帧里，EBP+8处存放的是3000，而x的7仍在原来的3000处。

先用movl 8(%ebp),%eax读参数，EAX得到3000。再用movl $9,(%eax)，沿EAX给出的地址找到x，写四字节9。这里有两次不同的内存操作：第一次读“保存地址的参数槽”，第二次写“该地址指向的对象”。若把第二条误写成movl $9,%eax，只会令寄存器改为9，x仍为7。

从C语义看，函数收到的指针参数本身也是一个副本。执行p=别的地址只修改副本；执行*p=9则修改副本地址所指的原对象。教材把后者称为按地址传递。这个说法方便描述效果，不能据此认为C会把指针形参变量与调用者某个变量自动绑定为同一个对象。

4.1.4 递归过程调用（教材 4.1.4；PPT 第3章）

递归何以不覆盖外层尚未用完的值

纸书 132 页 · PPT 第3章 78–79、91、111 页 · 需掌握

现在考虑f(n)=n*f(n-1)，并规定非负整数输入，f(0)=1。计算f(3)时，在f(2)返回前仍需记住外层的n=3；f(2)又需要在f(1)返回前保留2。若所有调用共用一个n的位置，内层修改会破坏外层等待的乘法。

每次调用都有自己的参数槽和必要工作区。f(3)的帧先留下3并调用f(2)；f(2)的帧留下2并调用f(1)；f(1)留下1并调用f(0)。f(0)命中出口，返回1。f(1)取回自己帧里的1与返回值1相乘，得到1；f(2)用自己的2乘1得2；f(3)再用3乘2得6。返回地址也各有一份，所以每次都能回到正确的外层乘法位置。

这一过程有两个方向：向下调用时保存尚未完成的任务，向上返回时逐层完成任务。只画调用箭头而不写返回值组合，会漏掉递归求值的一半。本例n逐次减少并有0出口，故非负输入会终止；若用无符号n但先计算n−1而忘记检查0，便可能回绕到巨大数，失去原本的终止依据。

可以把已经走过的调用与返回直接落实为下面的C函数。约定输入n在0至12内，int为32位；负数与过大输入应由调用者拒绝，本函数仅处理已满足前提的请求。

int factorial(int n) {
    if (n == 0) return 1;
    return n * factorial(n - 1);
}

先检查0才能决定是否继续调用，因此0不会再进入n−1的路径。递归返回值只是内层的结果，外层仍需乘自己的n。以3为输入，乘法在返回方向依次完成1乘1、2乘1、3乘2。若错误把return改成单纯factorial(n−1)，所有非负输入都会返回1，说明调用层数正确还不足以实现原计算。

朴素实现对输入n产生n+1层调用，总计算次数与n成正比，辅助栈空间也与n成正比。这里复杂度的规模参数是n，不是整数的位数。固定宽度返回类型还限制结果：例如32位有符号int的12!可表示，13!已超过其上界。递归能终止不代表结果在目标类型中一定可表示。

非静态局部变量的分配——由实际偏移恢复布局

纸书 133–135 页 · PPT 第3章 83–87 页 · 需掌握

前面add为result留了EBP−4这个位置，这只是本例选定的布局。C没有要求多个独立局部对象按声明顺序、连续或按地址大小排队；优化也可以让只需暂存数值的变量留在寄存器。查看一份汇编时，应逐条记录每个被访问偏移及宽度，再推断对象，不能先按源码顺序画好栈图并要求编译器服从。

4.1.6 x86-64的过程调用（教材 4.1.6；PPT 第3章）

把约定迁移到64位时，先改交接位置

纸书 136–141 页 · PPT 第3章 164–174、176–180 页 · 需掌握

相同的“传参数、记回程、保护现场、交返回值”需求仍然存在，但Linux x86-64通常先用RDI、RSI等寄存器传整数参数。add(3,5)可以先把3放EDI、5放ESI，call保存八字节返回地址，被调用函数在EAX中返回8。写32位子寄存器EDI、ESI会把对应64位寄存器的高32位清零，这适用于本例的非负int值。

不能继续认为64位第一个参数必在EBP+8，也不能仅把全部l后缀替换成q。int仍为32位，指针与long在Linux LP64环境通常64位；传递位置、返回地址宽度、栈对齐与保护集合都要按新ABI重新确认。本文的精确栈地址轨迹只属于前面声明的IA-32教学序列。

64位函数调用先改参数位置

纸书 136–141 页 · PPT 第3章 164–174、176–180 页 · 需掌握

x86-64把通用寄存器扩为64位，并增加R8至R15等。以下采用Linux常见System V AMD64 ABI，即平台的二进制调用约定。前六个适用的整数或指针参数通常依次用RDI、RSI、RDX、RCX、R8、R9；浮点参数使用XMM寄存器类别，具体分类还需遵循ABI。Windows x64规则不同，不能只凭“64位”互相套用。

考虑long add(long a,long b){return a+b;}，在这里long为64位。进入函数时RDI保存a、RSI保存b，可用下面核心代码返回：

movq %rdi, %rax
addq %rsi, %rax
ret

a=3、b=5时，先RAX=3，再8，ret返回调用者。参数无需像3.3的32位教学约定那样全部预先压栈。函数没有局部空间需求，也可能不建传统RBP栈帧；call仍会把返回地址放入栈，ret从栈恢复它。追踪方法保持一致，只需按此接口重新填写初始位置。

调用者还必须满足栈对齐要求。按该ABI常见要求，call执行前RSP为16的倍数；call压入8字节返回地址后，函数入口RSP相对16余8。若被调用函数还要调用其他函数，需要通过分配局部空间等方式安排下一次调用前的对齐。叶函数在规定条件下还可使用RSP以下128字节的red zone区域，课程基础追踪不依赖这项优化。

类型大小也不能自动统一成64位。该Linux ABI通常int仍4字节，long和指针8字节；Windows常见模型long仍4字节。读结构体或数组时要重新使用平台给出的大小和对齐，第二章与3.5建立的推导步骤仍适用。64位地址空间与某台处理器实际支持的虚拟地址位数也不是同一句话，不能从寄存器64位推断所有64位地址都可直接访问。

4.1.7 x86-64过程的浮点参数传递（教材 4.1.7；PPT未涉及）

浮点参数的交接——按类型分配两组寄存器

纸书 142 页 · PPT 第3章 105、175、178–179 页 · 传参需掌握；例4.6完整 AVX 展开无需掌握

整数参数、指针参数与浮点参数使用不同类别的寄存器。沿用Linux System V AMD64约定，普通double参数依次使用XMM0到XMM7，浮点返回值通常在XMM0。一个接口接收int i、double x、int *p时，i用EDI，x用XMM0，p用RSI：浮点参数不会占掉整数参数序列的第二个位置。

4.2.1 选择语句的机器级表示（教材 4.2.1；PPT 第3章）

程序在哪一步需要选择

纸书 143–146 页 · PPT 第3章 40–48、106–108 页 · 需掌握

考虑函数int smaller(int x,int y)，希望x小就返回x，否则返回y。在普通顺序执行中，处理器执行当前位置的指令后，前进到下一条。若把两条赋值直接顺序摆放，先将x放入结果，再将y放入结果，后一步会覆盖前一步，结果永远是y。因此我们必须让一条路径被执行时，另一条路径被跳过。

先用已经知道的函数参数位置表达数据。沿用带EBP帧的32位教学约定，x在8(%ebp)，y在12(%ebp)。用EAX暂存x、EDX暂存y，EAX同时作为最终返回值。这里的EBP偏移来自前一专题的真实压栈过程；若编译器省略帧指针或换调用约定，应按实际代码重新推导。

先读x到EAX，读y到EDX。此时只完成取数，还没有选择。我们想知道的是“EAX当前值是否小于EDX当前值”。x86用比较指令产生一组标志，再由跳转指令读取标志决定是否改变执行位置。

比较为何写成一次不存结果的减法

纸书 143–146 页 · PPT 第3章 40–48、106–108 页 · 需掌握

如果x=3、y=5，算x−y=−2，可以判断x小于y。比较指令cmpl %edx,%eax按“目的减源”计算标志，含义就是用EAX减EDX，但丢弃差值，EAX和EDX仍保存原数。这样比较后可以直接返回原x或原y，不必重新从内存加载它们。

SF是Sign Flag，符号标志，记录保留结果最高位；ZF是Zero Flag，零标志，记录保留结果是否全零；OF是Overflow Flag，记录带符号数学差值是否越过32位范围。在当前3减5的例子中，结果−2最高位1，SF=1；结果非零，ZF=0；−2可表示，OF=0。后面跟jl，即有符号小于时跳转，会发现SF与OF不同，条件成立。

为什么条件要看SF与OF不同，不能只看SF？暂取八位小模型方便观察，比较127与−1。数学差128为正，说明前者更大，但八位只保留0x80，最高位1，看起来像负数。此时有符号溢出OF=1。SF与OF同为1，jl不跳，判断正确。若差值没有溢出，OF=0，SF确实可直接代表数学差值的正负；发生溢出时，OF提醒我们这个最高位已经翻转了解释。两者异或把这一次翻转纠正回来。

比较无符号数则有另一个依据。x−y需要借位时，说明x的无符号值小于y。CF是Carry Flag，减法时记录借位，jb据CF=1决定跳转。相同位串若分别按有符号、无符号解释，可能需要不同跳转。选择条件时必须先明确程序中的类型，而不能只从机器最高位猜比较方式。

相等条件由ZF补上：相等时用je，ZF=1；不等用jne，ZF=0。有符号小于等于jle要求“ZF=1，或者SF与OF不同”，有符号大于jg则要求“ZF=0，并且SF与OF相同”。无符号小于等于jbe要求“CF=1或者ZF=1”，无符号大于ja要求“CF=0并且ZF=0”。这些组合来自严格小于与相等的合并，以及大于对小于等于的排除。可以拿3与5、5与5、8与5依次代入，分别检查小于、等于、大于三种情况，而不必把跳转表当作没有依据的缩写清单。

把两条互斥路径真正接起来

纸书 143–146 页 · PPT 第3章 40–48、106–108 页 · 需掌握

下面是smaller的一个教学函数体，省略已讲过的建帧与退帧指令：

movl 8(%ebp), %eax
movl 12(%ebp), %edx
cmpl %edx, %eax
jl .keep_x
movl %edx, %eax
.keep_x:

.keep_x是汇编标号，给某个指令位置起名字；它本身不读取内存，也不存一个需要加法的数。jl选择是否把后继位置改到这个标号。若跳过去，movl %edx,%eax被绕开，EAX保留x；若不跳，复制y到EAX。两条路径最终都在.keep_x汇合，随后由公共退帧和ret返回。

逐条跑x=3、y=5：第一条后EAX=3；第二条后EDX=5；比较只生成标志；jl成立，绕开复制y；到.keep_x时EAX仍3。再跑x=8、y=5：比较8−5=3，SF=0、OF=0，jl不成立；下一条将5写EAX，最后返回5。相等时差0，jl也不成立，但复制的y与原x相同，依然满足函数要求。

这段代码没有要求再额外存一个布尔变量。标志已经保存了条件所需的信息。若用setl %al显式形成0或1，只会写EAX低八位；要得到整个32位0或1，还需要先清零或再做零扩展。掌握寄存器局部写入后，就能解释为什么这里不能只看AL便断言EAX其余位也是零。

短路求值决定哪些内存访问根本不能发生

纸书 143–146 页 · PPT 第3章 40–48、106–108 页 · 需掌握

设函数接收指针p，C条件写为p != 0 && *p > 0。左边先判断p是否为空；左边为假时整个逻辑与已经为假，右边不再求值。这个顺序允许程序在p为空时避开解引用。我们还要假设非空p确实指向可读的int；非空本身没有证明地址有效。

可以先把p读入EAX，用testl %eax,%eax检查寄存器是否全零。test按位与但只修改标志，EAX不变。若ZF=1，跳到返回假的分支；只有ZF=0，才执行对(%eax)的读取并判断所指int是否大于0。

如果把两项条件提前全部算完，再对结果做按位与，就可能在p为空时已经执行了错误访存。源程序有两个布尔条件不意味着编译器可以无条件执行两个可能有副作用或异常的表达式。看汇编时，应先确认那个内存访问究竟位于哪条可达路径。

跳转表也必须先保证索引合法

纸书 143–146 页 · PPT 第3章 40–48、106–108 页 · 需掌握

把刚才的case任务写完整：输入2返回10，输入3返回20，输入4返回30，其余返回−1。C可以写成下面的函数，所有int输入都有定义。

int choose_value(int x) {
    switch (x) {
        case 2: return 10;
        case 3: return 20;
        case 4: return 30;
        default: return -1;
    }
}

一种教学实现先在32位无符号模型里计算index=(unsigned)x−2u，再检查index>2u。这里先转换为无符号再减，避免在C中对INT_MIN直接执行有符号减2。跳转表三项依次保存L2、L3、L4的代码地址；检查通过后才按index读取表项并间接跳转，每个标号写入自己的返回值，再汇入公共返回路径。

逐个走边界：x=2得到index=0，读第一项L2，结果10；x=4得到2，读第三项L4，结果30；x=5得到3，超范围走default；x=1得到FFFFFFFFH，无符号大于2，也走default；x为INT_MIN时减法依无符号规则保存7FFFFFFEH，同样超范围。这样上下两端都被同一检查排除，任何非法索引都没有机会先读取跳转表。

编译器也可以选比较链，甚至把返回值放入数据表，而不使用代码地址跳转表。选择取决于case稠密程度、目标与优化；switch的源语义并未规定必须生成哪一种。反汇编时必须从实际加载的是什么、间接跳到哪里以及范围检查，重建对应行为。

4.2.2 循环语句的机器级表示（教材 4.2.2；PPT 第3章）

循环增加了回到旧位置的边

纸书 147–149 页 · PPT 第3章 109–112 页 · 需掌握

现在希望函数计算0到n−1的和。先用n=3手工执行：初始sum=0、i=0。检查0<3成立，加0，sum仍0，i变1；检查1<3成立，加1，sum变1，i变2；检查2<3成立，加2，sum变3，i变3；检查3<3不成立，退出并返回3。条件检查发生了四次，循环体只做三次，最后一次失败检查也属于完整轨迹。

把这个过程写成C：

int sum_prefix(int n) {
    int sum = 0;
    int i = 0;
    while (i < n) {
        sum += i;
        ++i;
    }
    return sum;
}

本篇用非负且不超过65536的n，保证这个版本的32位int求和不溢出。n为0时第一次检查就失败，返回0；n为65536时和为2147450880，仍在32位int范围内。声明边界是为了区分控制流程正确与数值类型够不够大。

取ECX保存n，EDX保存i，EAX保存sum。函数体可写成：

movl 8(%ebp), %ecx
movl $0, %edx
movl $0, %eax
.check:
cmpl %ecx, %edx
jge .done
addl %edx, %eax
addl $1, %edx
jmp .check
.done:

check处比较EDX−ECX，也就是i−n。jge在有符号大于等于时跳，条件为SF与OF相同。代码用“退出条件i≥n”表达C中“继续条件i<n”的相反面，这并没有改变算法。只要退出条件不成立，就执行加i、i加1，最后无条件跳回.check。

在n=3的轨迹中，跳回.check的那条jmp共执行三次。jge第一次、第二次、第三次都不跳，第四次才跳到.done。若把更新i的指令遗漏，i将一直为0，条件永远成立；若把jmp目标写成循环体开头而绕开.check，则更新后的i再也没有被检查。这两种错误都能由逐条路径追踪发现。

从一轮轨迹提炼“每次回到检查点都成立的事实”

纸书 147–149 页 · PPT 第3章 109–112 页 · 需掌握

当i=2、准备做下一次检查时，sum=1，它恰好等于0到i−1的和。初始i=0时sum=0，是空区间的和。每做一轮，我们加上当前i，再把i增加1，因此回到检查点时，sum仍等于新i之前全部整数的和。

这个在循环入口持续成立的关系叫循环不变量。它帮助解释程序为何正确：初始化建立关系；循环体保持关系；退出时i=n，关系便变成sum等于0到n−1的和。终止则另有依据：每轮i增加1，直到达到固定n，且本篇范围避免计数器溢出。正确性关系与最终会停是两个需要分别说明的部分。

算法进行n轮加法，时间随n线性增长，额外工作空间只有三个整数，即常数空间。这个复杂度结论针对这段循环实现；若直接利用数学求和公式，又会引入乘法的中间溢出检查，不能因为公式短就省掉类型与范围分析。

反过来看一段陌生汇编

纸书 147–149 页 · PPT 第3章 109–112 页 · 需掌握

看到某个跳转回到较早的标号，可以先把那一小段圈出来，寻找每轮改变的寄存器。随后在进入循环前找初值，在出口找条件比较，最后用两轮小数据重演。这个顺序比先猜“它像for还是while”更可靠，因为编译器可以把不同C循环改造成相似的控制流。

例如刚才的代码，即使标号改成.L2、.L3，甚至把条件检查放在代码布局的后面，你仍能从EDX初始0、每轮加1、EAX每轮加EDX、与ECX比较这些数据依赖重建它。变量名和排版改变不会改变这些操作的含义。

遇到switch的间接跳转，第一步同样看已知约束。假定case只处理2、3、4，可以先算index=x−2，检查index按无符号解释是否大于2，超过范围走default；否则从三项跳转表里取目标。x=1时index为负，按同宽无符号解释为巨大值，也会被这一次上界检查排除。这个技巧依赖固定宽度减法和无符号比较，必须先推演一个小于下界和一个大于上界的输入，才可确认覆盖了两端。

4.3.1 数组的分配和访问（教材 4.3.1；PPT 第3章）

数组名怎样成为第一个元素的地址

纸书 150–154 页 · PPT 第3章 116–123 页 · 需掌握

设int a[4]={10,20,30,40};，在本节的IA-32模型中int占4字节，数组起点为1000。四个元素按顺序占1000至1003、1004至1007、1008至1011、1012至1015。访问a[2]要跳过两个元素，共8字节，因此地址1008，读出30。一般地址公式是起点+i×元素大小；乘的是元素大小，因为下标每增加1应越过一个完整元素。

C中数组表达式在许多使用场景下会转换为指向首元素的指针，但数组对象本身与指针变量仍不同。sizeof a给整个数组大小16；若int *p=a;，sizeof p在此模型中为4，给指针对象大小。p可以改为指向别处，a代表的数组对象不能通过a=p重新绑定。调用函数时若形参写int a[]，它会调整为指针形参，函数内的sizeof不能还原调用者数组长度，所以长度通常应另传。

p+2得到1008，*(p+2)读取30，p[2]表达相同访问。指针加法按所指类型缩放，因此p+2不是1002；char *按字符字节前进，int*按int大小前进。同一数组内部两个int指针相减，结果按元素个数计，例如指向a[3]与a[1]的指针相减为2。有效性前提不能省：只在同一数组及其尾后一位置等语言允许范围讨论。尾后指针可用于循环终止比较，不能解引用读取元素。

现在让基址在EBX、下标i在ECX。movl (%ebx,%ecx,4),%eax先算1000+i乘4，再读四字节；当i=2便得到30。若只求&a[i]，可用lea保留地址。到这里，有效地址的比例4已经由对象布局推出，无需凭汇编外形猜“这个程序一定是数组”。

连续二维数组的每一行有自己的跨度

纸书 150–154 页 · PPT 第3章 116–123 页 · 需掌握

考虑int m[2][3] = { {1,2,3}, {4,5,6} };。它是两个元素组成的数组，每个元素又是一个含三个int的行数组。每行12字节；若起点2000，第一行占2000至2011，第二行占2012至2023。m[1][2]先跳一行12字节，再跳两个int共8字节，地址2020，值6。公式为base+(i×列数+j)×sizeof(int)，适用于这里连续、按行存放的C数组。

逐项对应一下：m作为表达式通常转换为“指向含三个int的数组”的指针，所以m+1跨12字节；m[1]再转换为第二行首int地址，m[1]+2跨8字节。虽然m与m[0]的起始地址数值相同，指针类型和加1的跨度不同。只比较打印的地址，无法代替类型分析。

读循环时，这个跨度还能帮助判断行列。例如外层每次把行起点加12，内层每次加4并取三个数，恰好访问上述2乘3布局。若交换循环顺序，元素地址序列会改变，却仍可能访问同一对象；缓存效率属于后续存储系统课程，本节先确保地址与边界正确。

指针数组需要多一次读地址

纸书 150–154 页 · PPT 第3章 116–123 页 · 需掌握

换成int *rows[2];，让rows[0]指向3000起的三个int，rows[1]指向5000起的三个int。rows这个对象在IA-32中保存两个四字节地址值，若自身起点为2500，则M32[2500]=3000，M32[2504]=5000。求rows[1][2]时先算2504，读取其中的5000，再算5000+8=5008，最后读取元素。这是两级访问，第二行没有必须紧跟第一行。

对连续m[2][3]，求m[1][2]不需要先从内存读取一个“第二行指针”，因为行位置可以直接由起点和固定跨度算出。对rows，两行可分别分配和移动，代价是多保存地址并经由指针访问。两者有相似的下标写法，却有不同布局和类型；不能把int**直接当作int (*)[3]来使用。

把这两种过程画在纸上时，建议给每次内存读取单独编号：指针数组先读行地址、再读元素，连续矩阵只有元素读取。这个做法也适用于结构体中保存指针、链式对象等更复杂情况。

数组遍历的边界——在读取之前检查下标

    for (size_t i = 0; i < n; ++i) {
        sum += p[i];
    }
    return sum;
}

const表示本函数不通过p修改元素。循环在读取前验证i<n，因此最后合法下标为n−1；当n=0时条件第一次即为假，返回0。每次循环后，sum等于已读前i个元素之和。这个不变量既说明结果，也指出若条件错成i<=n会多读尾后一个位置。操作次数与n成正比，时间O(n)，额外只保存固定数量变量，辅助空间O(1)。

4.3.2 结构体数据的分配和访问（教材 4.3.2；PPT 第3章）

结构体偏移来自大小、对齐和顺序

纸书 155–157 页 · PPT 第3章 124–128 页 · 需掌握

数组各项同类型，结构体允许把不同类型的成员放入一个对象。成员不能任意挤在一起，因为平台ABI还规定对齐。对齐为4意为对象起始地址通常应是4的倍数。先按成员的声明顺序区分每个对象，再读取对应成员。结构体为不同成员保留各自的位置；联合体将让它们共享位置。精确的填充和偏移稍后在教材4.3.4一起推导。下面用到的示例按char、int、short的常见32位大小讨论。

struct Record {
    char tag;
    int value;
    short code;
};

4.3.3 联合体数据的分配和访问（教材 4.3.3；PPT 第3章）

联合体的共享存储——先看成员是否同时需要

纸书 158–159 页 · PPT 第3章 129–134 页 · 需掌握

union联合体则让多个成员从同一偏移开始共用空间。若成员是int i与char bytes[4]，在上述大小条件下常见大小为4。写某成员会影响同一存储的字节，解释另一成员还受语言规则与实现约定约束。要可移植地观察对象表示，仍应使用unsigned char访问或memcpy等允许方式；不能只因两个成员重叠，就把任意跨类型读取当作普通数值转换。

4.3.4 数据的对齐（教材 4.3.4；PPT 第3章）

数据对齐与填充——逐成员计算真实偏移

纸书 160–162 页 · PPT 第3章 135–149 页 · 需掌握

为什么要遵守这些对齐要求？在一次按8字节边界取数的教学模型中，1000至1007属于一个传送块，1008至1015属于下一个。一个四字节int若从1004开始，完整落在第一个块中；若从1006开始，就同时用到1006、1007和1008、1009，需要跨两个块取得数据并组合。合适的对齐可以减少这类跨边界工作，也让硬件和二进制接口更容易一致处理对象。真实x86支持许多未对齐访问，实际代价取决于实现以及是否跨缓存行或页面，不能把所有未对齐访问都说成一定异常或一定慢两倍。ABI要求的自然对齐则仍是分析普通结构体布局的依据。

以下沿用刚才的Record声明，明确采用IA-32大小与对齐：char大小及对齐1，short大小及对齐2，int大小及对齐4，整体对齐取成员要求的最大值。

从偏移0开始放tag，占一个字节，下一空位偏移1。value要求4字节对齐，所以偏移1、2、3留作填充，value从4开始占到7。code要求2字节对齐，偏移8已满足，放8、9。成员结束到偏移10，但若数组中下一条记录紧接其后，下一条的value也应对齐，因此结构体总大小向4的倍数补齐为12，末尾10、11也是填充。若对象起点6000，value地址6004、code地址6008；Record数组相邻对象起点差12。

因此读movl 4(%eax),%edx，在已知EAX指向此Record的前提下才可解释为读value。缺少类型与布局信息时，同样指令也可能访问数组第二项或别的数据。反汇编恢复类型通常只能提出受约束的候选，需要继续结合其他访问宽度、步长和源接口判断。

若调整为int value、short code、char tag，在上述约定中依次占0至3、4至5、6，末尾补到8。减少填充可能节省空间，但改变布局会影响文件格式、二进制接口及已有代码，不能随意改动跨模块共享的数据约定。现代64位ABI的long、指针及double对齐可能不同，应按题目给定的大小和对齐重算。

4.4.1 数组的越界访问（教材 4.4.1；PPT 第3章）

数组越界与对象生存期——地址存在还不够

纸书 163–164 页 · PPT 第3章 80–81、151–155 页 · 需掌握

对象还受生存期约束。函数自动局部数组在函数返回后不再作为原对象存在，返回它首元素的地址并在外部解引用，会使用失效地址。栈上的旧字节暂未被覆盖也不能延长对象生存期。缓冲区越界写可能覆盖邻近局部对象、保存寄存器或返回地址，具体布局虽随编译器变化，越界本身在C中已无有效行为保证。防止问题应从长度、容量和生存期入手，不能靠“这次运行没崩”判断。

4.4.2 缓冲区溢出攻击（教材 4.4.2；PPT 第3章）

缓冲区溢出与调用现场——越界写会影响谁

纸书 165–166 页 · PPT 第3章 156–159 页 · 需掌握

栈上不只放字符数组，还可能保存其他局部变量、旧寄存器值与返回地址。设一个8字节字符数组从1000开始，合法写入位置为1000至1007；若输入16字节且没有容量检查，后八次写入已经越过该对象。相邻空间究竟是什么，要从本次编译的栈布局判断，不能把某一种固定距离当成所有程序的事实。

若错误写入影响了保存的返回地址，函数体中的计算即使完成，ret仍可能转向错误位置。这把本节的容量错误与前面call/ret的现场连接起来。读取8字节容量的C字符串还要给结尾0留空间，最多保存7个普通单字节字符；检查长度时必须明确是否已计入这个结束符。

4.4.3 对缓冲区溢出攻击的防范（教材 4.4.3；PPT 第3章）

缓冲区溢出防范——先修访问，再理解三类保护

纸书 167–169 页 · PPT 第3章 160–163（自学） 页 · 需掌握

程序层面首先检查输入长度、对象容量与结束符，使用能够明确表达容量的接口，避免把未受限输入写入固定大小数组。保护机制不能让错误的越界访问获得有效语义，应先修复写入范围。作业题2(5)还要求理解编译器和操作系统的常见保护。

地址空间布局随机化ASLR让若干区域的起点在运行间变化，使依赖固定地址的预测更困难。栈保护在重要栈内容与缓冲区之间安排检测值，返回前检查它是否被改动，常称金丝雀值；异常时终止，避免继续沿被破坏的现场返回。不可执行页限制则让作为数据使用的栈、堆页面不能直接执行其中字节。这三者分别增加地址预测难度、检测特定栈破坏、限制数据页执行，作用层次不同，均不保证消除一切越界或攻击。
