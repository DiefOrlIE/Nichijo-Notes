5. 假设函数`product()`的C语言代码如下，其中`num_type`是用`typedef`声明的数据类型。

```c-template
1  void product(num_type *d, unsigned x, num_type y) {
2      *d = x*y;
3  }
```

函数`product()`的过程体对应的IA-32汇编代码如下：

```asm
movl 12(%ebp), %eax
movl 20(%ebp), %ecx
imull %eax, %ecx
mull 16(%ebp)
leal (%ecx,%edx), %edx
movl 8(%ebp), %ecx
movl %eax, (%ecx)
movl %edx, 4(%ecx)
```

给出上述每条汇编指令的注释，并说明`num_type`是什么类型。

## 提示1：先确定分析对象

`d`与`x`各占一个四字节参数槽。请检查`y`占了几个槽，以及通过`d`一共写了几字节。`mull`隐含的输入和输出寄存器必须一起记录。

## 提示2：把关键步骤展开

先采用数学幂记号，`2^32`表示2的32次方；这里没有执行C的`^`运算符。写`y=yL+2^32*yH`。`x*yL`产生64位高低半，`x*yH`只取能贡献到最终低64位的部分。第3条的`ECX`临时积不会被第4条覆盖，但`EDX:EAX`会被第4条重新产生。

## 完整解答与核对

先按无符号64位解释建立一份完整且对所有输入有定义的答案：`typedef unsigned long long num_type;`，在题设IA-32模型中它占8字节。`d`在`EBP+8`，`x`在`+12`，`y`低32位在`+16`、高32位在`+20`；末尾两次四字节写入共同保存一个64位对象。

|行|含义与结果|
|---|---|
|1|`EAX=x`|
|2|`ECX=yH`|
|3|`ECX=low32(x*yH)`|
|4|无符号乘法，`EDX:EAX=x*yL`，高半记`H`、低半记`L`|
|5|`EDX=low32(H+low32(x*yH))`，只算和，不访问内存|
|6|`ECX=d`，先前临时高半贡献已并入`EDX`|
|7|将`L`写到`d`起始的四字节|
|8|将最终高半写到`d+4`字节处|

原因是`x*y = x*yL + 2^32*(x*yH)`。结果只存64位，所以后一项超出64位的部分可以丢弃。第3条使用双操作数`imull`取低32位，这部分位串与无符号乘法的低32位一致；第4条则需要低半乘积的完整高低半，故使用`mull`。两条指令的角色不同。

若`x=3,yL=5,yH=2`，第3条得到6；第4条得到`H=0,L=15`；相加后高半6、低半15，最终为`0x000000060000000F`。再用`x=0`核对，高低半都应归零。

有一个不能省略的类型边界：代码足以确定这里需要64位整数存储，但不能唯一确定其有无符号。`typedef long long num_type;`在乘积可表示等有定义的输入上，也可产生同一套低64位运算；本轮用GCC分别编译两种声明，得到了相同核心指令。提交时可以给出上述`unsigned long long`这组相容答案，并说明64位是确定信息、符号性缺少唯一证据。不能单凭出现`mull`就断定整个64位源类型必须无符号。
