## 变量、地址、指针与引用 {#ch00-memory}
把整数 x 想成放在某个内存格里的 8，p 则是一张写着“那个格子地址”的纸条。执行 p=&x 只改变纸条，执行 *p=9 才改变 x。再考虑函数收到 p 的副本：它能通过 *p 修改 x，但给副本重新赋地址不能改变外面的 p。把这两类动作分别写在纸上，才不会把指针赋值和对象赋值混为一谈。

<p><strong>读完这一节要能做：</strong>能手绘 p、*p、&x 所指的对象，能解释传值、引用、指针三种参数。</p>
<div class="lesson-body">
<p>变量有值，也有内存地址。<strong>指针保存地址</strong>，<code>&amp;x</code> 获取 x 的地址，<code>*p</code> 访问 p 指向的对象；<strong>引用</strong>是已有对象的另一个名字。</p>
<p>把内存想成一排贴着门牌号的抽屉。整数变量 x 装着数字 7；指针 p 装着 x 的门牌号。<code>*p = 9</code> 是沿门牌号找到抽屉，把里面数字改成 9。指针可以重新指向别处；引用初始化以后通常固定绑定同一个对象。</p><div class="diagram"><pre class="tree-diagram">变量 x： [7]  地址假设 0x100
指针 p：[0x100] ───→ x
*p：   沿箭头取得 7</pre></div>
<p>推演：先执行 <code>int x=7; int* p=&amp;x; int&amp; r=x;</code>，然后 <code>*p=9; r+=2;</code>。最终 x=11，*p=11，r=11。<code>int* p</code> 的星号声明指针；<code>*p</code> 在表达式中解引用。</p><pre><code>#include &lt;iostream&gt;
using namespace std;
void byValue(int x) { x = 99; }  // 修改副本
void byRef(int&amp; x) { x = 99; }    // 修改调用者
void byPtr(int* x) { if (x) *x = 99; }
int main() {
    int x = 7;
    byValue(x); cout &lt;&lt; x &lt;&lt; '\n'; // 7
    byRef(x);   cout &lt;&lt; x &lt;&lt; '\n'; // 99
    byPtr(&amp;x);  cout &lt;&lt; x &lt;&lt; '\n'; // 99
}</code></pre><div class="question"><div class="qtitle">题：执行 int a=3,b=5; int* p=&a; p=&b; *p=8; 之后 a、b 各是多少？</div><details id="q00-1"><summary>展开答案与推导</summary><div class="answer">a=3、b=8。<code>p=&amp;b</code> 改变了 p 所保存的地址，之后 <code>*p</code> 才写入 b。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>进阶：<code>int*&amp; p</code> 是“指针的引用”，让函数能够修改调用者的指针本身。树的递归插入中，<code>Node*&amp; root</code> 可以把空子树接上一颗新结点；若形参只有 <code>Node* root</code>，在函数内重新赋值 root 通常仅修改该形参的副本。</p><pre><code>struct Node { int key; Node* left = nullptr; };
void attach(Node*&amp; root, int v) {
    if (root == nullptr) root = new Node{v, nullptr};
}
int main() {
    Node* root = nullptr;
    attach(root, 42); // 调用者的 root 现在指向新结点
    delete root;
}</code></pre>
</details>

## new、delete 与链式结点 {#ch00-nodes}
为什么链表结点必须活得比创建它的局部函数久？函数里的普通局部变量会在返回时结束生存期；用 new 创建的结点需要明确有人拥有它，直到 delete 才销毁。此后每次修改 next 前先问：原来的后继地址保存在哪里？有没有某块内存已经不可达？

<div class="lesson-body">
<p><code>new</code> 在动态存储区创建对象并返回指针；<code>delete</code> 销毁由单对象 <code>new</code> 创建的对象；<code>new[]</code> 要配 <code>delete[]</code>。<code>nullptr</code> 表示空指针，访问它指向的成员是错误的。</p>
<p>链表结点通常包含<strong>数据域</strong>和<strong>链接域</strong>：<code>Node{data,next}</code>。当 <code>p-&gt;next</code> 指向 q，表示沿着 p 的 next 指针可以走到 q。箭头 <code>-&gt;</code> 相当于 <code>(*p).next</code>。</p><div class="diagram"><pre class="tree-diagram">head ───→ [10 | next] ──→ [20 | nullptr]
           数据    指针       尾结点</pre></div>
<p>删除中间结点时，必须先保存待删地址、连好前后的指针，最后释放对象。释放后立即使用悬空指针会造成未定义行为。</p><pre><code>struct Node { int data; Node* next; };
void eraseAfter(Node* prev) {
    if (prev == nullptr || prev-&gt;next == nullptr) return;
    Node* victim = prev-&gt;next;
    prev-&gt;next = victim-&gt;next;  // 先跨过待删结点
    delete victim;              // 再释放
}</code></pre><div class="question"><div class="qtitle">题：若 q=p->next，先 delete q; 再 p->next=q->next; 有何问题？</div><details id="q00-2"><summary>展开答案与推导</summary><div class="answer"><code>delete q</code> 之后读取 <code>q-&gt;next</code> 等于访问已释放内存；必须先保存后继或先完成指针改接。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>区分三个常见错误：<strong>内存泄漏</strong>（对象无人可达却未释放）、<strong>悬空指针</strong>（对象已释放但仍保存旧地址）、<strong>重复释放</strong>（同一分配被 delete 两次）。现代实际工程常用 <code>std::unique_ptr</code> 自动管理所有权；为了直接理解本课程的链表指针操作，本讲义示例会明确使用原始指针并配套释放逻辑。</p>
</details>

## 读懂模板、结构体、递归函数 {#ch00-cpp}
遇到 template、struct 和引用参数时，先定位类型在哪里声明、函数实际拿到了对象还是副本。看链表代码时可把复杂类型临时替成 int 与 Node*，逐个还原语法；编译器检查类型规则，指针是否还指向有效结点仍需自己验证。

<div class="lesson-body">
<p><code>struct</code> 把多个字段合成一个结点类型；<code>template&lt;typename T&gt;</code> 让同一个类/函数支持多种元素类型；<code>const</code> 常用来限制修改。</p>
<p>模板像一张可以替换“元素类型”的蓝图。例如 <code>Node&lt;int&gt;</code> 保存整数，而 <code>Node&lt;string&gt;</code> 保存字符串。课程老课件常出现 <code>NULL</code> 和 <code>&lt;iostream.h&gt;</code>；这里用 <code>nullptr</code> 与 <code>&lt;iostream&gt;</code>。</p>
<pre><code>#include &lt;iostream&gt;
#include &lt;string&gt;
template &lt;typename T&gt;
struct Node {
    T data;
    Node&lt;T&gt;* next = nullptr;
};
int main() {
    Node&lt;int&gt; a{3, nullptr};
    Node&lt;std::string&gt; b{"hi", nullptr};
    std::cout &lt;&lt; a.data &lt;&lt; " " &lt;&lt; b.data &lt;&lt; '\n';
}</code></pre><p>读代码按“参数与返回值 → 关键状态 → 分支条件 → 指针变化 → 不变量”的顺序，先手绘图，逐句执行，不要仅凭变量名猜逻辑。</p><div class="question"><div class="qtitle">题：<code>Node* p=nullptr;</code> 后为什么不能立刻执行 <code>p->data=4</code>？</div><details id="q00-3"><summary>展开答案与推导</summary><div class="answer">p 还没指向任何有效结点。需要创建有效对象，例如 <code>p=new Node{4,nullptr};</code>，或者让 p 指向已有对象。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>深究：指针表达了“如何找到对象”，不自动保证对象存活；引用表达了“给对象起别名”，也不自动延长所有被引用对象的生命期。递归中的局部变量随着调用返回失效，返回其地址会产生悬空引用/指针。</p>
</details>

## 章节练习：从基础操作到陌生题 {#ch00-extra-exercises}
这些题目的思路和答案默认收起。先独立写出结果，再展开提示核查；一道题若仅能跟着答案做，说明还应回看相应操作示范。

<details class="question"><summary>【基础】int a=4; int* p=&amp;a; *p+=3; 最终 a 的值？</summary>
<p><strong>选方法的提示：</strong>画出 p 指向 a 的箭头。</p>
<p><strong>完整推理与结果：</strong>*p 修改同一对象，a=7。</p>
<p><strong>最容易错的地方：</strong>*p 并未新建整数。</p>
</details>

<details class="question"><summary>【巩固】int a=2,b=9; int* p=&amp;a; int*&amp; r=p; r=&amp;b; *p=5; 最终 a、b？</summary>
<p><strong>选方法的提示：</strong>先追踪 p 保存的地址，再追踪 *p。</p>
<p><strong>完整推理与结果：</strong>r 是 p 的引用，r=&amp;b 改 p 的指向，所以 a=2、b=5。</p>
<p><strong>最容易错的地方：</strong>指针变量的引用与所指对象的引用含义不同。</p>
</details>

<details class="question"><summary>【作业同级】单链 A→B，已知前驱 p 指向 A，将新结点 x 插入 A 和 B 间，两条赋值的顺序？</summary>
<p><strong>选方法的提示：</strong>先用 x 接住旧后继。</p>
<p><strong>完整推理与结果：</strong><code>x-&gt;next=p-&gt;next; p-&gt;next=x;</code>，这样形成 A→x→B。</p>
<p><strong>最容易错的地方：</strong>先改 p.next 可能弄丢 B。</p>
</details>

<details class="question"><summary>【作业同级】写出无额外结点的单链表逆置核心循环，给出复杂度。</summary>
<p><strong>选方法的提示：</strong>需要 prev、cur、next 三个工作指针。</p>
<p><strong>完整推理与结果：</strong><code>next=cur-&gt;next; cur-&gt;next=prev; prev=cur; cur=next;</code>，反复直到 cur 为空，时间 Θ(n)、额外空间 Θ(1)。</p>
<p><strong>最容易错的地方：</strong>必须先保存 next，再反转 cur 的箭头。</p>
</details>

<details class="question"><summary>【提高】为什么 void clear(Node* p){p=nullptr;} 无法清空调用者的头指针？如何改形参？</summary>
<p><strong>选方法的提示：</strong>指针按值传入，重新赋值只影响副本。</p>
<p><strong>完整推理与结果：</strong>声明 <code>void clear(Node*&amp; p){p=nullptr;}</code> 可以重置调用者头指针；但仍要逐结点 delete，否则会内存泄漏。</p>
<p><strong>最容易错的地方：</strong>头指针置空与释放链表内存是两件事。</p>
</details>
