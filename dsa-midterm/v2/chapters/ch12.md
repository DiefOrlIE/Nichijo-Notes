# 静态查找：顺序、折半和平均查找长度
<!-- id: ch12 | source: 6-Search Tree，第 1—29 页 -->
查找算法最终都要回答同一个问题：需要比较几次才找到或确定找不到？当数据有序后，可以舍弃不可能的半边；分析时仍要明确概率和计数习惯。


## 查找问题的基本模型与顺序查找 {#ch12-search}
要在没排序的名单中找人名，顺序查找不得不一路比较；若列表已排序，一旦碰见大于目标的关键码便可提前停止。分析算法前先注明表的存储方式、是否有序和查找成功的分布，否则“平均几次”没有唯一答案。

<div class="lesson-body">
<p>查找是在集合中寻找指定关键码的记录。<strong>静态查找</strong>的讨论通常假定操作期间集合不做插入删除；<strong>动态查找</strong>还要支持维护集合。</p>
<p>若序列无序，只知道目标键值，最直接的方法就是从第一个记录开始逐项比较，找到返回位置，搜索完整个序列仍无结果则失败。算法可用于数组与链表，最坏 O(n)。</p>
<pre><code>#include &lt;vector&gt;
int seqSearch(const std::vector&lt;int&gt;&amp; a,int key){
    for(int i=0;i&lt;(int)a.size();++i)
        if(a[i]==key)return i;
    return -1;
}</code></pre><div class="question"><div class="qtitle">题：长度 n 的无序表，等概率成功且从表头向后查找，平均关键码比较次数？</div><details id="q12-1"><summary>展开答案与推导</summary><div class="answer"><code>ASL_s=(1+2+...+n)/n=(n+1)/2</code>。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>使用监视哨的顺序查找可在数组合法额外位置放置目标 key，从而省去循环中每次下标越界判断。这不改变渐近复杂度；必须确认数组确实为哨兵预留空间，否则会越界写入。</p>
</details>

## ASL：成功和失败分别计算 {#ch12-asl}
平均查找长度是“每一种查找发生的概率×相应比较次数”之和。先把每个成功结点或失败区间的比较次数标出来，再乘概率、求和；成功查找与失败查找的概率模型和停止位置通常不同，不要混成一个数。

<div class="lesson-body">
<p><strong>ASL</strong> 是平均查找长度（Average Search Length）。若查找 i 的概率 pᵢ、代价 cᵢ，则 <code>ASL=Σ pᵢcᵢ</code>。成功与失败通常分开统计。</p>
<p>顺序查找 5 个元素，从前到后成本是 1,2,3,4,5；等概率成功 ASL=(1+2+3+4+5)/5=3。若失败意味着所有元素都比较过，单次失败成本为 5（是否增加最后的哨兵比较取决于计数约定）。</p>
<p>判定树的每个内部结点代表一次关键码比较，成功查到深度 d（根深度按比较次数从 1 开始）成本 d；失败落在空区间，按算法实际比较过的内部结点数计。</p><div class="question"><div class="qtitle">题：查找 3 个等概率关键码，成功比较次数分别为 1、2、2，ASL？</div><details id="q12-2"><summary>展开答案与推导</summary><div class="answer">(1+2+2)/3=5/3。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>失败概率若按 n+1 个可能插入位置等概率分配，则 <code>ASL_fail=Σqⱼcⱼ</code>；如果教材把最终失败的区间判断算作比较，数值可能不同。做题先在判定树上逐路径标注实际比较次数。</p>
</details>

## 二分查找的不变量、实现与判定树 {#ch12-binary}
有序数组 [2,5,8,12,16,23,30] 查找 23，先看中间值 12，便能排除左侧 0..3 位置；再看右半中间值 23，第二次命中。更新左右边界的理由来自“被丢弃的区间里不可能存在目标”，这就是二分循环不变量。

<div class="lesson-body">
<p>二分查找要求<strong>顺序存储且按关键码排好序</strong>（便于 O(1) 访问中间元素）。每次取中间位置 mid，与目标比较后舍弃不可能的一半；最坏 O(log n)。</p>
<p>当前候选区间为闭区间 <code>[lo,hi]</code>。若 a[mid]&lt;key，则 mid 及其左侧都不能含目标，更新 lo=mid+1；若大于则 hi=mid−1；相等立即成功。没有遇到相等时，区间最终变空。</p><div class="diagram"><pre class="tree-diagram">有序 [2,5,8,12,16,23,30]
搜索 23：lo=0,hi=6,mid=3 →12&lt;23
lo=4,hi=6,mid=5 →23 命中
搜索 9：mid3=12 &gt;9；mid1=5 &lt;9；mid2=8 &lt;9
lo=3,hi=2，失败</pre></div>
<pre><code>#include &lt;vector&gt;
int binarySearch(const std::vector&lt;int&gt;&amp; a,int key){
    int lo=0,hi=(int)a.size()-1;
    while(lo&lt;=hi){
        int mid=lo+(hi-lo)/2; // 避免 lo+hi 溢出
        if(a[mid]==key)return mid;
        if(a[mid]&lt;key)lo=mid+1;
        else hi=mid-1;
    }
    return -1;
}</code></pre><div class="question"><div class="qtitle">题：在 [1,4,6,9,12,15,18] 中二分查找 12，按 mid=floor((lo+hi)/2) 顺次比较的值？</div><details id="q12-3"><summary>展开答案与推导</summary><div class="answer">第一次 mid=3→9（偏小）；新区间 [4,6]，第二次 mid=5→15（偏大）；新区间 [4,4]，第三次 mid=4→12。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>判定树可画出二分查找比较顺序；n=2^h−1 时树为满二叉树，高度 h，成功 ASL=(1·1+2·2+...+h·2^(h−1))/(2^h−1)。注意：二分查找与 BST 都沿树形决策路径搜索，但二分查找基于有序数组，BST 基于带链接的动态结构。</p>
</details>

## 顺序、二分、BST 的适用条件 {#ch12-compare}
二分依赖 O(1) 访问中间位置，适合连续数组；一般单链表寻找中间结点还得沿链走，不能照套复杂度。BST 按大小沿指针向下走，但最坏可能退化成一条链；平衡树为查找、插删提供稳定的高度上界。

<div class="lesson-body">
<p>无序表通常采用顺序查找 O(n)；有序数组二分 O(log n)；二叉搜索树按树高 h 查找 O(h)，最坏仍可能 O(n)。</p>
<p>为什么不能把折半搜索直接套在普通单链表？即使知道逻辑中点的位置编号，要从链首走到中点也可能需要 O(n)，所以缺乏数组式的快速随机访问优势。</p>
<div class="question"><div class="qtitle">题：数据经常插删、又要求按键比较，优先考虑有序数组还是平衡搜索树？</div><details id="q12-4"><summary>展开答案与推导</summary><div class="answer">平衡搜索树通常较适合，插入/删除和搜索最坏可达 O(log n)。有序数组单次二分查找很快，但中间插删要搬移 O(n) 个元素。</div></details></div>
</div>
<details class="optional"><summary>选读：原理推广与额外边界</summary>
<p>当关键码不唯一时，要先声明是否返回任一匹配、首个匹配或全部匹配。返回第一个不小于 key 的 <code>lower_bound</code> 形式有专门的二分边界不变量，考试中别把它与“找到任意匹配即返回”的模板混用。</p>
</details>

## 章节练习：基础、典型与迁移 {#ch12-extra-exercises}
先独立解题；所有提示与答案默认折叠。

<details class="question"><summary>【基础】无序表顺序查找长度为 n、等概率成功，ASL 是多少？</summary>
<p><strong>选择思路：</strong>第 i 项需要比较 i 次。</p><p><strong>计算与结果：</strong>(1+2+...+n)/n=(n+1)/2。</p><p><strong>易错点：</strong>若题目给的比较次数和权重不同，须按实际概率求和。</p>
</details>

<details class="question"><summary>【巩固】二分搜索 [2,4,7,9,13,18,22] 的 13，依次比较哪些值？</summary>
<p><strong>选择思路：</strong>闭区间 mid=floor((lo+hi)/2)。</p><p><strong>计算与结果：</strong>先比较下标 3 的 9；搜索右侧 [4,6]，比较下标 5 的 18；再比较下标 4 的 13。共 3 次。</p><p><strong>易错点：</strong>不能把比较次数与数组下标混淆。</p>
</details>

<details class="question"><summary>【作业同级】按中间向下取整，在 [1,3,5,7,9,11,13,15] 中查找 8，记录所有比较关键字。</summary>
<p><strong>选择思路：</strong>失败前必须不断缩小闭区间。</p><p><strong>计算与结果：</strong>mid=3→7，小；区间 [4,7]，mid=5→11，大；区间 [4,4]，mid=4→9，大；区间空，失败。比较 7,11,9。</p><p><strong>易错点：</strong>失败仍有关键码比较次数。</p>
</details>

<details class="question"><summary>【作业同级】成功查找概率为 1/2、1/4、1/4，三关键码比较次数分别为 1、2、3，ASL？</summary>
<p><strong>选择思路：</strong>分别用各自概率乘以比较次数再相加。</p><p><strong>计算与结果：</strong>ASL=(1/2)×1+(1/4)×2+(1/4)×3=1.75。</p><p><strong>易错点：</strong>不同概率不能直接取比较次数算术平均。</p>
</details>

<details class="question"><summary>【提高】为何对一般单链表直接使用二分下标策略，无法保证 O(log n) 的时间？</summary>
<p><strong>选择思路：</strong>访问逻辑中点本身需要沿链表移动。</p><p><strong>计算与结果：</strong>链表不支持 O(1) 按序号跳到中点，每轮找中点有线性代价，普通实现不具有数组二分的 O(log n) 随机访问优势。</p><p><strong>易错点：</strong>比较次数对数不代表总操作时间对数。</p>
</details>
